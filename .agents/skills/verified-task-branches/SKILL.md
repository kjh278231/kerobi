# 검증 단위 Git 브랜치 운영

브랜치 하나는 독립적으로 검증·병합할 수 있는 하위 작업 하나를 담는다. 스프린트는 일정과 검증을 묶으며 브랜치의 수명을 결정하지 않는다. 저장소별 검증·점유·출처 정책을 먼저 적용한다.

## 착수

`git status --short --branch`와 `git worktree list`를 확인한다. 저장소 지침·인수인계에서 작업 번호, 선행 commit, 현재 점유, 검증 계약을 복구한다. `tools/session.py`가 있으면 해당 시작 절차를 따른다.

최신 로컬 main에서 `work/<하위번호>`와 독립 worktree를 만든다. 예시는 `work/m2-03a`다. 기본 분기 깊이는 main의 직접 자식이다. M1·M2·M3 같은 영역은 점유로 관리하며 상시 통합 브랜치를 추가하지 않는다. 한 브랜치에는 한 담당자가 쓴다.

선행 작업이 준비됐으면 먼저 병합한 뒤 최신 main에서 다음 작업을 시작한다. 선행 작업의 병합을 기다리면서 진행해야 할 때만 임시 자식 브랜치를 사용한다. 부모 병합 후 main 기준으로 정리하고 남은 차이가 자식 작업뿐인지 확인한다.

## 미커밋 선행 변경

dirty main에서 작업해야 하면 파일과 index를 보존하는 스냅숏을 먼저 만든다. 스냅숏은 복구 수단이며 검증 완료 기준선이 아니다. 스냅숏에서 갈라진 브랜치를 병합하기 전 `git log main..<작업>`과 전체 diff에서 숨은 선행 변경을 확인한다.

선행 변경은 코드·검증 도구·기준 자료·운영 문서 등 검증 가능한 묶음으로 커밋한다. 각 묶음의 검증 범위와 미검증 범위를 기록한다. 스냅숏 대비 파일 내용과 mode가 보존됐는지 확인한다. 기존 조사·구현 작업은 깨끗한 기준선 위에 작업 커밋만 재적용하고, 파일 전체 복사로 중복 반영하지 않는다.

main을 비워야 하면 먼저 시작 상태와 보존본의 일치를 확인하고, 백업 ref가 있는 stash 등으로 원본을 보존한다. 원본을 지우거나 덮어써서 깨끗하게 만들지 않는다. 공유 이력은 재작성하지 않고 정리용 새 브랜치에서 작업한다.

## 검증과 병합

완료 기준을 작업 시작에 고정한다. 필요한 검증이 통과한 직후 병합하며 스프린트 말이나 상위 마일스톤 완료를 기다리지 않는다.

| 종류 | 병합할 수 있는 상태 |
|---|---|
| 조사 | 정한 질문에 근거로 답하고, 조건·미확인 범위·후속 작업을 기록함 |
| 오라클 | 기준 원본 식별·재현성과 오류 검출을 확인함 |
| 구현 | 계약 범위의 동작 비교와 영향받는 회귀를 통과함 |
| 기존 변경 정리 | 내용 보존과 필요한 회귀를 확인하고, 기존 미검증 동작을 명시함 |

전체 관문과 해당 작업의 합격을 구분한다. 미검증 구현은 구현 완료로 승격하지 않는다. 실패가 남으면 해당 branch에 보존하고 원인·다음 명령을 인계한다.

최신 main에서 작업 전체 diff와 선행 commit을 검토하고 필요한 통합 검사를 한다. 병합은 한 번에 하나씩 `git merge --no-ff <작업>`으로 수행한다. 사용자 지시와 저장소 운영 규칙으로 허용된 범위에서 병합하며, 이미 병합 권한이 있는 작업을 다시 승인받지 않는다. 커밋에는 작업 번호·실제 검증·남은 한계를 추적할 수 있게 남긴다. 원격 동작은 저장소 정책과 사용자의 권한 범위를 따른다.

## 기록과 정리

main의 상세 결과는 병합으로 반영한다. 미병합 작업은 main 인수인계에 branch·commit·위치·검증 상태만 기록한다. 상세 파일을 main에 미리 복사하지 않는다. 같은 저장소를 쓰는 병합 세션만 공유 진행 문서를 갱신한다.

병합 뒤 작업 commit의 도달 여부와 최종 diff·status를 확인한다. **main 병합과 같은 단계에서** 작업 worktree와 작업 브랜치를 정리한다(`git worktree remove`, `git branch -d`). 다음 작업이나 보고로 미루지 않는다. 미커밋·미추적 변경이 있으면 먼저 커밋하거나 보존하고, 재생성 가능한 ignore 산출물만 지운다. 정리하지 못하면 그 이유와 경로를 보고에 적는다. 병합하지 않은 worktree나 다른 세션이 점유한 worktree는 정리하지 않는다. 스냅숏에서 재적용해 원래 commit이 병합 이력에 없는 경우에는 원래 이력을 backup ref로 보존하고 대응표를 남긴 뒤 정리한다. 얻었던 점유를 해제하고, branch·검증·병합 commit·남은 한계를 보고한다.
