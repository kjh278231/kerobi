# M3-04a crossover 진입 계약 조사

## 착수 검증 계약

- 종류: 정적 조사. 기준 원본은 Gurobi 13.0.3의 `../re/decomp/` C와 필요한 asm이다.
- 질문: `2baaa4`, barrier 직접 `13f64d`, warm-start `13f716`의 진입 조건·ABI, x/y/slack/reduced cost의 순서·차원·좌표·스케일·목적 sense, 기저 출력·보존·실패 상태를 확인한다.
- 비교 경계: 호출 직전 입력 상태와 반환 직후 출력·상태. C만으로 확정할 수 없는 항목은 미확인으로 분리한다.
- 증거: 원본 파일과 줄·함수 주소를 기록하고 호출자 및 변환 함수를 대조한다. 자연 실행 가능성과 조건은 별도로 기록한다.
- 합격: 각 질문에 원본 근거 또는 명시적인 미확인과 후속 작업을 기록하고 링크·인용 위치 및 `git diff --check`가 통과한다.
- 동등성: 런타임 원본 캡처와 같은 입력 상태의 비교를 수행하지 않으므로 미검증이다. 정적 조사 완료는 구현 일치를 뜻하지 않는다.
- 제약: Rust·공유 파일·main을 수정하지 않으며 Gurobi를 실행하지 않는다. 후속 오라클은 실제 목표 사건과 필수 배열을 요구해야 한다.

## 정적 조사 결과

원본 C 경로는 저장소의 부모에 있는 `../re/decomp/c/` 기준이다. 파일명 앞의 숫자는 ELF 파일 오프셋이며 괄호의 줄은 해당 C 파일의 줄이다. 실행 캡처는 없다.

### 진입과 ABI

- PDHG `34f033` ([C](../../../re/decomp/c/003639a0_PRIVATE000000000034f033.c), 186, 529–575줄)은 `local_50 = 2baa47(model)`을 사용한다. 종료 분기에서 `local_50 != 0`, 상태가 9·11·16이 아니고 앞선 특수 조건을 만족하지 않을 때 `2baaa4`를 호출한다. 따라서 자연 실행 경로가 존재하지만 이 조건만으로 특정 입력에서 도달한다고 확정할 수 없다. `2baa47` ([C](../../../re/decomp/c/002dc5e0_PRIVATE00000000002baa47.c), 8–15줄)은 두 선행 검사 결과가 모두 0일 때 현재 `Crossover != 0`을 반환한다. 호출자는 진입 시 Crossover를 저장하고 종료 시 복원한다 (53, 579줄). 두 선행 검사의 전체 의미는 미확인이다.
- `2baaa4` ([C](../../../re/decomp/c/002dc620_PRIVATE00000000002baaa4.c), 39–45, 154–165, 244–255줄)는 선택적으로 `2c6a7a`를 호출하고 시작 구조를 준비한 뒤 `13f64d`를 호출한다. 시작 구조 S 또는 결과 R·R의 x 포인터가 없으면 복사를 건너뛰어도 호출한다. 모델 포인터 자체의 null 허용을 뜻하지 않는다. 선택 분기의 정확한 의미와 `2c6a7a`의 결과 반영은 미확인이다.
- barrier `2bb770` ([C](../../../re/decomp/c/002dd9b0_PRIVATE00000000002bb770.c), 275–326줄)은 같은 복사·세 변환을 자체 수행한 뒤 `13f64d`에 직접 진입한다. warm-start `0c3d0d` ([C](../../../re/decomp/c/0014acb0_PRIVATE00000000000c3d0d.c), 784–796줄)는 `local_60 != 0`일 때 `13f716(model, 1, work)`을 직접 부른다. `13f716` mode 0은 결과 배열 네 개를 요구하지만 mode 1은 별도 경로로 시작 구조를 확보한다 ([C](../../../re/decomp/c/001bc5d0_PRIVATE000000000013f716.c), 160–185, 1704–1725, 1966–1975줄). mode 1의 필수 start 구성 전체는 미확인이다.
- ELF x86-64에서 `2baaa4`는 `xmm0` 시작 work, `rdi` 모델, `rsi` work 포인터를 받는다. `13f64d`는 `xmm0` work 차이, `rdi` 모델, `esi` 스레드 수, `rdx` work 포인터를 받는다. `Crossover != 5`면 `rsi=0`으로 `13f716`에 tail jump한다. 값 5에 스레드 2 미만이면 임시로 -1을 넣고 mode 0을 호출한 뒤 5를 복구하며, 그 외에는 `9b54f1`로 간다. ELF `0x1bc570–0x1bc5c2`, `0x2dc893–0x2dc898`의 반환 레지스터와 호출자를 보면 C의 `void` 선언 및 누락된 double 인자는 부정확하다. 기준 ELF SHA-256은 `8e87fca221fdffc922331c8619426031b3e72dfd419446422f88af0cb0e98f9c`다. 검증 명령은 `objdump -d --start-address=0x1bc570 --stop-address=0x1bc5f0 ../.venv/lib/python3.13/site-packages/gurobipy/.libs/libgurobi130.so`다.

### 배열과 변환

`D = *(model+0xe8)`, `n = *(int *)(D+0xc)`, `m = *(int *)(D+8)`, `R = *(model+0x1b0)`, `S = *(model+0x1a8)`로 둔다. n은 열, m은 행이다. [복사 코드](../../../re/decomp/c/002dc620_PRIVATE00000000002baaa4.c) 167–243줄과 [기존 원본 노트](../../../re/notes/14_barrier_crossover_pdhg_concurrent.md) 753줄을 함께 읽었다.

| 원본 결과 | 길이 | 시작 구조 | 의미 |
|---|---:|---|---|
| `R+8` | n | `S+0x60` 앞 | x |
| `R+0x10` | m | `S+0x60` 뒤 | slack |
| `R+0x20` | n | `S+0x68` 앞 | reduced cost |
| `R+0x18` | m | `S+0x68` 뒤 | row dual y |

두 배열은 각각 `n+m`개의 double이며 기존 포인터를 해제하고 재할당한다. `R` 첫 4바이트를 `S+0x54`에 복사한다. 이름은 기존 노트와 차원에서 해석했으며 부호와 좌표는 아래 변환을 포함해야 한다. 축약 여부와 원래 모델 인덱스 매핑은 해당 model의 호출 문맥에 종속되므로 전역 원래 모델 순서로 단정하지 않는다.

변환 순서는 `07a069`, `07a2ee`, `07a366`이다 ([호출](../../../re/decomp/c/002dc620_PRIVATE00000000002baaa4.c), 239–243줄). `07a069` ([C](../../../re/decomp/c/0010b0f0_PRIVATE000000000007a069.c), 49–58, 66–78, 181–194, 328–350, 455–475줄)은 `D+0x3e0`이 null이 아니면 열 x에 그 열 배열을 곱하고, slack을 `D+0x3d8` 행 배열로 나누며, reduced cost를 열 배열과 `D+1000`의 곱으로 나누고, y에 행 배열을 `D+1000`으로 나눈 값을 곱한다. 이 필드의 정확한 명칭과 스케일 방향은 추가 검증이 필요하다. `07a2ee` ([C](../../../re/decomp/c/0010bad0_PRIVATE000000000007a2ee.c), 26–35, 86–96줄)는 y의 모든 원소 부호 비트를 뒤집으며 목적 sense 조건은 없다. `07a366` ([C](../../../re/decomp/c/0010bbf0_PRIVATE000000000007a366.c), 16–25, 54–71줄)은 `D+0x3c == 1` 및 `D+0x408`의 열 flag가 1인 열의 x·reduced cost, 행 sense가 `>`인 행의 slack·y 부호를 뒤집는다. 목적 sense가 이 플래그에 어떻게 반영되는지는 미확인이다.

mode 0 본체는 `R`의 네 포인터를 확인한 다음 별도 `n+m` 작업 배열에 x, slack, reduced cost를 복사하고 y의 부호 비트를 반전한다 ([C](../../../re/decomp/c/001bc5d0_PRIVATE000000000013f716.c), 173–185, 270–334줄). 이 시점에서의 좌표와 앞의 `S` 배열과의 관계 전체는 추가 추적이 필요하다.

### 출력과 실패

`13f716`은 조건에 따라 `0cda5b` cleanup에 mode 0 또는 1을 전달하고, 한 분기에서는 열·행 상태 배열과 작업 벡터를 전달한다 ([C](../../../re/decomp/c/001bc5d0_PRIVATE000000000013f716.c), 1655–1681줄). 이 호출만으로 최종 basis 설치 위치나 기존 basis 보존을 확정할 수 없다. 결과 포인터가 빠지면 상태 12의 별도 분기를 제외하고 메시지를 출력하고 종료 경로로 간다 (같은 파일 173–190줄). 할당 실패는 `0x2711`이며, 일부 내부 오류는 모델 상태에 기록하고 함수 반환은 0으로 바뀐다 (1975–1992줄). `2baaa4`는 모델 상태가 바뀌고 새 상태가 -1006이 아니면 변경 로그를 남긴다 (249–255줄). 따라서 함수 반환값 0만으로 기저 성공을 판정할 수 없다. 실패 시 기존 basis·결과 배열의 보존 여부와 상태별 최종 값은 미확인이다.

### 후속 검증

- M3-04b와 M3-04d는 각각 primal·dual push 경계, phase 상태와 위 작업 배열의 실제 소비를 조사한다. M3-04f는 cleanup 호출 전후 basis 설치·보존·실패를 추적한다.
- 런타임 오라클은 새 번호 M3-04a-1로 분리한다. PDHG 자연 진입, barrier 직접 진입, warm-start mode 1을 각각 원본에서 캡처하고 모델·바이너리 해시, 파라미터, 상태, 차원, 네 배열과 변환 전후, basis 및 반환·상태를 저장한다. 원본 목표 사건 0회, 필수 배열 누락, 해시 0 또는 합성 사례만 있으면 목표 합격을 거부한다. 저장 기록 재생은 별도 대조군이다.
- 원본 실행을 하지 않아 배열 수치, sense, 스케일, basis 보존과 동등성은 미검증이다. Rust 구현도 없다.

## 진입 판단의 추가 추적

PDHG `34f033`은 진입 시 `env+0x2ba0`을 `uVar1`에 저장하고 종료 시 복원한다 ([C](../../../re/decomp/c/003639a0_PRIVATE000000000034f033.c), 49–53, 577–581줄). `local_50`은 별도로 `2baa47`의 결과이며 저장값 자체가 아니다. 종료 판단의 `status`는 `local_58+100`이다. `T`는 `status==2 && SolutionTarget>0` 또는 `env+0x2b40 < 1e100 && local_58+0xe0 != 0`이다 (529–535줄).

| 조건 | 결과 |
|---|---|
| `T`이고 `local_50==0` | 해 처리 분기 |
| `T`이고 `local_50!=0` | 해 처리 분기와 `2baaa4` 호출 모두 건너뜀 |
| `!T`, `local_50==0` 또는 상태 9·11·16 | 해 처리 분기 |
| `!T`, `local_50!=0`, 상태가 9·11·16 외 | `2baaa4` 호출 |

해 처리 분기는 `SolutionTarget<1`이면 조건에 따라 `07a542` 또는 `36578f`를 호출하고, 별도 조건에서 start 설치를 시도한다 (536–570줄). `2baa47`은 `2d0596`과 `0a7f923`이 모두 0일 때 현재 Crossover가 0이 아닌지 반환한다. 이 검사들의 전체 의미는 미확인이다.

barrier `2bb770`의 `local_e8` 하위 바이트를 `B`라 하자. 두 검사 `2d0596`·`0a7f923`이 0이고 Crossover가 0이 아니면 B=1, 그렇지 않으면 Crossover를 0으로 설정하고 B=0으로 진행하는 경로가 있다 ([C](../../../re/decomp/c/002dd9b0_PRIVATE00000000002bb770.c), 168–175, 465–473줄). 실제 switch 전에 barrier 호출이 성공해야 한다.

| barrier 종료 상태 | switch의 동작 |
|---|---|
| 2 | `SolutionTarget<1`이고 B=1이면 crossover, B=0이면 결과 객체가 있을 때 `07a542`; `SolutionTarget>=1`이면 둘 다 생략 |
| 3, 4, 5, 9, 11, 16, 17 | 결과 객체와 네 포인터가 모두 있으면 `07a542`; crossover 생략 |
| 13 | B=1이면 crossover. B=0이고 `SolutionTarget<1`이면 결과 객체가 있을 때 `07a542`; 그 외 생략 |
| 그 밖의 상태 | B=1이면 crossover. B=0이면 결과 객체가 있을 때 `07a542` |

근거는 같은 파일 196–230, 326–330줄이다. crossover 분기도 결과·설정에 따라 `2c6a7a`를 거친다. 이 표는 해당 switch까지 도달한 경우만 설명한다.

warm-start `0c3d0d`는 `local_60`을 0으로 초기화한다. `iVar16 != 0`인 초기화 분기에서 `local_50=088237(env,model)`을 얻고, `local_50==2`, `11603b(model)!=0`, 선택된 `uVar24 != 6`이면 `local_60=1`이다 ([C](../../../re/decomp/c/0014acb0_PRIVATE00000000000c3d0d.c), 172–182, 930–935, 1014–1024줄). `11603b` ([C](../../../re/decomp/c/001a85a0_PRIVATE000000000011603b.c), 7–13줄)는 `model+0x238`과 그 `+0x20` 포인터가 있고 `+0x14==2`, `+4>0`인지 검사한다. 이후 784–796줄의 해당 분기에 도달해야 mode 1을 호출한다. `088237`의 모든 반환 조건과 선행 분기 전체는 여기서 확정하지 않는다.

## 스케일과 부분 상태

`C[j]=D+0x3e0`의 j번째 double, `R[i]=D+0x3d8`의 i번째 double, `O=*(double *)(D+1000)`으로 쓴다. `C` 포인터가 null이면 `07a069`는 네 배열을 모두 건드리지 않고 반환한다. 그렇지 않고 각 포인터가 유효한 경우의 식은 다음과 같다.

| 배열 | `07a069` 직후 |
|---|---|
| x[j] | x[j] × C[j] |
| slack[i] | slack[i] ÷ R[i] |
| reduced cost[j] | reduced cost[j] ÷ (C[j] × O) |
| y[i] | (R[i] ÷ O) × y[i] |

근거는 [07a069](../../../re/decomp/c/0010b0f0_PRIVATE000000000007a069.c) 50–57, 70–83, 187–194, 328–333, 465–480줄이다. 이어 `07a2ee`가 y를 뒤집고 `07a366`이 앞 절의 열 flag·행 sense 조건으로 부호를 바꾼다. 이 세 함수는 목적 sense 필드를 직접 검사하지 않는다. C·R·O에 사전에 반영된 의미는 아직 미확인이다.

`2baaa4`는 기존 `S+0x60`과 `S+0x68`을 먼저 해제하고 null로 만든다. 첫 할당 실패는 둘 다 null인 상태로 `0x2711`을 반환한다. 두 번째 할당 실패는 새 `S+0x60`이 남고 `S+0x68`은 null인 부분 상태로 반환한다 ([C](../../../re/decomp/c/002dc620_PRIVATE00000000002baaa4.c), 167–204줄). `13f716` 공통 종료 경로는 진입 시 저장한 `env+0x2478`, `+0x24a0`, `+0x26fc`를 복원한다 ([C](../../../re/decomp/c/001bc5d0_PRIVATE000000000013f716.c), 120–126, 1997–1999줄). 이 복원은 다른 모든 모델 필드가 보존된다는 뜻은 아니다.

## cleanup의 상태 배열 설치 경계

`13f716`이 cleanup에 `local_308`, 그 뒤의 행 상태, x·slack을 전달하는 분기에서 ([C](../../../re/decomp/c/001bc5d0_PRIVATE000000000013f716.c), 1673–1680줄), `0cda5b`는 `02f7e1`을 호출한다. 반환이 0이고 workspace `model+0xe0`의 상태 `+0xf0==1`, 두 상태 인자가 모두 존재하고 `D+0x324<1`이면 `0325b4(workspace, 열 상태, 행 상태, x, slack)`을 호출한다 ([C](../../../re/decomp/c/00153cc0_PRIVATE00000000000cda5b.c), 178–191줄). `0325b4`는 workspace `+0x168`이 가리키는 배열에 열 상태 n개와 이어서 행 상태 m개를 복사한다 ([C](../../../re/decomp/c/000d3150_PRIVATE00000000000325b4.c), 55–77, 136–151줄). `0cda5b`는 한 종료 경로에서 workspace 상태를 `model+100`에 기록하고, 공통 종료에서 정리 후 `iVar25`를 반환한다 (1927–1933, 2108–2111줄). `local_308`은 workspace `+0x168`의 내부 상태 배열이며 음수 상태와 비음수 basis 위치를 사용한다 (같은 `13f716` 파일 551–581, 942–953줄). 공개 VBasis/CBasis 값과 혼동하지 않는다. 이는 내부 상태 배열 설치 경계다. cleanup 후 최종 basis의 공개·보존과 실패별 상태는 M3-04f와 원본 실행에서 확인해야 한다.

## 검증 계약의 항목과 실행 결과

1. 범위는 세 진입 경계의 정적 조사다. 기준 `063516e`에서 분기했고 선행 미커밋 변경은 없다. push 알고리즘 조사는 M3-04b·04d, 해당 분기 구현은 M3-04c·04e, cleanup 연결은 M3-04f로 남긴다.
2. 원본은 위 SHA-256의 Gurobi 13.0.3 ELF 및 연결된 C다. 시작은 각 호출 직전, 종료는 반환 직후다. 모델·설정·work·배열과 포인터 수명, 상태·반환값·임시 설정 복원이 비교 경계다. RNG와 동시 실행의 전체 상태는 미확인이다.
3. 후속 비교 필드는 진입 사건·호출 인자, n·m과 네 배열, 변환 전후 부호 비트, 상태 배열, basis, 반환값 및 상태, 세 복원 설정이다. 정수·포인터 존재와 사건 순서는 정확히 비교한다. 부동소수점 허용 오차, NaN·무한대·±0의 최종 규칙은 캡처 설계에서 정한다. 시간과 work는 별도 기록하며 수치 일치 근거로 대체하지 않는다.
4. 필요한 실제 사례는 PDHG의 T 양쪽과 상태 분기, barrier switch의 각 상태군, warm-start mode 1, 두 할당 실패와 cleanup 설치·실패다. 입력·해시·원본 출력은 아직 없다. 합성 오류 주입은 실제 사건의 보조 사례다.
5. 원본 캡처·재생·비교 명령과 사례 수는 M3-04a-1에서 정한다. Gurobi 사용 중이므로 실행하지 않았다. Rust·Python 회귀는 코드 변경이 없어 실행하지 않았다. 정적 확인 명령과 결과는 아래에 기록한다.
6. 원본 실행 사례·캡처 수는 0이다. 저장 재생, 오류 주입과 동등성 비교는 미실행이며 통과 수로 집계하지 않는다. ELF 해시와 정적 위치만 확인했다.
7. 정적 조사 수행과 동등성은 별개다. 동등성은 미검증이다. `work/m3-04a`는 미병합이며 상세 인계는 [M3 인수인계](../handoff/M3.md)에 있다. 다음은 M3-04a-1 캡처 계약과 M3-04b·04d·04f다.

## 검토자 확인

Terra의 착수 `aaa31e7`, 조사 `32bceef`, 보완 `e75a6f6`을 별도로 검토했다. 원본 C와 ELF에서 ABI, 배열 분할·변환 순서, 부분 할당 실패, 임시 환경값 복원, cleanup 상태 배열 설치 경계를 대조했다. 시작 구조가 없는 경우를 모델 포인터가 없는 경우로 쓴 문장을 수정했고, y 스케일 식의 피연산자 순서를 원본대로 기록했다.

검토자의 독립 Python 단언에서 상대 링크 27개, 원본 인용 구간 8개, 실제 ELF SHA-256과 명령어 바이트 4곳, 변경 경로 2개를 확인했다. 모두 종료 0이었다. ELF의 `0x1bc598`, `0x1bc5c2`, `0x2dc893`, `0x2dc898`에서 호출·tail jump와 `eax` 반환값 소비를 확인했다. 이 검사는 정적 근거의 식별 검사이며 원본 상태 전이 비교가 아니다.

```bash
sha256sum ../.venv/lib/python3.13/site-packages/gurobipy/.libs/libgurobi130.so
objdump -d -M intel --start-address=0x1bc570 --stop-address=0x1bc5c7 ../.venv/lib/python3.13/site-packages/gurobipy/.libs/libgurobi130.so
objdump -d -M intel --start-address=0x2dc82c --stop-address=0x2dc8f7 ../.venv/lib/python3.13/site-packages/gurobipy/.libs/libgurobi130.so
git diff --check main
```

이번 판정은 정적 조사 완료, 원본 동등성 미검증이다. 수치·좌표·목적 sense와 최종 basis의 보존은 후속 원본 캡처에서 확인한다.
