# M2-06e 검증 계약과 결과: pseudocost 초기화·노드 갱신·감쇠

작성 기준은 [스프린트 검증 기준](../15_sprint_verification.md)이다. 노드 구조와 사건 추적은 [M2-06a](mip_node_select_spec.md)·[M2-06b-2](mip_node_key.md)를 따른다. M2 인수인계의 첫 다음 작업이고, 사용자의 "다음 스프린트 진행" 지시로 착수했다(2026-11-11).

## 1. 범위와 주장

- 작업 종류: 조사·오라클(읽기 전용 원본 캡처와 규칙 재생). Rust·Python 패키지는 바꾸지 않는다.
- 조사 질문:
  1. pseudocost 표 A(`M+0x3250`)는 어디서 어떤 값으로 만들어지는가(초기화).
  2. 노드 LP가 끝난 뒤 표 A를 바꾸는 일반 갱신은 어디서, 어떤 조건과 식으로 일어나는가(노트 15 §3.7.3이 "찾지 못함"으로 남긴 지점).
  3. 실패·악화 노드의 조상 감쇠(`6ee1d3`)는 어떤 조건과 식인가.
- 완료 후 주장할 것: 아래 §2의 규칙이 §4 사례의 원본 실행에서 표 A의 방향별 `cnt`·`sum` 전이를 비트까지 재현한다. 발동 조건(어느 노드에서 갱신·감쇠가 일어나는가)도 포함한다. 표 A의 모든 `cnt`·`sum` 변화가 관측한 사건으로 설명된다(사슬·종료 스냅숏 검사).
- 제외 범위와 후속:
  - 표 B(`M+0x3258`)의 환산비용 갱신(`5fb8ec` `0x514de3`·`0x514e2a`, C:806–858)과 표 C: 사건은 기록하지만 입력 해석은 하지 않는다(후속 M2-06e-2).
  - strong branching 경로(`62f909`·`64427c`)와 `6755af`·`67eb3e`의 `6edfcf` 호출: 전후 상태와 `6edfcf` 자체 식만 검사하고, 호출자 입력(SB LP 결과)은 M2-06g에서 다룬다. SB 캐시(`+0x20`–`+0x40`, `6ee5d1`)도 06g.
  - 병렬 표 복사·병합(`6eca1a`·`6ecf59`·`6ed2ad`·`6ed6a1`): Threads=1만 다룬다. 실행되면 횟수를 기록한다.
  - 재시작 등에서 이전 표를 평균으로 물려받는 초기화(`6ec3da`의 시드 경로): 실행되면 규칙을 검사하고, 0회면 C·asm만으로 남긴다.
  - 표를 읽는 쪽(`6ef12f` 이득 추정, `6eed2e` 신뢰성, 점수): M2-06g·후속.
- 선행: main `e5c3eb8`, 미커밋 선행 변경 없음.

## 2. 원본과 상태 경계

- Gurobi 13.0.3 `libgurobi130.so` SHA-256 `8e87fca221fdffc922331c8619426031b3e72dfd419446422f88af0cb0e98f9c`. 주소는 file offset. 상수는 `.rodata`에서 직접 읽었다.

### 2.1 표 A와 초기화 `6ec3da`

- 표(0x80 B): `+0x00`/`+0x08` int `cnt_down`/`cnt_up`, `+0x10`/`+0x18` double `sum_down`/`sum_up`, 길이 n+m(`T+0x70` = M, M+8→+0xe8의 +0xc = 열 수, +8 = 행 수). 노트 15 §4.6.
- `5daa82`가 `6ec3da(M, src, map, &M+0x3250)`(`0x4fc90c` 시드 경로, `0x4fc937` 새 표)와 표 B·C(`0x4fc95f`·`0x4fc983`, 항상 새 표)를 만든다. 이 밖에 `M+0x3250`을 쓰는 명령은 바이너리 전체 objdump에서 없었다(`lea 0x3250(` 4곳·`,0x3250(` 쓰기 0곳).
- `6ec3da`(C 전문): 네 배열을 0으로 채우고 `+0x60` η = 1, `+0x64` = 0, `+0x68` = 0, `+0x70` = M, `+0x78` = 0. `src`·`map`이 있고 `M+0x620→+0x850 == 0`이면 j < 열 수에 대해 `map[j] < 0`에서 멈추고(`break`), `cnt_down_src[map[j]] ≠ 0`이면 `sum_down[j] = sum_down_src/cnt_down_src`(위쪽도 같음), `cnt`는 0으로 둔다. 끝에서 `+0x850 = 0`.

### 2.2 갱신 `6edfcf(f, Δ, T, j)` (asm `0x5b7330`–`0x5b73c7`)

```text
g = maxsd(Δ, 1e-10)                     # .rodata 0x2a6e5e0 = 1e-10; NaN이면 1e-10
f > 0: dir = up,   g = g / (f + 0.001)  # 0x2a6e5e8 = 0.001
f < 0: dir = down, g = g / (0.001 - f)
f == 0(또는 NaN): 아무것도 안 함
cnt[dir][j] == 0: sum = maxsd(sum, g)   # 같거나 NaN이면 g
그 밖:            sum = g + sum
cnt[dir][j] += 1; 변경 목록(+0x48/+0x50/+0x58)에 j 추가
```

호출자: `5fb8ec`(표 A 노드 갱신 2곳, 표 B 2곳), `62f909`, `64427c`, `6755af`, `67eb3e`.

### 2.3 노드 갱신 `5fb8ec` C:546–594 (asm `0x511277`–`0x511407`, `0x514e47`–`0x514ea5`)

블록 입구 `0x511277`은 `jne` 3곳(`0x510a28`·`0x510c56`·`0x510cea`)에서만 온다. N = `[rsp+0x130]`, I = N+0x18, J = `[rsp+0x60]`(분기 정보: +0x10 LP 목적, +0x34 변수, +0x38 분기 값 x, +0x40 방향 문자), M = rbp.

```text
발동: N+0x10(부모) != 0 이고 I+0x28(상태) != 7 이고 J+0x34(변수 j) >= 0
cutoff = M+0x620→+0x3220→+0x40 (풀 없으면 1e100)            # 5e7204
T = 5e2919(M) == 0 ? M+0x3250 : W+0x3ff0                       # Threads=1이면 앞쪽(캡처로 확인)
w = pow(0.8 / ((double)I+0x2c + 1.0), cutoff < 5e99 ? 0.1 : 0.2)
f = '<' ? (연속 ? -0.5 : floor(x) - x) : (연속 ? 0.5 : ceil(x) - x)
p = I+0x78(부모 LP 목적); p <= -1e100 이면 끝
상태 4·5: cutoff < 5e99 이면 6edfcf(f, w·(cutoff - p), T, j)
상태 1·2: 6edfcf(f, (J+0x10 - p)·w, T, j)
그 밖: 없음
```

상수: `0x2a6c4d8` = 0.8, `0x2a6c558` = 1.0, `0x2a6c4d0` = 5e99, `0x2a6c4e0` = 0.1, `0x2a6c4e8` = 0.2, `0x2a6c4f8` = 0.5, `0x2a6c4f0` = −0.5, `0x2a6c500` = −1e100. w는 `[rsp+0x18]`, cutoff는 `[rsp+0x20]`에 저장된다.

### 2.4 감쇠 `5fe9cd` C:97–123 → `6ee1d3(N, T)`

`5fe9cd` 진입에서 T = (`*plVar4`)+0x3250, 즉 노드 M의 전역 표 A다(스레드 복사본이 아님). `0x51679f`에서 N = r15, K = rbx(+0x10 LP 목적, +0x34 변수), I = N+0x18.

```text
(앞에서) cutoff < K+0x18 이면 I+0x28 = 5
발동: N+0x10 != 0, K+0x34 >= 0, 상태 != 9, p = I+0x78 > -1e100,
      그리고 (상태 4·5 또는 (상태 1·2 이고 K+0x10 - p > 1e-10))   # 0x2a6c538
6ee1d3: L = I+0x08. L+0x38 == 6 또는 L+0x58 >= 0 이면 v = L+0x70, 아니면 (L+0x18 == 0 이면 끝) v = L+0x28. v == 0 이면 끝
        L+0x58 < 0: w = 0.5, s = 1.0;  그 밖: w = 1.0, s = (double)L+0x54
        A = N+0x10 부터 부모로: A != 0 이고 w > 0.001 이고 A+0x18 != 0 인 동안
           w = w·0.5; j = A.I+0x34; j >= 0 이면
             s' = A.I+0x40 == '<' ? s : -s
             s'·v[j] >= -1e-10 이면 sum[dir][j] = (1 - w/((double)cnt[dir][j] + 1.0))·sum[dir][j], 변경 목록에 j
```

asm의 연산 순서와 상수는 결과 절에서 확인한다.

## 3. 비교 계약

`tools/mip_pseudocost_check.py`가 판정한다. 하나라도 실패하면 종료 코드 1이고 첫 차이(사건 번호·표·j·기준값·실제값)를 출력한다. 부동소수는 u64 16진수 비트로 비교한다(±0 구분). 수치 오차는 허용하지 않는다.

| 검사 | 규칙 |
|---|---|
| C1 재현성 | 사례마다 원본 3회 gz 바이트가 같다. `ok`, `errors` 없음, `tool_sha256`이 현재 도구와 같다, 파라미터가 `{Threads 1, Seed 0, LogToConsole 0, NodeLimit 2000}`. manifest SHA-256과 같다 |
| C2 초기화 | `6ec3da` 새 표: 0이 아닌 항목 없음, η = 1, `+0x64` = 0, `+0x68` = 0. 시드 경로(src·map 있고 `+0x850 == 0`): §2.1 식(첫 음수 map에서 멈춤, 평균, cnt 0)과 비트까지 같다. `6eca1a` 복사: 원본 표의 재생 상태와 같다 |
| C3 노드 갱신 | `5fb8ec` 블록 입구 사건마다 §2.3 발동 판정이 바로 뒤 `6edfcf` 호출 유무·호출 지점(n12/n45)과 같다. 호출된 표는 그 M의 표 A다. 스택 w가 Python `math.pow` 결과와 비트까지 같고 cutoff 칸이 입구에서 읽은 값과 같다. `6edfcf` 뒤 항목이 §2.2 식과 비트까지 같다 |
| C4 감쇠 | `5fe9cd` 감쇠 입구마다 §2.4 발동 판정이 바로 뒤 `6ee1d3` 사건 유무와 같고 표가 표 A다. `6ee1d3` 뒤 항목이 §2.4 식(조상 순서대로 적용)과 비트까지 같다 |
| C5 대칭 전파 | `6ef22e` 전 상태가 재생 상태와 같고, 뒤 상태가 §6.1 규칙의 결과와 같다 |
| C6 사슬 | 표마다 모든 사건의 전 상태가 직전까지 재생한 상태와 같다. 다른 호출자(`62f909`·`64427c`·`6755af`·`67eb3e`·`5fb8ec` 표 B)의 `6edfcf`는 한 방향 cnt가 1 늘고 반대쪽이 그대로인지만 본다. 해제(`6edb26`) 직전 표 전체(0이 아닌 항목)가 재생 상태와 같다. 해제되지 않은 표 0, 병렬 병합·초기화 경로 호출 0 |
| C7 비간섭 | `ins` 사건 열(in_sel, from, tree, 노드 8필드, heap_n)과 출력 줄이 같은 설정의 M2-06b-2 run 1과 같다 |
| C8 분기 | 6사례 합계에서 n12, n45, cutoff 미발동, clamp, cutoff 없는 n12, 감쇠 적용·부호 제외, `L+0x58` 음·양, LP 상태 6, 벡터 없음, LP 정보 없음, 대칭 변경, 시드 초기화, cnt 0 갱신, 다른 호출자 갱신이 모두 1회 이상 |
| T 변조 | (`--self-test`) run 1 사본에 10종(노드 갱신 결과 비트, 입구 depth, cutoff 없는 4·5 입구에 cutoff 1, 바뀐 감쇠 사건 삭제, 감쇠 벡터 부호, 해제 스냅숏, 새 표 스냅숏, 대칭 뒤 상태, 다른 호출자 두 방향 증가, 힙 삽입)을 넣으면 각각 실패 |
| V 변이 | (`--self-test`) Python 규칙의 한 절을 바꾼 변이가 아래 분기 수 규칙대로 거부·생존한다 |

V의 기대는 공식 캡처 전에 탐색 sweep(38모델 NodeLimit 500, §6.1)에서 정했다. "분기 수 > 0인 사례에서만 거부"이고, 38모델 모두에서 이 규칙이 실제 거부 집합과 같았다.

| 변이 | 바꾼 절 | 거부 조건(그 사례의 분기 수 > 0) |
|---|---|---|
| P1 | 지수 0.1 ↔ 0.2 | n12 + n45 |
| P2 | depth + 1 → depth | n12 + n45 |
| P3 | 분모 0.001 → 0 | n12 + n45 |
| P6 | w = 1 | n12 + n45 |
| P4 | cnt 0에서 max 대신 더하기 | 0이 아닌 sum에 cnt 0 노드 갱신(sweep 0회 → 생존 기대) |
| P5 | 1e-10 하한 제거 | Δ ≤ 1e-10 노드 갱신 |
| P8 | 상태 4·5에서 cutoff < 5e99 조건 무시 | cutoff 때문에 미발동한 입구 |
| G1 | 감쇠 입구의 `lp − p > 1e-10` 조건 무시 | 그 조건만으로 미발동한 입구 |
| D1 | w 반감을 적용 뒤로 | 0이 아닌 sum에 감쇠 적용 |
| D2 | cnt + 1 → cnt | 0이 아닌 sum에 감쇠 적용 |
| D3 | 부호 조건 제거 | 0이 아닌 sum이 부호 조건으로 제외됨 |
| D4 | s = `L+0x54` 대신 1 | `L+0x58 ≥ 0`이고 두 s로 판정이 갈리는 0이 아닌 sum |
| S1 | 대칭 대표를 같은 평균의 뒤 열로 | 같은 평균인데 항목이 다른 열(sweep 0회 → 생존 기대) |
| S2 | 대칭 전파 없음 | 대칭 단계가 표를 바꿈 |
| Z1 | 시드에서 음수 map을 건너뜀 | 끝 전에 음수 map(sweep 0회 → 생존 기대) |
| Z2 | 시드에 평균 대신 합 | cnt > 1인 원본 항목(sweep 0회 → 생존 기대) |

- 시간·work·병렬: Threads=1, 종료는 NodeLimit 2000. Threads > 1의 표 복사·병합은 범위 밖이다(C6이 호출 0을 요구).
- 원본 재현성: 같은 설정 3회 독립 실행의 gz 바이트 비교(C1).

## 4. 사례와 원본 자료

모두 실제 MIPLIB 입력이다(`../re/bench/data/miplib/<사례>.mps.gz`). M2-06b-2와 같은 6사례·설정이라 C7 기준이 있다.

| 사례 | 노리는 분기(sweep 500 기준) |
|---|---|
| markshare_4_0 | n45 다수, Δ 하한, `L+0x58 ≥ 0`·s ≤ 0(D4) |
| pk1 | n12·감쇠 일반, D4 |
| neos5 | 대칭 전파(`6ef22e` 변경) |
| tr12-30 | 다른 호출자 갱신 다수, 감쇠 |
| fhnw-binpack4-4 | incumbent 없음: cutoff 미발동(n45 0회)·cutoff 1e100 n12, 대칭 전파 |
| neos-860300 | sub-MIP 시드 초기화, 벡터 없는 감쇠, 분기 변수 없는 입구 |

- 캡처 도구: `tools/mip_pseudocost.js`(읽기 전용, 사건 §2·도구 머리말). 기준 자료: `bench/oracle/m2_06e/`(manifest·`<사례>_<회>.json.gz`).
- 적용하지 않은 범주: 연속 변수 분기(`'C'`, sweep 0회), 노드 상태 7 외 비발동 상태·p ≤ −1e100(0회, 상태 7은 sweep 5모델에서만), 병렬. w가 0.001 이하로 줄어 멈추는 감쇠(조상이 그보다 얕음, sweep 0회).

## 5. 재실행 명령

```sh
for m in markshare_4_0 pk1 neos5 tr12-30 fhnw-binpack4-4 neos-860300; do for r in 1 2 3; do
  tools/gurun.sh node tools/mip_pseudocost.js ../re/bench/data/miplib/$m.mps.gz bench/oracle/m2_06e/${m}_$r.json.gz '{"NodeLimit":2000}'
done; done
python3 tools/mip_pseudocost_check.py --write-manifest   # 처음 한 번
python3 tools/mip_pseudocost_check.py                    # C1–C8
python3 tools/mip_pseudocost_check.py --self-test        # + T, V
python3 tools/mip_pseudocost_check.py --sweep <캡처>...  # 탐색(판정 근거 아님)
```

회귀: Rust·Python 패키지를 바꾸지 않으므로 cargo·pytest는 해당 없음. 같은 `5fb8ec`·`5fe9cd` 지점을 쓰는 기존 검사기는 없다.
