# M2-03b-1 선형 무계 재분류와 보류 소비 조사

## 1. 범위와 주장

- 종류: 조사와 조사용 원본 구간 검사. 검증 기준은 [스프린트 검증 기준](../15_sprint_verification.md)이다.
- 질문: `5ce67b`의 LP 상태 5→12 조건, 즉시 재풀이 조건, `600d25`가 쓴 노드 상태 3의 소비자와 큐 재등록 경계를 확정한다.
- 포함: 선형 모델의 루트 캐시, 현재 노드와 루트의 동일성, 상태 재분류, 수치 재풀이 진입과 최종 변환, `5fb8ec`·`5c239f`·`5ff14d`·`5fe9cd`의 소비 조건.
- 제외: 추가 제약의 ray 검사는 M2-03b, 실제 자식 무계 재현은 M2-03c, Rust 변경은 M2-03d다. 조사만으로 구현 동등성을 주장하지 않는다.
- 선행: M2-03a가 병합된 main `24d62bc`. 시작 시 미커밋 변경과 다른 worktree, 영역 점유가 없었다. `work/m2-03b-1`과 독립 worktree에서 작업한다.

## 2. 원본과 상태 경계

- 기준: Gurobi 13.0.3, Linux x86-64. 바이너리 SHA-256 `8e87fca221fdffc922331c8619426031b3e72dfd419446422f88af0cb0e98f9c`.
- 원본: `../re/decomp/c/`의 `5ce67b`, `600d25`, `5fb8ec`, `5c239f`, `5ff14d`, `5fe9cd`, `5ff754`, `5f9d4e`, `5fa560`. 주소는 파일 첫 행의 ELF 오프셋을 사용한다. Ghidra 주소에는 `0x100000`을 더한다.
- 정적 조사 시작은 LP 결과 상태 정규화 직전, 종료는 재풀이와 노드 마무리 분기다. 호출자 전체 실행 동등성은 검사하지 않는다.
- 실행 검사는 호출 없는 `5ff754(node, 3)`와 재등록 게이트 `5ff14d(&node, M, NULL)`의 조기 반환을 포함한다. 후자는 상태 `{0,1,2,3,4,5,6,9,11}`만 호출한다. `{7,8,10}`은 실제 큐·allocator·lock 문맥이 필요하므로 정적으로 확인한다.
- 상태 3의 소비자 추적에서 `60145b`의 분기 자격 검사를 발견해 실행 범위에 추가했다. 상태 1은 추가 predicate를 호출하므로 이 함수에 한해 제외한다. 기존 계약 사례와 실패를 제거하지 않았다.
- 입력: 합성 `N+0x18→I`, `I+0→M`, `M+8→model`, `model+0x100→env`, `M+0x620→top`. 할당 버퍼의 전체 바이트를 비교하며 실제 basis·domain·RNG·타이머는 구성하지 않는다.
- setter는 `I+0x28`만 3으로 바꾼다. 재등록 게이트 조기 반환은 반환값 0, node holder와 모든 버퍼 보존을 요구한다. 실제 모델에서 얻은 노드의 증거로 쓰지 않는다.

## 6. 재분류와 즉시 재풀이

필드 이름은 M2-03a와 같다. `N`은 현재 노드, `I=*(N+0x18)`, `M=*(I+0)`, `L`은 LP 결과 정보, `W+8`은 relaxation 모델이다. `M+0xa8`은 루트 relaxation 캐시이며 `M+0`·최상위 `*(M+0x620)+0`·`I+0x28`과 별개다.

| 입력과 문맥 | 출력과 다음 경계 | 근거 |
|---|---|---|
| 루트 캐시 2, 현재 LP 상태 5 | `L+0x38=12`. 현재 노드의 루트 동일성과 무관 | `5ce67b`:750–752, ELF `0x4f1aaa`→`0x4f5f7b`→`0x4f5f84` |
| 루트 캐시 2, 현재 LP 상태 4 | `L+0x38=3` | 같은 블록 `0x4f5f91`–`0x4f5fa2` |
| 루트 캐시 -1, 현재 노드가 루트 | LP 상태를 캐시에 저장. 상태 5이고 추가 제약 네 종류가 모두 0이면 `M+0=5` | `5ce67b`:740–745, `0x4f5fa7`–`0x4f6007` |
| 루트 캐시가 -1·2 이외, 현재 노드가 루트 | LP 상태 2·5일 때 캐시를 갱신. 선형 상태 5이면 `M+0=5` | `5ce67b`:754–761, `0x4f5f12`–`0x4f5f76` |
| 재분류 후 상태 12, 캐시 2 또는 현재 노드가 루트 | 즉시 수치 재풀이 블록으로 진입 | `5ce67b`:769–773, `0x4f5ee8`–`0x4f5f0d` |
| 위 진입에서 원래 env의 `GURO_PAR_FEASHELPER=-2` 또는 원래 모델 `+0x1a0!=NULL` | 최상위 MIP 상태 13, setter로 노드 상태 3, 즉시 반환. `600d25` 호출과 카운터 증가를 거치지 않음 | `5ce67b`:774–779, `0x4f53a8`–`0x4f53d3`, `0x4f5ea2`–`0x4f5ee3` |
| 재풀이 뒤에도 상태 12가 남아 마지막 변환에 도달 | 저장 basis·norm 등을 정리한 뒤 `600d25`가 노드 3으로 바꿈. 캐시 2에서도 최상위 `+0xd4` 증가 | `5ce67b`:2244–2259, `600d25`:1033–1051 |

`5ce67b`는 재풀이 뒤에도 같은 상태 정규화 규칙을 적용한다. C:873·993·1578·2032에도 5→12 쓰기가 있다. 최초 재분류만 검사하고 재풀이가 성공했다고 가정하면 안 된다. 직접 setter로 나가는 노드 3과 `600d25`가 반환한 노드 3의 카운터 부수효과도 다르다.

기본 선형 경로에서 basis 조합과 모델 predicate가 LP driver 재풀이를 선택하면, 원본은 relaxation의 Presolve=1, Threads=1과 선택 Method·ConcurrentMethod를 설정한다. `GURO_PAR_RELAXPREP>=0`이면 Presolve를 그 값으로 덮어쓴다. workspace를 해제한 뒤 `0c3d0d`를 호출하고 Method·ConcurrentMethod·Presolve·Threads를 복구한다. 오류 10020은 relaxation 상태 12로 바꾸며 다른 오류는 전파한다. basis가 있고 특정 norm 정보가 없는 분기는 `cda5b` 또는 `14abfb`를 사용한다. 이 선택의 전체 수치 동등성은 실행하지 않았다. 근거는 `5ce67b`:782–1039와 저장 어셈블리 `0x4f53a8`–`0x4f56a2`다.

## 7. 노드 상태 3의 소비와 후속 처리

상태 3은 **즉시 같은 노드를 큐에 다시 넣으라는 뜻이 아니다**. worker는 상태 3을 분기 대상으로 넘길 수 있다.

| 경계 | 상태 3에서의 행동 | 원본 근거 |
|---|---|---|
| `5fb8ec`의 LP 호출 루프 | 상태가 0이 아니면 후처리로 이동. 상태 1·2 전용 해·점수 갱신은 건너뜀 | C:546–596·800–805·2759–2779 |
| `5c239f`의 휴리스틱 | 노드 상태 2 전용 `8ad3a3` 호출을 건너뜀 | C:415–422 |
| `60145b(N)` | `(I.status & ~1)==2`, 즉 상태 2·3이면 참 | C:12, ELF `0x519b1b`–`0x519b26` |
| `5c239f` → `627f3e` | 분기 자격이 참이면 자식 생성 호출 | C:429–441 |
| `627f3e` | 상태 2만 `62a05d` 후보 평가로 진입. 상태 3은 대체 분기 블록으로 진입 | C:87–88·697 이후, ELF `0x53212c`–`0x532136` |
| `5ff14d(&N, M, worker)` | 상태 `{7,8,10}`만 같은 노드 재등록. 상태 3은 반환값 0이며 holder와 상태를 보존 | C:17–19, ELF `0x5176c4`–`0x5176da` |
| `5fe9cd` | 콜백·후처리 이후의 상태가 `{7,8,10}`일 때만 재등록. 그 밖에는 자식 수 0이면 해제, 자식이 있으면 mode 3으로 내부 노드를 유지 | C:139–202, ELF `0x516874`–`0x5168e5` |

따라서 게이트에 상태 3을 넣어 재등록이 없음을 확인하는 검사만으로 탐색이 끝났다고 판정할 수 없다. 그 전에 만들어진 자식의 후속 실행을 함께 확인해야 한다. `5fe9cd` 앞의 콜백과 `6fdec9`도 실제 문맥에서 관측해야 한다.

### 대체 분기에서 읽는 정보와 넘기는 상태

`627f3e`의 비상태2 블록은 현재 domain `I+0x80/0x88`, 변수 타입 `M+0x650`, LP 모델 상태와 현재 해 `*(I+8)+0x18`, 모델의 추가 제약 배열, 전역 또는 worker의 pseudocost 표를 읽는다. 선형 경로의 핵심 경계는 다음과 같다.

- 실제 relaxation 모델 상태가 5이고 현재 해 포인터가 있으면, 큰 절대 bound와 현재 해 방향으로 우선 후보를 찾는다. `L.status`의 재분류 값과 `relaxation_model+0x64`의 상태는 서로 다른 저장소다.
- `7970f2`는 모델 `D+0xf0/f4`로 지정한 보조 변수 구간을 검사한다. 반환 후보가 없고 추가 제약도 없으면 정수 변수의 domain을 순회한다. 폭 `>=1e-10`인 이진·정수 후보를 검사하고, 일반 정수의 유한 양쪽 bound에는 `floor((lb+ub)*0.5)`를 사용한다. 무한쪽에는 10000 주변 분할 또는 유한쪽 bound의 2배를 사용한다. 이진 후보 점수의 전체 부동소수 일치는 이번 범위 밖이다.
- 후보 kind 0이면 `5ff358`로 down·up 자식을 순서대로 만들고 `603386`으로 분기 bound를 기록한다. `6c4eee`의 추정과 부모 bound를 자식 bound에 반영한다. 이 과정이 성공해야 자식 목록을 소비할 수 있다.
- 정수 후보가 없고 폭을 가진 연속 변수가 남으면 `5ff358`로 자식 한 개를 만들고 **자식 상태를 10**으로 설정한다. 이 자식이 이후 재등록 게이트의 대상이 될 수 있다. 상태 3 부모 자체를 상태 10으로 바꾸는 코드가 아니다. 근거는 C:1084–1095, ELF `0x532b62`–`0x532bb7`이다.
- 후보와 가변 연속 변수가 모두 없으면 bound로 구성한 해를 `6fb96f`에 제출하고 성공 시 노드 상태 5를 쓴다. 상태 3만으로 무계나 Numeric을 확정하지 않는다.

위 내용은 C와 어셈블리로 확인한 경계다. 정수 후보의 순서·동점·무한 bound 분할 수치·자식 basis·allocator·후속 선택까지 실행 검증한 결과는 아니다. Rust `bnb.rs`의 자식 `Numeric | Unbounded → Numeric` 종료와 동일하다고 보고할 수 없다.

### 후속 오라클의 훅 경계

| 원본 경계 | 저장할 내용 |
|---|---|
| `5ce67b` 진입과 각 Status 정규화 전후 | `&N`의 교체, N의 부모 `+0x10`·깊이 `I+0x2c`·id `+0`, 루트 동일성, `L.status`·실제 LP 모델 상태·루트 캐시·MIP 상태 |
| `0x4f1a98`과 `0x4f1aca` | 첫 정규화의 `r12=M`, `r13=L`, `[rsp+0x3b0]=N`, 관련 카운터. 재풀이 정규화는 별도 주소로 식별 |
| `0c3d0d`·`cda5b`·`14abfb` 입출력 | 재풀이 method·basis·domain·오류·실제 상태, 파라미터 복구 |
| `600d25` 입출력 | `rdi=N`, `rsi=L`, `rdx=W`, `rcx=work`, 노드 상태와 top `+0xd4` |
| `60145b`와 `627f3e` 입출력 | 분기 자격, 부모·자식 상태·id·domain, 순서와 kind·변수·분할값 |
| `5ff14d`·`5fe9cd`·자식의 다음 `5ce67b` | 같은 부모의 재등록과 새 자식 처리를 구분, 상태 10의 소비와 holder 해제 여부 |

`627f3e`의 Ghidra 시그니처는 부동소수 인자를 정확히 표현하지 못한다. ELF `0x5320d1`–`0x5320f3`에서 실제 ABI는 `xmm0=budget`, `rdi=&N`, `rsi=worker`, `rdx=W`, `rcx=children`, `r8d=flag`, `r9=work`다. 후속 훅은 C의 선언 순서를 그대로 복사하면 안 된다. 실제 자식 판정에는 부모 포인터와 깊이를 사용하며 루트 로그만으로 대체하지 않는다.

최상위 `+0xd4`가 단순 재시도 횟수라는 해석은 채택하지 않는다. 이번 조사에서 확인한 소비자 `6a0962`:183–190·387–391은 보조 풀이·재시작 선택을 제한한다. 전역 종료 상태 전체에 미치는 영향과 추가 소비자는 후속 실제 추적에서 확인한다.

## 8. 실행 결과

- Python 3.13 가상환경, Linux x86-64, Gurobi 13.0.3 원본 독립 프로세스 3회가 일치했다. 매 실행 setter 18개·재등록 조기 반환 18개·분기 자격 16개, 총 156회 원본 함수를 호출했다. 상태 3은 두 루트 문맥 모두 분기 자격 참, 같은 노드 재등록 없음이었다.
- setter의 상태 4바이트 이외, 분기 자격 검사와 재등록 게이트의 모든 합성 버퍼·holder가 보존됐다. 실패 0, xfail 0이다. 분기 자격의 상태 1 두 문맥은 계약에 명시한 제외이며 실행 통과 수에 넣지 않았다.
- 저장 기준 재생과 오류 주입 4개가 통과했다. setter 상태·분기 자격·재등록 반환값·버퍼 보존 여부를 각각 바꾸면 첫 차이의 run·case·필드·기준·실제값·정확 비교 규칙을 출력하며 거부했다.
- 기존 M2-03a 13개×3회 캡처의 저장 회귀와 Python 문법 검사가 통과했다. 원본 재캡처와 혼동하지 않는다.
- 새 캡처 SHA-256은 `4133b455a209a727c7657e31c69033aba1fe5a9ec9f42fe3e79b4e16baa388b9`이다. C 15개·어셈블리 10구간·도구·캡처 해시는 [manifest](../../bench/oracle/mip_unbounded_reclassification_sources.json)에 있다.
- LP 재분류·즉시 재풀이·대체 분기 전체·실제 자식 연결은 정적 조사 결과다. 원본 호출자 전체 실행이나 Rust 구현 동등성은 미검증이다. Rust·Python 통합 회귀는 솔버 코드 변경이 없어 실행하지 않았다.

## 9. 판정과 인수인계

M2-03b-1 조사는 완료다. 선형 상태 재분류·즉시 재풀이·상태 3의 분기 소비·상태 10 자식 생성과 재등록 경계를 특정했다. 합성 원본 구간 검사만 통과했으며 Rust 동등성과 실제 자식 연결은 미검증이다.

다음은 M2-03c-1의 선형 호출자·대체 분기 오라클이다. 먼저 같은 입력을 캡처할 훅을 만들고, 실제 자식임을 부모·깊이·루트 동일성으로 확인한다. 상태 주입으로 경계를 검사한다면 합성 실험으로 기록하고 실제 자식 무계 사례와 구분한다. 이후 M2-03d 구현은 원본 비교가 가능한 분기 하나만 선택한다. 추가 제약 ray의 M2-03b는 별도로 남는다.

작업 branch는 `work/m2-03b-1`이며 선행 미커밋 변경은 없다. 상세 결과는 작업 branch에서 작성해 검증 후 `--no-ff` 병합한다. 종료 branch·검증·다음 명령은 [M2 인수인계](../handoff/M2.md)에 기록한다.
