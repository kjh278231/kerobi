# M2-03d-7 검증 계약과 결과: B&B 노드 LP simplex ws의 빈 행 출처

작성 기준은 [스프린트 검증 기준](../15_sprint_verification.md)이다. 배경은 [M2-03d-6](mip_retry_bnb_node_lp.md) §6 C2다. 03d-6은 nidda 노드 16948 재풀이에서 simplex ws가 API LP에서 96행(R)을 비운 LP임을 캡처했지만 출처를 확인하지 못했다. 03d-6 인수인계의 제안 항목이고, 사용자의 "다음 스프린트 진행" 지시로 착수했다(2026-11-10).

## 1. 범위와 주장

- 작업 종류: 조사(원본 실행 훅으로 답한다)와 그 근거의 오라클 고정. Rust 솔버 코드는 바꾸지 않는다.
- 조사 질문:
  - Q1. 노드 16948 재풀이의 `02f7e1` 반환 시 ws CSC(`ws+0x70/0x78/0x80/0x88`)와 b(`ws+0xa0`)는 D(`lp+0xe8`)의 `+0xf8/+0x100/+0x108/+0x110/+0x380`과 같은 메모리인가. 다르면 그 포인터를 가진 lp·D 필드는 무엇인가. `08b2fe` 반환값은 `lp+0xe8`인가.
  - Q2. 재시작 뒤 B&B 본 탐색의 노드 LP 수명에서 ws와 D의 열 길이·rhs가 처음 갈라지는 시점은 언제인가(ws 생성, 행 추가, 노드마다 등).
  - Q3. ws 열 길이를 줄이고 b를 0으로 두는 원본 함수와 그 조건은 무엇인가.
- 정적 사실(C, 이번 착수 전 확인): `02f7e1`(`0xd06f0`) C:569는 `lp+0xe0`(ws)이 null이 아니면 `return 0`이다. CSC 포인터 대입 C:896–908은 ws를 새로 만들 때만 실행된다. 03d-6 캡처에서 k=1·k=2 모두 `cda5b` 진입 시 ws가 있었다. 따라서 03d-6의 갈래("`08b2fe`가 다른 자료를 돌려줌" 또는 "`02f7e1` 안에서 D 길이가 바뀜")는 이번 호출을 설명하지 못할 수 있다. 03d-6 캡처의 D `nnz_end` 4955는 API nnz 4955와 같고 ws nnz는 1840이다.
- 포함 사례: `neos-3754480-nidda`, 03d-5·03d-6의 H 설정 seed 1, 재풀이 노드 16948(call 19901).
- 제외 범위와 후속:
  - Rust 재생(L2)과 `bnb.rs` 연결은 M2-03d-4다.
  - R의 행 선택 규칙을 Rust로 옮기는 일은 이번 범위 밖이다. 규칙이 드러나면 후속 번호로 제안한다.
  - 2행 sense 변경(225, 375), 86행 cut 종류는 다루지 않는다.
- 선행: main `b5804da`. 미커밋 선행 변경 없음.
