# M2-06f 검증 계약과 결과: pseudocost 표 A Rust 이식

작성 기준은 [스프린트 검증 기준](../15_sprint_verification.md)이다. 원본 규칙과 기준 자료는 [M2-06e](mip_pseudocost.md)다. M2 인수인계의 첫 다음 작업이고, 사용자의 "다음 스프린트 진행" 지시로 착수했다(2026-11-11).

## 1. 범위와 주장

- 작업 종류: 구현(L1 저장 기준 재생). Gurobi는 실행하지 않는다(06e 기준 자료 재사용).
- 완료 후 주장할 것: 새 `crates/mip/src/pseudocost.rs`의 표(`Pseudocost`)와 다섯 연산(새 표·시드 `6ec3da`, 갱신 `6edfcf`, 노드 갱신 판정·w `5fb8ec` C:546–594, 감쇠 판정 `5fe9cd` C:119–123과 감쇠 `6ee1d3`, 대칭 전파 `6ef22e`)에 06e 여섯 사례 run 1의 사건 입력을 넣으면, 원본 캡처의 모든 판정(입구 12,442·감쇠 입구 12,450의 발동 유무), 노드 갱신 11,157회의 w 비트와 결과 항목, 감쇠 8,972회·대칭 4회·새 표 636개(시드 6)의 결과, 표 636개의 해제 직전 스냅숏이 비트까지 같다.
- 입력 전제: 재생 입력은 캡처 사건의 입력 칸(입구의 부모 유무·상태·depth·j·x·방향·변수형·lp·p·cutoff, 감쇠의 L 칸·조상 (j, 방향, v[j]), 대칭의 cls, 시드의 src·map)에서만 만든다. 기대값은 캡처의 결과 칸(`upd.after`·`w`, `dec.after`, `sym.after`, `new.nz`, `free.nz`)에서만 가져온다. 06e 검사기의 Python 규칙 재생 결과는 입력에도 기대값에도 쓰지 않는다. Rust는 새 표를 스스로 만들고(시드는 Rust가 들고 있는 원본 표에서) 끝까지 이어 간다. 사건마다 캡처 상태로 되돌리지 않는다.
- 다른 호출자(`62f909`·`64427c`·`6755af`·`67eb3e`·`5fb8ec` 표 B 쪽이 아닌 표 A 쪽의 SB 등) 갱신 37,452회는 입력 f·Δ가 캡처에 없다. 재생 입력에 `set`(캡처 `after` 주입)으로 넣고, 주입 직전 Rust 항목을 캡처 `before`와 비교한다. 이 항목은 Rust 연산의 검증이 아니라 사슬 유지다.
- 제외 범위와 후속:
  - `bnb.rs` 연결: 조상 I·부모 링크의 수명(06e §6)과 노드 LP 결과 벡터(`L+0x28`·`L+0x70`)의 의미가 미확인이다. 03d·06b처럼 이식만 한다. 후속 번호로 연결 전 조사를 둔다.
  - 변경 목록(`+0x48`/`+0x50`/`+0x58`): 06e 6사례의 `upd` 사건 모두 `chg`·`chg_after`가 0이다(목록 포인터 null, Threads=1). Rust에 넣지 않는다.
  - η(`+0x60`)·`+0x64`·`+0x68`·`+0x78` 머리 칸: 06e C2가 새 표 값만 검사했고 이 연산들은 쓰지 않는다. Rust에 넣지 않는다.
  - 표 B·C, 병렬 복사·병합(`6eca1a` 등), 다른 호출자의 입력 계산(06e-2·06g), 표 선택 `5e2919`(Threads=1이면 표 A).
- 선행: main `49c622d`(M2-06e 병합 포함), 미커밋 선행 변경 없음.

## 2. 원본과 상태 경계

- Gurobi 13.0.3 `libgurobi130.so` SHA-256 `8e87fca221fdffc922331c8619426031b3e72dfd419446422f88af0cb0e98f9c`. 주소는 file offset.
- 이번에 다시 읽은 C·asm(`../re/decomp/`):

| 함수 | 위치 | 옮길 규칙 |
|---|---|---|
| `6ec3da` `0x5b6690` | C 전문 | 길이 n+m 네 배열 0. `+0x850 == 0`이고 src·map이 있으면 j < 열 수에서 `map[j] < 0`이면 멈춤, `cnt_src ≠ 0`인 방향만 `sum = sum_src/cnt_src`, cnt 0 |
| `6edfcf` `0x5b7330` | C 전문, asm `maxsd` | `g = Δ > 1e-10 ? Δ : 1e-10`(asm maxsd, NaN이면 1e-10; Ghidra의 `<=`는 NaN에서 다름). f > 0 위, f < 0 아래(`g/(0.001 − f)`), 그 밖 반환. cnt 0이면 `sum > g ? sum : g`, 아니면 `g + sum`. cnt += 1 |
| `5fb8ec` C:546–594 | asm `0x5112a7`–`0x511402`, `0x514e47`–`0x514ea5` | 부모 있음·상태 ≠ 7·j ≥ 0. w = `pow(0.8/((double)depth + 1.0), 5e99 > cutoff ? 0.1 : 0.2)`. f: `'<'`면 (`'C'` ? −0.5 : `floor(x) − x`), 아니면 (`'C'` ? 0.5 : `ceil(x) − x`). `−1e100 >= p`면 끝(asm `jae`, NaN은 계속; Ghidra 표기와 다름). 상태 4·5는 `5e99 > cutoff`일 때 `w·(cutoff − p)`, 상태 1·2는 `(lp − p)·w` |
| `5fe9cd` C:119–123 | asm `0x51679f`–`0x5167f5` | 부모 있음·j ≥ 0·상태 ≠ 9·`!(−1e100 >= p)`, 그리고 상태 4·5 또는 (상태 1·2이고 `lp − p > 1e-10`) |
| `6ee1d3` `0x5b73d0` | C 전문, asm `0x5b73d0`–`0x5b7539` | L 없으면 끝. `L+0x38 == 6 || L+0x58 >= 0`이면 v = `L+0x70`, 아니면 `L+0x18`이 없으면 끝, v = `L+0x28`. v 없으면 끝. `L+0x58 < 0`: w 0.5·s 1, 아니면 w 1·s = (double)`L+0x54`. 조상마다(정보 있고 w > 0.001) w ·= 0.5, j ≥ 0이면 s' = `'<'` ? s : −s, `!(−1e-10 > s'·v[j])`이면 `sum = (1 − w/((double)cnt + 1))·sum` |
| `6ef22e` `0x5b7b20` | C 전문, 비교 asm `0x5b7c31` | 방향마다 j < 열 수: cnt > 0이면 v = sum/cnt, 클래스 대표가 없거나 `best < v`(엄격)이면 대표 = j. 그다음 j < 열 수에서 대표 r ≥ 0이면 cnt·sum을 r의 값으로 |

- 시작·끝: 표 하나의 상태(방향별 cnt·sum, 길이 n+m). 사건 하나는 원본의 한 호출(입구 판정과 `6edfcf`, 감쇠 입구 판정과 `6ee1d3`, `6ef22e`, `6ec3da`, 해제)이다.
- 입력: §1 입력 전제의 칸. 감쇠의 v는 조상 j 위치에만 캡처 값을 두고 나머지는 0인 길이 n+m 벡터로 만든다(`6ee1d3`은 조상 j만 읽는다). 같은 j가 다른 v 값으로 두 번 나오면 입력 생성에서 실패시킨다.
- 출력: 입구 판정(발동·w 비트), 지정한 항목(cnt 둘·sum 둘 비트), 표 전체의 0이 아닌 항목.

## 3. 비교 계약

`tools/mip_pseudocost_rust.py`가 판정한다. 하나라도 실패하면 종료 코드 1이고 첫 차이(사례·사건 번호·표·j·원본·Rust)를 출력한다. 부동소수는 모두 u64 비트로 비교한다(±0 구분, 수치 오차 없음).

| 검사 | 규칙 |
|---|---|
| M 입력 | 여섯 사례 run 1의 SHA-256이 `bench/oracle/m2_06e/manifest.json`과 같다(06e C1이 run 2·3을 같게 만든다) |
| X 재생 입력 | 사건에서만 만든다. 끝에 `end` 줄. 이전 trace를 지우고 실행. `new`의 `f`가 `6ec3da`가 아니거나, 병렬·bulk 경로 사건이 있거나, 표 B 등 모르는 표의 갱신이 있으면 실패 |
| G 입구 | 모든 `gate`마다 Rust 발동 유무 = 바로 뒤 `upd`(`site` 있음) 유무. 발동이면 Rust w 비트 = 캡처 `w`, Rust 결과 항목 = 캡처 `after` |
| D 감쇠 | 모든 `dgate`마다 Rust 발동 유무 = 바로 뒤 `dec` 유무. `dec`마다 캡처 `after`의 j 항목 = Rust 항목 |
| S 대칭 | `sym`마다 Rust 표의 0이 아닌 항목 = 캡처 `after` |
| N 새 표 | `new`마다 Rust 새 표(새 또는 시드)의 0이 아닌 항목 = 캡처 `nz` |
| F 해제 | `free`마다 Rust 표의 0이 아닌 항목 = 캡처 `nz`. 끝에 남은 표 0 |
| O 주입 | 다른 호출자 `upd` 직전 Rust 항목 = 캡처 `before` |
| K 개수 | 06e §6 합계와 같다: 입구 12,442(발동 11,157 = n12 9,012 + n45 2,145), 감쇠 입구 12,450(감쇠 8,972), 대칭 4, 새 표 636(시드 6), 해제 636, 주입 37,452 |
| T 변조 | Rust 출력 변조 5종(항목 sum 비트, w 비트, 입구 발동 줄, 줄 삭제, 해제 스냅숏)이 각각 거부된다 |
| V 변이 | `pseudocost.rs` 사본에 06e §3 V와 같은 절 변이를 넣어 다시 돌린다. 사례별 거부·생존이 아래 기대와 같아야 한다(06e §6 결과로 실행 전 고정) |

V 기대는 06e §3 V의 "그 절이 결과를 바꾼 분기 수 > 0인 사례에서만 거부" 규칙을 그대로 쓴다. 사례별 분기 수는 06e 검사기 `replay`의 통계(`VARIANTS`의 키 합)로 Rust 실행 전에 계산했다(§3.1).

## 4. 사례와 원본 자료

06e §4와 같다: markshare_4_0, pk1, neos5, tr12-30, fhnw-binpack4-4, neos-860300(실제 MIPLIB, NodeLimit 2000, Threads 1, Seed 0). 기준 자료 `bench/oracle/m2_06e/<사례>_1.json.gz`, manifest SHA-256. 캡처 도구 `tools/mip_pseudocost.js`(06e).

- 적용하지 않은 범주(06e에서 실행 0회, Rust는 C·asm대로 옮기되 미검증): 연속 변수 분기(`'C'` ±0.5), 상태 7·그 밖 상태·p ≤ −1e100의 미발동, w ≤ 0.001에서 멈추는 감쇠, 대칭 동률(S1), 시드의 음수 map 멈춤(Z1)·`+0x850 ≠ 0`, `6edfcf`의 f = 0·NaN, 감쇠 곱 NaN.
