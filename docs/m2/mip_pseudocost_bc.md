# M2-06e-2 검증 계약과 결과: pseudocost 표 B 갱신과 표 C 용도

작성 기준은 [스프린트 검증 기준](../15_sprint_verification.md)이다. 표 A와 갱신 함수 `6edfcf`는 [M2-06e](mip_pseudocost.md)를 따른다. M2 인수인계의 첫 다음 작업이고, 사용자의 "다음 스프린트 진행해. 너가 작업자야" 지시로 착수했다(2026-11-11).

## 1. 범위와 주장

- 작업 종류: 조사·오라클(읽기 전용 원본 캡처와 규칙 재생). Rust·Python 패키지는 바꾸지 않는다.
- 조사 질문:
  1. 표 B(`M+0x3258`)는 어디서 어떤 입력·조건·식으로 갱신되는가(`5fb8ec` C:806–858).
  2. 표 C(`M+0x3260`)는 누가 쓰고 누가 읽는가(용도). 쓰는 쪽의 Δ는 어떤 종류의 값인가.
- 완료 후 주장할 것:
  - 표 B: §2.2 규칙이 §4 사례 원본 실행의 표 B 갱신 전부(호출 유무·순서·j·방향·결과 비트)와 블록 work 증가를 재현한다. 표 B를 바꾸는 다른 경로가 없다(해제 스냅숏까지 재생 사슬 일치, 실행 범위 한정).
  - 표 C: 쓰는 곳·읽는 곳 지도(§2.3)를 C·asm과 실행 호출 수로 확인한다. `67eb3e`의 갱신은 Δ = 0 규칙으로 비트까지 재현하고, `6755af`의 갱신은 Δ가 0 이상 정수 또는 2e9인 `6edfcf` 호출로 비트까지 설명됨을 확인한다(Δ를 만드는 probing 내부는 범위 밖).
- 제외 범위와 후속:
  - `6755af`·`67eb3e`가 Δ를 만드는 probing 내부(`8950df`·`89668f` 등)와 언제 probing을 하는지: M2-06g(06e 인계에서 이미 배정) 또는 후속 번호.
  - 표를 읽는 쪽의 결과 계산(`6ef12f` 이득 추정, `6eed2e` 신뢰성 판정)의 실행 비교: 이번에는 호출 문맥과 표 식별만 센다. 식 검증은 M2-06g.
  - 병렬 표(`W+0x3ff8`·`W+0x4000`), Threads > 1: 범위 밖. 블록에서 쓴 표가 그 M의 `0x3258` 표인지(=Threads=1 경로) 확인만 한다.
  - 행(슬랙) 항목: 블록은 j < 열 수만 돈다(C·asm). 행 항목은 캡처하지 않는다.
- 선행: main `b667e62`, 미커밋 선행 변경 없음.

## 2. 원본과 상태 경계

- Gurobi 13.0.3 `libgurobi130.so` SHA-256 `8e87fca221fdffc922331c8619426031b3e72dfd419446422f88af0cb0e98f9c`. 주소는 file offset. 상수는 `.rodata`에서 직접 읽었다.

### 2.1 블록 위치와 입력

`5fb8ec` C:800–858, asm `0x511aa4`–`0x511ac9`, `0x514c74`–`0x514e33`. M = rbp, W = rbx, N = `[rsp+0x130]`, I = N+0x18, r13 = work 칸(`double*`, `5eda00`의 두 번째 인자와 같음).

| 입력 | 의미(출처) |
|---|---|
| `I+0x28` | 노드 상태. 2이면 블록 실행 |
| `I+0x98` | 노드 저장 basis(int, 열 n + 행 m). 노드 LP 상태 2 뒤 `5d4427` C:294–318이 할당하고 `113d92`로 채운다(C, [M2-03c-2](mip_retry_basis.md)). 열 j의 −1·−2만 쓴다 |
| `I+0x80`·`I+0x88` | 노드 lb·ub(비스케일, 열 n)([노드 구조 표](mip_unbounded_entry.md)) |
| `(I+8)+0x28` | 노드 LP 환산비용(열 우선, [M2-06f-2](mip_node_life.md)) |
| `M+0x650` | 변수 타입 바이트 |
| `(M+8)+0xe8`의 `+0xc` | 열 수 n |
| 표 B | `5e2919(M) == 0`이면 `M+0x3258`, 아니면 `W+0x3ff8` |

### 2.2 표 B 갱신 규칙(asm)

```text
0x511aa4: 5eda00(M, r13) != 1 이면 반환(블록 없음)
0x511abe: I+0x28 != 2 이면 건너뜀;  0x514c74: I+0x98 == 0 이면 건너뜀
0x514c9e: 표 B == 0 이면 건너뜀
for j in 0..n-1:                                        # 0x514d26–0x514d5d
  vt[j] == 'C' 이면 다음
  ub[j] > lb[j] 아니면 다음                              # comisd, jbe: 같거나 NaN이면 다음
  b = I+0x98[j]
  b == -1: cnt_up[j] < 5 이면 6edfcf( 1.0, maxsd(rc[j], 0.0), B, j)    # 0x514de3, ra 0x514de8
  b == -2: cnt_down[j] < 5 이면 6edfcf(-1.0, maxsd(-rc[j], 0.0), B, j) # 0x514e2a, ra 0x514e2f; -rc는 부호 비트 xor
r13 != 0 이면 *r13 = (double)(int)n · 5.0 + *r13         # 0x514d8a–0x514da9 (n ≤ 0이면 0·5.0)
```

상수: `0x2a6c558` = 1.0, `0x2a6c488` = −1.0, `0x2a6c508` = 5.0, `0x2a6c460` = 부호 비트 마스크. `maxsd x, 0`은 x > 0이면 x, 아니면(−0·NaN 포함) +0. `6edfcf`의 식은 06e §2.2(`max(Δ,1e-10)/(|f|+0.001)`, cnt 0이면 max, 이후 더함). 따라서 표 B 항목 하나는 "그 열이 노드 LP 해에서 비기저로 bound에 있을 때 bound를 떠나는 방향의 단위 환산비용"을 방향마다 최대 5번까지 모은 값이다. 디컴파일 C는 −2 분기의 Δ 인자를 빠뜨렸다(asm이 근거).

판별되지 않는 절(사전 선언): `maxsd(·, 0)`를 빼도 `6edfcf`의 1e-10 하한이 같은 결과를 만든다(음수·0 Δ 모두 1e-10). 이 절은 실행으로 판별할 수 없다.

### 2.3 표 C와 표 읽는 쪽(정적)

- 만들기·해제: `5daa82` `0x4fc983`(항상 새 표, 06e §2.1), 해제 `5e1674`. 병렬 복사·병합 `5bf638`·`5c37fd`·`5c3438`(범위 밖).
- 쓰는 곳(06e 캡처의 `upd` 사건에서 표 C 호출자는 이 둘뿐):
  - `6755af`(probing, `GURO_PAR_ROOTPROBE`): 열마다 `6eed2e`로 신뢰성 부족을 확인한 뒤 두 방향을 probing하고 `6edfcf(∓1, Δ, C, j)`. Δ = 그 방향 probing의 bound 변경 수(`8950df` 차이, int) 또는 실패(infeasible)면 2e9(`0x41ddcd6500000000`)(C:430–440, 1665–1676, 1940–1943, 2012–2020).
  - `67eb3e`: 같은 열에 `6edfcf(1.0, 0, C, j)`·`6edfcf(-1.0, 0, C, j)`(C:299–300). 결과는 cnt만 1씩 늘리는 효과(Δ 하한 1e-10).
- 읽는 곳: `6eed2e(W, N, T, j)`(신뢰성: `cnt_down` 또는 `cnt_up` < `T+0x60` η이면 1, 루트·SB 캐시 예외)와 `6ef12f(x, W, T, T2, j, &dn, &up)`(이득 추정: 방향별 `sum/cnt`(T2가 있으면 두 표 합산) 또는 SB 캐시, 1e-6 하한, `avg·frac`). C에서 표 C를 넘김을 확인한 곳: `6eed2e`는 `6755af`(C:261·296·392 등)·`6fdec9`(C:265), `6ef12f`는 x = 0.5로 `627f3e`(C:346–352)·`62a05d`(C:1381)·`62f909`(C:553, `local_168` = 표 C). 표 B는 `62f909`(C:114·167)·`62a05d`(C:1142·1294)가 표 A와 함께 읽는다(T2 후보). 나머지 호출자(`646052`·`62ec1d`·`67e4da`·`63056b`·`637ccf`)가 어느 표를 넘기는지는 실행 카운트로 본다.
- 실행 확인: 새 도구가 `6ef12f`·`6eed2e` 진입마다 (함수, 호출자, 반환 주소, T·T2가 어느 표인지)를 센다. 판정이 아니라 지도 확인이다.

## 3. 비교 계약

`tools/mip_pcost_bc_check.py`가 판정한다. 하나라도 실패하면 종료 코드 1이고 첫 차이(사례·사건 번호·j·기준값·실제값)를 출력한다. 부동소수는 u64 16진수 비트로 비교한다(±0 구분). 수치 오차는 허용하지 않는다.

캡처 도구 `tools/mip_pcost_bc.js` = 06e 도구 `tools/mip_pseudocost.js` + 아래 사건(06e 도구 파일은 고치지 않는다, 06e C1이 해시를 고정함).

- `bgate`(함수형 probe `0x511ab2`, `5eda00 == 1` 뒤 매번): 노드 id, nest, `I+0x28`, `I+0x98` null 여부, 그 M의 `0x3258` 표 번호, work 칸 값(r13, null이면 null).
- `bblk`(함수형 probe `0x514ca7`, 표 B가 있을 때): rdi 표 번호와 `M+0x3258` 표 번호, n, 열마다 `vt`·lb·ub·basis·rc. 같은 M의 앞 `bblk`과 다른 칸만 보내는 무손실 차분(첫 사건은 전체). 규칙으로 걸러서 줄이지 않는다.
- `bend`(함수형 probe `0x511ac9`, 직전 `bgate`가 있을 때 한 번): work 칸 값.
- 카운트 `rd`(사건 목록 밖): `6ef12f`(`0x5b7920`)·`6eed2e`(`0x5b77a0`) 진입마다 (함수, 호출자 함수, 반환 주소, T 표 slot, T2 표 slot).

| 검사 | 규칙 |
|---|---|
| B1 재현성 | 사례마다 원본 3회 gz 바이트가 같다. `ok`, `errors` 없음, `tool_sha256`이 현재 도구와 같다, 바이너리 SHA-256, 파라미터 `{Threads 1, Seed 0, LogToConsole 0, NodeLimit 2000}`. manifest SHA-256과 같다 |
| B2 비간섭 | 새 사건(`bgate`·`bblk`·`bend`)과 카운트 `rd`를 뺀 사건 열·카운트·출력 줄이 `bench/oracle/m2_06e`의 같은 사례 run 1과 같다 |
| B3 블록 판정 | `bgate`마다 상태 2·basis 있음·표 있음이면 바로 뒤에 `bblk`가 있고, 아니면 없다. `bblk`의 rdi 표 = 그 M의 `0x3258` 표. `bgate`·`bblk`·`bend` 순서가 맞다 |
| B4 갱신 | `bblk`마다 §2.2로 예측한 호출 열(j 순서, 방향, 반환 주소)이 그 `bblk`와 `bend` 사이의 `5fb8ec` 표 B `upd` 사건 열과 같다. 각 `upd`의 전 항목이 재생 상태와 같고 뒤 항목이 `6edfcf`(06e `upd_rule`) 결과와 비트까지 같다. 표 B `upd`가 창 밖에 없다 |
| B5 work | `bend` work = `bgate` work + `(double)n · 5.0`(블록을 돈 경우, r13 있음), 아니면 같다. 비트 비교 |
| B6 사슬 | 표 B마다 새 표(0)에서 모든 표 B `upd`를 재생한 상태가 해제 스냅숏(0이 아닌 항목 전체)과 같다. 해제되지 않은 표 B 0 |
| B7 분기 | 6사례 합계에서 −1 호출, −2 호출, 상한(cnt = 5) 건너뜀, cnt = 4에서 호출, `'C'` 건너뜀, lb = ub 건너뜀, basis ≥ 0 건너뜀, rc ≤ 0인 −1 호출(Δ = 0), rc ≥ 0인 −2 호출, 상태 ≠ 2 `bgate`, 호출 0인 `bblk`가 모두 1회 이상 |
| C1 표 C `67eb3e` | 반환 주소 `0x5634af`는 f = 1.0, `0x5634cb`는 f = −1.0, Δ = 0으로 `upd_rule` 결과와 비트까지 같다 |
| C2 표 C `6755af` | 갱신마다 Δ ∈ {0, 1, …, 10⁷} ∪ {2e9}와 f = ±1(증가한 방향) 중 결과 비트를 재현하는 값이 있다. cnt 0이고 max가 기존 sum을 유지한 경우는 "판별 불가"로 따로 센다 |
| R 지도 | (보고만) `rd` 카운트를 표 slot별로 집계해 §2.3 지도와 비교해 출력한다. 지도에 없는 (함수, 호출자, slot) 조합은 실패로 보지 않고 출력한다 |
| T 변조 | (`--self-test`) run 1 사본에 아래 T1–T12를 넣으면 각각 실패 |
| V 변이 | (`--self-test`) §2.2 규칙의 한 절을 바꾼 변이가 아래 분기 수 규칙대로 거부·생존한다 |

T: T1 표 B `upd` 뒤 비트 1 ulp, T2 표 B `upd` 하나 삭제, T3 호출된 열의 basis −1↔−2, T4 `bend` work 1 ulp, T5 호출이 있는 `bgate` 상태 2→1, T6 |rc| > 1e-10인 호출 열의 rc 부호, T7 표 B `upd` 하나를 창 밖(`bend` 뒤)으로 이동, T8 바이너리 SHA-256을 0으로, T9 `bblk` 사건 전부 삭제, T10 표 B `upd`·`bblk`·`bgate` 전부 삭제(목표 0회 입력 → B7 실패), T11 호출된 열의 ub를 lb로, T12 06e 사건 하나(`ins` 필드)를 바꿈(B2).

| 변이 | 바꾼 절 | 거부 조건(그 사례의 분기 수 > 0) |
|---|---|---|
| V1 | 상한 5 → 4 | cnt = 4에서 호출 |
| V2 | 상한 5 → 6 | 상한으로 건너뜀 |
| V3 | −1·−2 방향을 서로 바꿈 | 호출 |
| V4 | `'C'` 검사 없음 | 다른 조건을 통과한 `'C'` 열 |
| V5 | `ub > lb` → `ub ≥ lb` | 다른 조건을 통과한 lb = ub 열 |
| V6 | f = ±0.5 | 호출 |
| V7 | −2에서 Δ = max(rc, 0) | |rc| > 1e-10인 −2 호출 |
| V8 | `maxsd(·, 0)` 제거 | 판별 불가(§2.2, 항상 생존 기대) |
| V9 | work = 호출 수 · 5.0 | 호출 수 ≠ n인 블록(r13 있음) |
| V10 | 열 역순 | 호출이 2회 이상인 블록 |

- 시간·work·병렬: Threads=1, 종료는 NodeLimit 2000(06e와 같은 설정, B2 기준). Threads > 1 경로는 범위 밖.
- 원본 재현성: 같은 설정 3회 독립 실행의 gz 바이트 비교(B1).

## 4. 사례와 원본 자료

모두 실제 MIPLIB 입력이다(`../re/bench/data/miplib/<사례>.mps.gz`). M2-06e와 같은 6사례·설정이라 B2 기준이 있다. 06e 캡처에서 6사례 모두 표 B 갱신(`0x514de8`·`0x514e2f`)과 표 C 갱신(`6755af`)이 있었고, `67eb3e`는 tr12-30·fhnw-binpack4-4·neos-860300에 있었다.

| 사례 | 노리는 분기(06e 캡처 기준) |
|---|---|
| markshare_4_0 | 표 B 소수(268), 작은 n |
| pk1 | 표 B 1,101, sub-MIP(nest 2) |
| neos5 | 표 B 822 |
| tr12-30 | 표 B 3,721, 큰 n(1,028), `67eb3e` |
| fhnw-binpack4-4 | 표 B 7,645(−2 다수), `6755af` 다른 두 지점, `67eb3e` |
| neos-860300 | 표 B 5,209, 큰 n(1,466), `6755af` 세 지점 |

- 캡처 도구: `tools/mip_pcost_bc.js`. 기준 자료: `bench/oracle/m2_06e2/`(manifest·`<사례>_<회>.json.gz`).

## 5. 재실행 명령

```sh
tools/hrun.sh -- 'tools/mip_pcost_bc_runs.sh bench/oracle/m2_06e2'   # 6사례 × 3회, Gurobi 한 프로세스씩
python3 tools/mip_pcost_bc_check.py --write-manifest                # 처음 한 번
python3 tools/mip_pcost_bc_check.py                                 # B1–B7, C1–C2, R
python3 tools/mip_pcost_bc_check.py --self-test                     # + T, V
```

회귀: Rust·Python 패키지를 바꾸지 않으므로 cargo·pytest는 해당 없음. 06e 검사기(`python3 tools/mip_pseudocost_check.py`)는 자료·도구를 바꾸지 않으므로 그대로 통과해야 한다.
