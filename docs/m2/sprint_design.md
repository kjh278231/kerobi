# M2 스프린트 설계 보완

이 문서는 [1주 작업 목록](../14_sprint_plan.md)의 조사·구현 경계를 정의한다. 설계 제안과 원본에서 확인한 동작을 구분한다. `06`·`07` 문서의 구조체 예시는 목표 설계이며 현재 구현 상태로 읽지 않는다.

착수와 완료 판정은 [동작 동등성 검증 기준](../15_sprint_verification.md)을 따른다. 이 문서의 비교 경계를 작업별 [검증 계약](../templates/sprint_acceptance.md)의 필드·사례·명령으로 구체화한다.

## 1. 현재 실행 경로와 상태 소유권

현재 `bnb::solve_original`은 presolve와 복원 경로를 선택하고, `solve_started`는 루트 결과를 받아 노드를 푼다. `Node`는 모델 복사본과 bound를 들고 자식 LP를 다시 푼다. 원본의 worker·plunge·cut pool 전체가 구현된 상태는 아니다.

| 데이터 | 현재 소유 위치 | 다음 설계의 제약 |
|---|---|---|
| 원래 모델 | `solve_original` 입력 | incumbent 최종 검증의 좌표와 목적 기준 |
| 축약 모델·열 매핑·레코드 | presolve 상태, `bnb.rs` 복원 함수 | 열 번호 공간을 섞지 않고 레코드를 역순 소비 |
| 루트 domain·후보 해 | `root.rs`의 `RootProgress` | 루트 LP 상태와 MIP 진행 상태를 각각 보존 |
| 탐색 경계·incumbent·한도 | `termination::State`, `bnb.rs` | 목적 sense 정규화와 해 없음 표현 일관성 |
| 노드 LP 상태 | LP 반환값 | MIP 종료 상태로 변환하기 전 증명·재처리 조건 확인 |
| 마감 시각 | 최초 시작 시각과 `deadline` | fallback·재풀이에서 TimeLimit을 새로 시작하지 않음 |

새 모듈 경계는 원본 상태가 필요한 시점에 확정한다. 성능 개선을 이유로 노드·basis·worker 전체를 한 번에 재작성하지 않는다. M2-10b가 저장·복구 계약과 작은 이행 단위를 만든다.

## 2. M2-03 자식 LP 무계

확인된 근거는 `600d25`의 case 5와 `5c239f`의 상태 전달이다. case 5는 직접 노드 상태 11로 가는 경로와 `UnbdRay`를 검사한 뒤 상태 11 또는 3으로 가는 경로가 있다. 현재 Rust는 자식 LP의 Numeric·Unbounded를 Numeric 종료로 처리한다. 이 상태를 원본과 일치한다고 판정하지 않는다.

| 하위 작업 | 입력 | 설계 산출물 | 넘겨줄 정보 |
|---|---|---|---|
| 03a | 해당 디컴파일·필요 어셈블리 | 직접 진입 조건의 필드표와 제어 흐름. [03a 조사 완료](mip_unbounded_entry.md) | 선형 입력은 상태 3으로 보류, 직접 상태 11은 추가 제약 문맥 |
| 03b | 03a의 모델 범위 | 방향·정수·bound·행 검사와 상태 3 이후 호출표 | 필요한 ray·해·basis 데이터와 허용오차 |
| 03c | 조건을 밟는 모델과 훅 | LP 상태→노드 상태→MIP 상태 추적 | 재현 모델·파라미터·기준 출력 |
| 03d | 검증 가능한 조건 하나 | Rust 변경과 해당 오라클 대조 | 지원 범위와 미지원 시 현재 처리 |

03a 조사에서 순수 선형 입력은 `600d25`의 ray 경로에 들어가지 않고, 루트 캐시가 2이면 호출자가 LP 상태 5를 12로 재분류함을 확인했다. M2-03b는 추가 제약 문맥의 ray 검사를 맡고, 새 M2-03b-1은 선형 경로의 재분류와 보류 후 재처리 경계를 맡는다. 합성 원본 호출 13개×3회는 함수 구간 확인이며 실제 자식 노드의 증거가 아니다.

M2-03b-1 조사는 [재분류·대체 분기·재등록 경계](mip_unbounded_reclassification.md)로 완료했다. 상태 3은 `60145b`에서 분기 자격을 가지며 `627f3e`의 대체 분기로 간다. 연속 변수만 남은 경우 새 자식 상태 10이 생길 수 있다. 부모 상태 3 자체를 큐에 다시 넣는 구현으로 바꿀 수 없다. 원본 합성 setter·재등록 게이트·분기 자격 총 156회만 실행 확인했다. M2-03c-1은 이 선형 경로의 호출자·자식 상태를 캡처한다.

M2-03c-2 오라클은 [재풀이 basis](mip_retry_basis.md)로 완료했다. 재풀이 `cda5b`는 노드 `I+0x98/0xa0`(압축 `I+0xb0`를 `69d7ea`가 푼 basis)를 첫 LP와 똑같이 받는다. method는 `param_3[3]==0`이다. Rust 재풀이는 실패한 LP의 basis가 아니라 노드 저장 basis에서 시작해야 한다. 재풀이 뒤 상태 2이면 `5d4427`로 노드 basis를 갱신한다. Rust 비교 경계는 M2-03d-1, 구현은 M2-03d-2에서 다룬다.

M2-03d-1 조사는 [Rust 재풀이 비교 경계](mip_retry_rust_boundary.md)로 완료했다. 원본 두 사례의 LP(nidda 464행, gmu 53×110)는 Rust가 모델 파일과 자연 B&B로 만들 수 없다. 03d-2는 원본 LP 결과를 주입한 재풀이 제어 재생(L1)으로 비교한다. 범위는 basis가 있는 노드에서 첫 LP·재풀이에 노드 basis를 넘기고 재풀이 method 규칙(`param_3[3]==0`)과 주입 LP 6 처리를 하는 데까지다. basis 상속(`5ff358`→`69e299`)·LP 2 뒤 저장·모든 자식 warm start는 §1의 M2-10b 범위이고 L1 기준 자료로 판별할 수 없다. primal warm start와 LP cutoff 상태는 `crates/lp`(M1) 선행이다. 선행이 없는 동안 실제 경로는 `bnb.rs:176`의 Numeric 종료를 유지하고 dual·cold 재풀이로 대신하지 않는다. 진행 순서는 사용자가 03d-2 우선으로 승인했다.

M2-03d-2는 [재풀이 판단 제어](mip_retry_control.md)로 완료했다. `crates/mip/src/retry.rs`의 `process_node_lp`가 LP를 클로저로 받아 판단만 한다. B&B에는 아직 연결하지 않았다. nidda L1 비교를 통과했고, 실제 경로 연결과 LP 포함 동등성은 M2-03d-4다. 순서는 M2-10b, M1 요청, M2-03d-3 다음이다.

M2-03d-3은 [노드 LP 오라클](mip_retry_node_lp.md)로 완료했다. 두 원본 사례 모두 일반 B&B 노드가 아니다. nidda는 재시작 뒤 RINS가 정수를 모두 고정해 푼 연속부 LP이고, gmu는 sub-MIP 루트 LP다. 노드 LP는 모델 파일 행을 그대로 쓰지 않는다('>' 행 부호 반전, 일부 행 배수 조정). 그래서 Rust LP 재생 입력은 캡처 파일(`*.node_lp.json`)이다. M2-03d-4의 `bnb.rs` 연결 검증에는 일반 B&B 노드의 자연 재풀이 사례가 추가로 필요하다.

M2-03d-5는 [일반 B&B 노드 자연 재풀이 스캔](mip_retry_bnb_scan.md)으로 완료했다. `5ce67b` 직접 호출자와 `5bbf7f` 깊이로 문맥을 나눴다. 228회에서 재시작 없는 본 탐색 노드 재풀이는 0건, 재시작 뒤 본 탐색 노드 1건(nidda seed 1 노드 16948)이다. 이 노드도 재시작·cut 때문에 Rust가 자연 도달할 수 없으므로 M2-03d-4는 LP 재생(L2)과 원본 `5fb8ec` 경로 관측까지가 검증 범위다. 노드 LP 캡처 M2-03d-6을 [완료](mip_retry_bnb_node_lp.md)했다. L2 재생 입력은 API LP에서 `simplex_blanked_rows`를 비운 LP이고 기대 상태는 2다.

M2-03d-7·03d-8은 노드 LP 빈 행이 DynamicRows 다이브 행 비활성임을 확인하고 선택 규칙을 원본 캡처로 재구성했다. M2-03d-9는 [선택 블록을 Rust로 이식](mip_dive_rows_rust.md)했다(`dive_rows::select`, L1 저장 기준 재생 통과). M2-03d-10은 [비활성 목록 유지와 D 교체](mip_dive_list_rust.md)를 옮겼다(`dive_rows::RowList`, L1 통과). 관문(C:1581–1610·C:526)의 모든 평가 입력과 결과는 M2-03d-11 [관문 오라클](mip_dive_gate.md)이 캡처했고 Python 규칙이 정확히 재현한다. M2-03d-12가 관문을 [Rust로 이식](mip_dive_gate_rust.md)했다(`dive_rows::Gate`, L1 통과). 세 부분 모두 `bnb.rs`에는 아직 연결하지 않았다. `10f448`은 D 열 순서를 제자리에서 누적해 바꾸므로 M2-03d-4는 노드 LP 배열을 이어 써야 한다. 그 분할이 두 포인터 교환(안정 분할 아님)임은 M2-03d-13 [분할 순서 오라클](mip_dive_split.md)이 재생성 4,306회로 확인했다. M2-03d-14가 Rust `swap_in`을 그 재생성 4,306회로 [재생 대조](mip_dive_split_rust.md)해 L1로 통과했다(안정 분할 변이 거부).

03c는 루트가 무계였다는 로그만으로 통과하지 않는다. 실제 자식 노드임을 훅의 호출 문맥으로 확인한다. 재현하지 못하면 시도한 조건과 미확인 분기를 기록하고 구현은 설계 대기로 둔다. 03d가 상태 3의 재처리를 요구하는 경우 그 기능을 별도 작업으로 분리한다.

## 3. M2-04 중단 계약

중단 지점은 원본이 확인한 연산 경계로 정한다. 조사표에는 마감 확인 위치, 그 시점의 모델·레코드·작업 큐 유효성, 반환 상태와 호출자의 후속 행동을 적는다. 부분 presolve 결과를 완성된 축약 모델처럼 소비하거나, 아직 처리하지 않은 노드를 소진된 것으로 판정해서는 안 된다.

검증 입력은 만료하지 않는 제한, 진입 전 만료, 패스 중 만료를 구분한다. 내부 상태 검증은 결정적 검사 지점을 사용하고 벽시각 검사는 실제 제한 실행으로 별도 기록한다. 확인 간격이나 시간 초과 허용 폭은 원본 근거·측정 없이 새 수치로 고정하지 않는다.

## 4. M2-05 복원 계약

`restore_candidate`의 입력은 축약해와 그 해를 만든 presolve 상태다. 출력 후보는 원래 변수 공간에서 bound·정수성·행·목적을 검증한다. 다른 실행에서 만든 열 매핑을 재사용하지 않는다. type 11처럼 원시해 복원에서 아무 동작이 없는 레코드도 다른 복원 정보까지 지원했다고 판정하지 않는다.

05c는 레코드 한 종류의 생성 지점, 저장 필드, 역순 의존과 경계 사례를 기록한다. 05d는 같은 종류의 원본 합성 출력과 실제 해 하나를 비교한다. 실제 해를 얻지 못한 경우 합성 분기 검사까지만 완료 범위에 적는다. 기존 fallback 사유가 사라지는지는 경로 계측으로 확인한다.

## 5. M2-06 탐색·분기 설계

노드 선택과 분기 평가를 분리한다. 선택 작업의 입력은 동일한 후보 노드 집합과 RNG 상태다. 출력은 선택 노드, 남은 목록 순서와 RNG 상태다. 단순히 최적 목적이 같다는 검사로 선택 규칙을 검증하지 않는다.

pseudocost 작업은 방향별 표와 갱신 사건을 입력으로 받는다. strong branching은 임시 bound·LP basis 변경 후 부모 상태를 복구해야 한다. reliability 작업은 그 평가 결과를 소비한다. 세 기능의 초기화·수명·갱신 순서는 06e~06g의 원본 조사에서 확정한다. 12개 노드 선택 규칙은 한 구현 작업에 묶지 않고 규칙별 후속 번호를 만든다.

M2-06a가 노드 용기의 순서 규칙과 [추적 형식](mip_node_select_spec.md)을 원본 추적 재생으로 확인했다. M2-06b가 전역 힙을 [Rust로 이식](mip_node_heap_rust.md)했다(`node_heap::NodeHeap`, L1 통과, `bnb.rs` 미연결). M2-06b-2가 [키 식](mip_node_key.md)을 `child_key`·`deep_key`로 옮겼다(입력은 부모 LP 분수 수, 루트 분수 수 `M+0xa4`, 목적 간격 `M+0x40`). M2-06e가 pseudocost 표 A의 [초기화·노드 갱신·감쇠·대칭 전파](mip_pseudocost.md)를 원본 캡처로 확정했고, M2-06f가 그것을 [`pseudocost::Pseudocost`로 이식](mip_pseudocost_rust.md)했다(L1 통과, `bnb.rs` 미연결). M2-06f-2가 연결 전 입력을 [조사](mip_node_life.md)했다. 조상 I 수명은 `5f9d4e` 해제 연쇄(형제가 모두 단계 5를 벗어나면 부모 I 해제)가 정하고, 감쇠 벡터는 현재 노드 LP의 환산비용(`12ef7f`)·cutoff 출력·`95da98` 출력이다. 연결에는 노드 수명 모형(06f-3), LP 환산비용·cutoff 상태(M1 경계), `95da98`(06f-4)과 노드 처리 순서(06c·06d)가 필요하다.

## 6. M2-07 cut 설계

설계 순서는 실행 범위 확인, 공통 수명 설계, pool과 LP 연결, 생성기별 조사·구현이다. presolve의 clique·mod-k 구현이 있다는 사실만으로 런타임 cut 생성기가 구현됐다고 간주하지 않는다.

공통 설계표는 다음 내용을 포함한다.

| 경계 | 확정할 내용 | 독립 검증 |
|---|---|---|
| separator→buffer | 열 좌표·sense·rhs·kind·rank, bound 변경과 해 후보 | 생성 직후 원본 계수·순서 |
| buffer→pool | 정규화·해시·중복·강화 순서 | 같은 입력의 채택·거부 사유 |
| pool→LP | 점수·직교성·밀도 제한, 행 번호 | 같은 후보의 선택 순서 |
| LP→pool | slack·basis·행 삭제와 역매핑 | 설치·삭제 뒤 원래 제약과 해 검사 |
| 재풀이→다음 pass | 경계·진전·work·종료 규칙 | pass별 LP 결과·종류별 cut 수 |

07f~07l에서 생성기별 구현 작업을 추가할 때는 한 변환 또는 생성 단계로 나눈다. 예를 들어 Gomory는 tableau 추출, 후보 순서, 정수화, bound 역대입, rank·수치 거부를 독립 비교할 수 있어야 한다. MIR은 행 집계와 VUB 대입을 공통 상태로 명시한 뒤 생성기를 연결한다. 실제 함수 경계와 양이 확인되기 전에는 이 단계 전체를 1주 구현으로 추정하지 않는다.

유효성은 작은 정수점 전수 검사와 원본 계수 비교를 함께 사용한다. 유효한 cut이더라도 선택 순서가 다르면 패리티 불일치다. 기본 separator 범위는 `07` §5의 본문 규칙과 실제 호출 근거로 확정한다. 기존 표의 단계 표기 충돌은 07a에서 항목별로 정정한다.

## 7. M2-08·09 휴리스틱과 API

전파는 원래 모델·현재 domain·cutoff 중 무엇을 읽는지와 bound 변경 순서를 명시한다. 휴리스틱은 호출 조건, RNG 소비, 고정 변수, sub-MIP 파라미터와 후보 해 검증을 각각 기록한다. sub-MIP 설계는 깊이·중단·해 복원 계약을 먼저 정하고, RINS·pump·diving은 이를 소비한다.

콜백은 공개 API에서 보이는 where·상태·해·목적을 검증한다. 제출 후보가 축약 공간인지 원래 공간인지, 언제 검증·설치되는지를 09a~09d에 적는다. cbCut·cbLazy는 cut pool 수명·좌표 설계 이후 구현 번호를 만든다. MIP start는 완전한 해 한 개와 부분·복수 해 처리를 나눈다.

## 8. 스프린트 기록 형식

기존 영역 기록에 하위 작업 번호를 제목으로 붙이고 다음을 남긴다.

1. 범위와 제외한 분기, 원본 함수와 어셈블리 확인 위치.
2. 입력·상태 소유권·출력·실패·중단 규칙.
3. 비교 모델·파라미터·원본 기준과 재실행 명령.
4. 결과·미확인 항목·후속 작업 번호·커밋 상태.

이 문서의 계획은 원본 해독 완료나 새로운 구현의 검증 결과가 아니다.
