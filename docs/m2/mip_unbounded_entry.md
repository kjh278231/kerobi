# M2-03a 직접 무계 확정 진입 조사

## 1. 범위와 주장

- 종류: 조사. `600d25`의 LP 상태 5 진입 조건, 직접 노드 상태 11을 쓰는 조건, 읽는 필드와 호출 경계를 확정한다.
- 포함: switch 실제 점프 대상, 문맥 상태 분기, 추가 제약 수 게이트, 재풀이 결과 분기, 정수 domain과 추가 제약의 직접 확정 게이트.
- 제외: 무계 방향 검사 전체는 M2-03b, 정상 실행의 실제 자식 노드 훅은 M2-03c, Rust 변경은 M2-03d다.
- 선행: main `f86edd8`와 기존 미커밋 변경을 보존한 스냅숏 `7ea2301`. 작업 branch는 `sprint/m2-03a`다.
- 검증 기준: [스프린트 검증 기준](../15_sprint_verification.md). 이번 조사 결과로 Rust 구현 동등성이나 전체 M2 관문 통과를 주장하지 않는다.

## 2. 원본과 상태 경계

- 바이너리: Gurobi 13.0.3, `../.venv/lib/python3.13/site-packages/gurobipy/.libs/libgurobi130.so`.
- 실제 SHA-256은 `8e87fca221fdffc922331c8619426031b3e72dfd419446422f88af0cb0e98f9c`로 기존 지도와 일치한다.
- C: `../re/decomp/c/00518170_PRIVATE0000000000600d25.c`. Ghidra 주소는 ELF 주소에 `0x100000`을 더한 값이다.
- 어셈블리: ELF `0x518170` 진입, 점프 테이블 `0x2a6c440`, 상태 5 분기 `0x5181e9`, 직접 확정 `0x518664`, 추가 제약 게이트 `0x519a50`.
- ABI: Linux x86-64 SysV. 인자 `rdi=node`, `rsi=LP 정보`, `rdx=LP 문맥`, `rcx=work 포인터`. 반환은 `eax` 오류 코드다. 호출 인자와 구조 필드는 어셈블리로 대조한다.
- 시작은 `600d25` 진입 직전, 종료는 반환 직후다. 합성 직접 호출은 호출 없는 분기만 사용한다. 내부 allocator·solver가 필요한 경로는 직접 합성하지 않는다.
- 문맥·추가 제약·domain 조건은 정적 분석으로 확인한다. 실제 자식 노드에서의 도달 여부는 이번 작업에서 검증하지 않는다.

## 5. 재실행 명령

작업 worktree의 저장소 루트에서 실행했다. `.venv`와 `re`는 저장소와 같은 부모 디렉터리에 있다.

```bash
../.venv/bin/python tools/mip_unbounded_entry_oracle.py --output bench/oracle/mip_unbounded_entry.json
../.venv/bin/python tools/mip_unbounded_entry_oracle.py --check bench/oracle/mip_unbounded_entry.json
git diff --check
```

첫 명령은 Gurobi를 차례로 3개 독립 프로세스에서 호출한다. 각 프로세스는 버전·바이너리 해시·함수 진입 바이트·점프 테이블을 확인한 뒤 13개 합성 상태를 실행한다. 두 번째 명령은 Gurobi를 불러오지 않고 저장 결과를 검사한다. 실제 모델의 최적화는 수행하지 않는다.

오류 검출 재현은 다음과 같다. 세 필드 모두 검사기가 실패해야 한다.

```bash
python3 - <<'PY'
import copy, json, subprocess, sys, tempfile
from pathlib import Path
doc = json.loads(Path('bench/oracle/mip_unbounded_entry.json').read_text())
with tempfile.TemporaryDirectory() as tmp:
    for field, value in [('node_status', 11), ('counter', 17), ('preserved', False)]:
        bad = copy.deepcopy(doc)
        bad['runs'][0]['cases'][0][field] = value
        path = Path(tmp) / (field + '.json')
        path.write_text(json.dumps(bad))
        result = subprocess.run([sys.executable, 'tools/mip_unbounded_entry_oracle.py',
                                 '--check', str(path)], capture_output=True, text=True)
        assert result.returncode != 0 and 'AssertionError' in result.stderr
        print('REJECT:', field)
PY
```

어셈블리의 재생 경계는 [원본 자료 manifest](../../bench/oracle/mip_unbounded_entry_sources.json)의 `ranges`에 있다. 각 쌍을 `objdump -d -M intel --start-address=<시작> --stop-address=<끝> <바이너리>`로 출력한다. 저장 시 바이너리 경로를 `libgurobi130.so`로 바꾸고 행 끝 공백과 마지막 빈 행을 제거했다. 명령어와 바이트는 바꾸지 않았다. 원본 C·파라미터 표의 SHA-256도 manifest에 있다.

## 7. 필드와 제어 흐름

### 필드 소유권

`N=param_1`, `I=*(N+0x18)`, `M=*(I+0)`, `model=*(M+8)`, `D=*(model+0xe8)`다. `L=param_2`는 노드 LP 결과 정보, `W=param_3`는 LP 실행 문맥이다.

| 필드 | 의미와 자료형 | 근거 |
|---|---|---|
| `L+0x38` | `int` LP 상태 | `600d25` 진입 `0x518184`, `5ce67b`의 `GRBgetintattr("Status")` |
| `M+0xa8` | `int` 루트 relaxation 상태 캐시 | `5daa82`:175에서 -1, `5ce67b`:740–761에서 루트 노드일 때 상태 2·5 저장 |
| `M+0x790` | 루트 노드 포인터 | `5ce67b`의 현재 노드 동일성 비교 |
| `M+0x620` | 최상위 MIP 문맥 포인터 | `600d25`의 보류 계열 카운터 및 루트 완료 처리 |
| `D+0x18` | `int` SOS 수 | `a7e4de`의 SOS1·SOS2 타입/멤버 검사 |
| `D+0x1c` | `int` 2차 제약 수 | 드라이버 모델 통계·기존 필드 지도, `600d25` 게이트 |
| `D+0x258` | `int` 이중선형 제약 수 | `78dd89`·`78d933`의 변수 쌍과 식, 드라이버 통계 |
| `D+0x1a8` / `D+0x1b0` | `int` 비선형 제약 수 / 제약 포인터 배열 | `b3fb65`와 `600d25`의 항목 순회 |
| `D+0xc` / `D+0x410` | `int` 열 수 / `char[]` 변수 타입 | `0x518446`, `0x51846b`에서 읽고 `'C'`와 비교 |
| `I+0x80` / `I+0x88` | 현재 노드의 `double[]` lb / ub | `0x518431`–`0x518438`, domain 차이 연산 |
| `M+0x34cc` | `int` 유효 MIQCPMethod | `5daa82`:769–775에서 env+0x26cc 복사, 이후 자동값 확정 가능 |
| `W+8` | 실제 relaxation 모델 포인터 | `0x5182ea`에서 복사 함수의 인자로 전달 |
| `I+0x28` | `int` 출력 노드 상태 | 상태 11 쓰기 `0x518668`, 보류 쓰기 `0x51825e` |

`M+0xa8`는 현재 자식 LP 상태나 공개 Model.Status 저장소와 다른 필드다. 위 `M`은 `presolved_model+0x2b8`의 B&B 객체이며 `model+0x1b8`의 공개 MIP 결과 객체와도 구분한다.

### LP 상태 5의 진입과 재풀이

점프 테이블은 `LP 상태 - 2`를 인덱스로 쓰지만, 실제 상태 5는 `0x5181e9`로 간다. 테이블의 4번째 바이트 `0x27`에 기준 주소 `0x5181c2`를 더한 값이다. 따라서 C의 `case 5`를 실제 상태 7로 해석하면 안 된다.

1. `M+0xa8 != 5`이면 보류한다. 값이 2면 노드 상태 3만 쓰고, 그 밖에는 최상위 `+0xd4`도 1 증가한다.
2. 루트 캐시가 5면 추가 제약 수 네 개 중 양수가 있는지 확인한다. 네 값이 모두 0인 정상 선형 모델은 `0x519a50`에서 `0x518257`로 가므로 노드 상태 3, 카운터 +1이다. 이 경로에서 `UnbdRay`를 읽지 않는다.
3. 추가 제약이 있으면 `99b471(W+8, &copy)`로 재풀이용 모델을 만든다. copy env의 Presolve를 0, Cutoff를 1e100으로 설정하고 원 relaxation의 `+0x50` 포인터를 복사한다. `+0x50`의 전체 수명 계약은 이번 조사 범위 밖이다.
4. `a7f923(copy)`가 0이면 Threads=1, Method>1일 때 Method=0으로 바꾸고 LP 드라이버 `0c3d0d(copy, work)`를 호출한다. 0이 아니면 `2bb770(copy, work)`를 호출한다. `a7f923`의 모델 구조 판정은 C와 어셈블리의 인자 전달을 대조했으며, 여기에 없는 모델 유형을 추정해 추가하지 않는다.
5. copy의 상태 2는 지역 상태 5로, 상태 4는 지역 상태 3으로 바꾼 뒤 copy를 해제한다. 지역 상태 3이면 노드 4, 상태 6이면 노드 5다. 상태 5에서만 아래 직접 확정 검사를 진행한다. 그 밖은 노드 3과 카운터 +1이다. 생성·풀이 오류는 해제 후 오류 코드를 반환한다.

노드 4·5 경로는 최상위 루트인 경우 상위 MIP 상태와 트리 bound 갱신도 실행한다. 이번 합성 호출은 그 조건을 거짓으로 고정했다. 이 부수효과의 실행 동등성은 주장하지 않는다.

### 방향을 읽기 전 직접 상태 11을 쓰는 조건

아래 조건을 모두 만족해야 `0x518664`에서 노드 상태 11을 쓴다. 앞 절의 루트 캐시 5·추가 제약 존재·재풀이 후 지역 상태 5도 전제다.

| 순서 | 필요한 조건 | 거짓이면 |
|---|---|---|
| 1 | 모든 열에서 타입이 `'C'`이거나 `ub[j]-lb[j] <= 1e-10` | ray 경로 `0x51871e` |
| 2 | 모든 SOS에 대해 `a7e4de(model, i, lb, ub) != 0` | ray 경로 |
| 3 | 모든 이중선형 제약에 대해 `78dd89(...) != 0` 또는 `78d933(..., work) != 0` | ray 경로 |
| 4 | 모든 비선형 제약에 대해 `b3fb65(env, constraint[i], lb, ub, work) != 0` | ray 경로 |
| 5 | `SOS 수 <= 0` 또는 `2차 제약 수 <= 0` 또는 `MIQCPMethod != 1` | ray 경로 |

순회는 각각 인덱스 오름차순이며 최초 거짓에서 ray 경로로 간다. 조건 1은 domain 폭 검사다. 고정값 자체를 반올림하거나 정수성과 비교하는 조건으로 바꿀 수 없다. 조건 5의 직접 확정 배제는 SOS·2차 제약·MIQCPMethod=1이 **동시에** 성립할 때다.

`a7e4de`는 env IntFeasTol을 읽는 SOS domain 검사다. `78dd89`는 곱의 두 변수 중 하나의 domain 폭이 1e-10 이하인지 확인한다. `78d933`은 FeasibilityTol과 bound 기반 식 검사를 사용한다. `b3fb65`도 FeasibilityTol을 읽고 제약 타입별 검사를 한다. 각 함수의 전체 수치 연산과 ray 경로의 수치 허용오차는 M2-03b에 남긴다. 특히 C의 `b3fb65` 호출에는 work 인자가 빠져 있지만 어셈블리 `0x518606`이 `r8=work` 전달을 확인해 준다.

### 선형 모델의 호출자 처리

`5ce67b`:740–761은 루트 노드에서 relaxation 상태를 `M+0xa8`에 저장한다. 상태가 5이고 추가 제약 수 네 값이 모두 0이면 `M+0=5`를 직접 설정한다. 따라서 선형 루트의 MIP 무계 확정은 `600d25`가 노드 상태 11을 쓰는 경로와 다르다.

루트 캐시가 2인 문맥에서는 현재 LP 상태 5를 상태 12로 바꾼 뒤 `600d25`에 전달한다(`5ce67b`:718–723·750–752). 이번 합성 `LP=5, root=2` 사례는 변환 함수 자체의 분기 확인이며 정상 호출자의 전체 실행 재현이 아니다. 상태 12·13의 보류 카운터 증가도 합성 원본 호출로 별도 확인했다.

정확한 선형 LP에서 부모의 유계 relaxation에 bound를 추가한 자식이 새로 무계가 될 수 없다는 점은 수학적 해석이다. 실제 수치 상태·재분류·보류 후 재처리 동작은 그 해석만으로 대체하지 않는다.

## 8. 미확인 목록과 후속 분할

- M2-03b는 추가 제약 문맥에서 ray 검사의 수치·정수·bound·행 조건을 조사한다. 순수 선형 모델이 같은 ray 경로에 들어간다는 기존 전제는 이번 정적 분석과 호출 실험으로 제외했다.
- M2-03b-1을 추가한다. `5ce67b`의 상태 5→12 재분류와 상태 3의 후속 소비·재처리 경계를 조사한다. 같은 선형 상태의 실제 호출자 입력과 재처리 조건이 산출물이다.
- M2-03c는 실제 자식 노드의 호출 전후를 훅으로 확인해야 한다. 이번 합성 포인터 구조에는 부모·깊이·basis가 없으므로 그 증거가 될 수 없다.
- 재풀이·직접 상태 11·ray 분기는 실행 검증이 없고, copy의 전체 숨은 상태·일반 제약 predicate의 전체 수치 경계도 미확인이다. 구현은 M2-03d까지 보류한다.
