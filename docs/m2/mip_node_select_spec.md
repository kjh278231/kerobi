# M2-06a 노드 저장 상태·선택 추적 명세 검증 계약과 결과

작성 기준은 [스프린트 검증 기준](../15_sprint_verification.md)이다. 설계 배경은 [06 §3](../06_branch_and_bound.md#3-노드-선택-select-노트-15-35)과 [M2 설계 §5](sprint_design.md#5-m2-06-탐색분기-설계)다.

## 1. 범위와 주장

- 작업 종류: 조사(추적 오라클 포함).
- 조사 질문:
  1. **노드 용기와 순서 의미**: 전역 힙(`T+0x120/0x130`), plunge 목록(`W+0x3fa8/0x3fb0`), 지연 목록(`W+0x3fb8/0x3fc0`)에 노드가 들어가고 나가는 지점과 그 순서 규칙.
  2. **힙 키와 동률 처리**: 힙 키 `I+0x50`을 쓰는 곳과 식, 삽입(sift-up)·꺼내기(sift-down)의 같은 키 처리.
  3. **필드 소유권**: 위 용기 연산이 읽고 쓰는 노드 필드(N·I)와 worker·트리 필드. M2-10b(노드 basis 저장)가 이어받을 표.
  4. **추적 형식**: 원본에서 캡처할 수 있고(훅), 독립 3회가 같고(결정성), 저장 자료만으로 힙 연산을 재생해 모든 스냅숏과 맞는(재생 가능) 형식.
- 포함 전제: Threads=1, Seed=0, NodeLimit로 끝(시간 한도 없음), 최상위 MIP(`5bbf7f` 중첩 1)의 `6e8eb3` 호출만. sub-MIP의 선택은 세되 판정하지 않는다.
- 제외(후속 번호):
  - plunge 규칙 1–12의 점수·RNG 소비(M2-06c·06d). 조상 깊이·`5fb13c` 기반 목록 정리의 **유지 판정 규칙**도 06c다. 이번에는 정리 결과의 순서 의미만 본다.
  - 힙 키 식 전체의 Rust 이식과 대조(M2-06b). 이번에는 쓰는 지점과 C·asm 식을 기록하고, 추적에는 키 비트를 그대로 저장한다.
  - pseudocost(06e), strong branching(06g), 재시작(06j), 로그(06k), node file(`6e4db7`·`70262a`, M5), 병렬 worker 힙(`param_4 == 0`, `6e7b32`, M6).
  - status 10 노드의 둘째 힙(`T+0x150/0x158/0x160`): 삽입만 기록하고 꺼내는 곳은 이번 범위 밖(§6에 횟수 보고).
- 선행: main `e46e1a5`, 미커밋 선행 변경 없음. Rust 소스는 바꾸지 않는다.

## 2. 원본과 상태 경계

- Gurobi 13.0.3 `libgurobi130.so` SHA-256 `8e87fca221fdffc922331c8619426031b3e72dfd419446422f88af0cb0e98f9c`.
- 함수(파일 오프셋 = 훅 오프셋):
  - `6e8eb3` `0x5b29d0`(선택; 전역 힙 pop C:213–371, 규칙 판정 C:381–461, 꼬리 asm `0x5b4499`–`0x5b49eb`).
  - `6e5802` `0x5b1e70`(힙 삽입, C 전문).
  - `6e713c` `0x5afbc0`(자식 → plunge 목록, C 전문), `68bdcf` `0x56e490`(지연 목록 추가), `68c1fd` `0x56e800`(지연 목록 → 힙 또는 버림).
  - `627f3e` `0x5320c0`(자식 생성과 힙 키, C:297–335, asm `0x5334b5`–`0x5335c8` 외 키 쓰기 지점).
- 시작 경계: `6e8eb3` 진입. 종료 경계: `6e8eb3` 반환. 그 사이의 `6e5802` 진입 사건.
- 사건 사이의 다른 힙 변경은 재생이 맞지 않는 것으로 드러난다(§3 A2).
- 탐색 캡처(§4.1)에서 드러나 첫 공식 캡처 전에 더한 경계:
  - `6e460c` `0x5aed60`(cutoff 가지치기, C:49–104): 진입 사건, 지우는 노드는 그 안의 `606036`(`0x51ba80`) 호출 순서, 반환 때 힙 전체. Frida x64 문맥에 xmm0이 없어 cutoff 값은 읽지 않는다. 대신 남은 노드 bound의 최댓값 < 지운 노드 bound의 최솟값을 검사한다.
  - `6e3763` `0x5adfd0`(트리 해제), `6a6563`(재시작)의 `606036` 호출. 재시작은 06j 범위라 그 트리를 "모름"으로 두고 다음 힙 스냅숏에서 다시 맞춘다(resync 수 보고). 그 밖의 호출자가 최상위 트리 노드를 `606036`에 넘기면 실패다.
  - 최상위 트리 식별: `5bbf7f` 중첩 1의 `5daa82` 루트 삽입이나 중첩 1의 `6e8eb3`이 쓰는 트리. 그 트리에 대한 삽입·가지치기는 중첩 깊이와 관계없이 기록한다. 탐색에서 sub-MIP(중첩 2)가 상위 트리를 가지치기하는 것을 보았다. 트리 번호는 최상위가 된 순서이고 `6e3763` 해제 뒤 같은 주소는 새 번호다(포인터 값은 저장하지 않음).
  - 힙 스냅숏은 pop이 있는 `6e8eb3` 진입·반환과 `6e460c` 반환에서만 저장한다(자료 크기). 삽입만 있는 선택의 힙은 다음 스냅숏에서 대조된다.

## 3. 비교 계약(판정 규칙, 첫 캡처 전 고정)

| 검사 | 내용 | 규칙 |
|---|---|---|
| A1 결정성 | 사례별 독립 3회의 추적(포인터 제외 투영)과 출력 줄 | 정확히 같음 |
| A2 힙 재생 | 첫 스냅숏의 힙 배열에서 시작해 `6e5802` 삽입(C 규칙)과 `6e8eb3` pop(C 규칙)을 재생 | 모든 `6e8eb3` 진입·반환 스냅숏의 힙 배열(노드 id 순서)·키 비트가 같음. 꺼낸 노드는 반환 때 plunge 목록 또는 지연 목록 끝에 있어야 함 |
| A3 동률 변이 | (V1) pop에서 두 자식 키가 같으면 왼쪽, (V2) 삽입에서 부모 키와 같으면 계속 올림, (V3) pop에서 마지막 원소 키가 작은 자식과 같으면 계속 내림, (V4) 키 오름차순·삽입 순 안정 정렬 | 각 변이가 A2에서 거부되거나, 거부되지 않으면 "자료가 판별하지 못함"으로 보고. 거부·생존은 결과를 본 뒤 바꾸지 않는다 |
| A4 목록 정리 | `6e8eb3` 반환 시 plunge 목록 | 선택 노드는 빠지고, 남은 노드는 진입 목록의 상대 순서를 유지하며, 빠진 노드는 진입 목록 순서로 `6e5802` 삽입되거나 버려짐 |
| A5 동률 횟수 | 힙에 같은 키 비트의 노드가 함께 있는 pop 수, V1–V4가 다른 결과를 내는 pop 수 | 보고. 0이면 06b의 "동률 노드를 포함한 원본 선택 순서 비교"가 자연 실행으로 판별되지 않음을 §7에 적고 행을 고친다 |

- 모든 부동소수는 u64 비트 16진수로 저장·비교한다. 노드 식별은 `N+0x00`(노드 id, `M+0x58` 카운터)이다. 포인터는 저장하지 않는다.
- 사건 이름·필드가 추가·누락되면 실패다. 사례 수·사건 수·스냅숏 수를 출력한다.
- 검사기 `--self-test`는 저장 자료를 변조해(힙 순서 바꾸기, 키 비트 바꾸기, 삽입 사건 지우기, 3회 중 1회 변경, 목록 순서 바꾸기) 각 검사가 거부하는지 확인한다.
