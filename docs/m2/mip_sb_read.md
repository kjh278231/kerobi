# M2-06g 검증 계약과 결과: pseudocost 읽기 식·SB 캐시·신뢰 임계값 η

작성 기준은 [스프린트 검증 기준](../15_sprint_verification.md)이다. 표 A·`6edfcf`는 [M2-06e](mip_pseudocost.md), 표 B·C는 [M2-06e-2](mip_pseudocost_bc.md)를 따른다. M2 인수인계의 첫 다음 작업이고, 사용자의 "다음 스프린트 진행해줘. 너가 작업자야" 지시로 착수했다(2026-11-11).

## 1. 범위와 주장

- 작업 종류: 조사·오라클(읽기 전용 원본 캡처와 규칙 재생). Rust·Python 패키지는 바꾸지 않는다.
- 범위 분할(착수 때 결정): 스프린트 목록의 06g 행("strong branching 예산·복원 계약")은 코드 경로가 다른 두 계약을 묶었다. 이번 06g는 표를 읽는 쪽 식, SB 결과 캐시, 신뢰 임계값 η·SB 반복 한도(예산)만 맡는다. SB LP 풀이(`691453`·`691b56`)의 결과 소비, 임시 bound·basis 복원표, 후보 목록(`62ec1d`)·SBMAXCANDS는 **M2-06g-2**로 넘긴다. 06h의 선행은 06g-2가 된다.
- 조사 질문:
  1. `6ef12f(x, W, T, T2, j, &dn, &up)`(이득 추정)의 식. 표 합산(T2), SB 캐시 적중, 1e-6 하한, 분수부.
  2. `6eed2e(W, N, T, j)`(신뢰성 판정)의 식. 루트 예외, 캐시 예외, η 비교.
  3. `6ee4ac(x, W, T, j)`(캐시 적중 판정)의 식.
  4. `6ee5d1(x, f⁻, Δ⁻, f⁺, Δ⁺, env, W, T, j)`(SB 캐시 쓰기)의 식과 할당. 호출 지점(`62f909` `0x54287f`, `64427c`)에서 인자가 무엇으로 만들어지는가.
  5. η(`T+0x60`)와 SB 반복 한도(`T+0x64`)의 값과 수명. `62f909` 진입 조정(C:123–150, asm `0x543677`–`0x543736`)과 반환 때 복원(C:1167–1168), 그 밖의 `6edd89` 호출, `6edda1`(`64da9f` 루트).
- 완료 후 주장할 것: §2의 규칙이 §4 사례 원본 실행에서
  - `6ef12f`·`6eed2e`·`6ee4ac` 호출 전부의 출력(dn·up 비트, 반환값)을 입력 칸에서 재현한다.
  - `6ee5d1` 호출 전부의 쓴 칸 5개(stamp·work·x·캐시 두 칸)를 스택에 저장된 인자에서 비트까지 재현하고, `62f909` 호출 지점의 인자를 호출자 메모리에서 비트까지 재현한다.
  - 읽는 쪽이 본 캐시 칸이 마지막 `6ee5d1` 쓰기 값과 같다(사슬, 실행 범위 한정).
  - η 조정 블록이 실행될 때마다 판정과 `6edd89` 값을 입력에서 재현하고, `62f909`가 반환할 때 η·`T+0x64`를 진입 값으로 되돌림을 확인한다. `6eed2e`가 읽은 η가 사건 사슬의 현재 η와 같다.
  - `6edda1` 호출 전부의 `T+0x64` 값을 입력에서 재현한다.
- 제외 범위와 후속:
  - **M2-06g-2**: `691453`·`691b56` SB 풀이, 그 결과(`62f909`의 하·상 목적 배열, `local_100`·`local_f0`·`local_f8`)를 만드는 과정, bound·basis 복원, `62ec1d` 후보 목록, SBMAXCANDS, SB 비용 `T+0x68` 누적(`62f909` C:863)의 의미.
  - 점수식(`sqrt((dn+1e-5)(up+1e-5))` 등)과 `62f909` C:191–199의 캐시 적중 시 1.0001배: 후보 선택 작업(M2-06i).
  - `W+0x30`·`W+0x38`을 쓰는 곳: 진단 캡처로 찾아 기록만 한다(판정 근거 아님). 못 찾으면 미확인으로 남긴다.
  - 병렬 표(`W+0x3ff0`·`W+0x3ff8`), Threads > 1.
  - probing Δ 계산(`8950df` 등, 06e-2 인계): 후속 번호(가칭 M2-06e-3).
- 선행: main `c195957`, 미커밋 선행 변경 없음.

## 2. 원본과 상태 경계

- Gurobi 13.0.3 `libgurobi130.so` SHA-256 `8e87fca221fdffc922331c8619426031b3e72dfd419446422f88af0cb0e98f9c`. 주소는 file offset. 상수는 `.rodata`에서 직접 읽었다: `0x2a6e600` = 1.0, `0x2a6e608` = 100.0, `0x2a6e610` = 0.01, `0x2a6e618` = 1e-6, `0x2a6e5e0` = 1e-10, `0x2a6e5e8` = 0.001, `0x2a6caa8` = 0.01, `0x2a6e5c0` = 부호 제거 마스크.
- 표 구조(0x80 B, 06e): `+0`·`+8` cnt⁻·cnt⁺(int), `+0x10`·`+0x18` sum⁻·sum⁺, `+0x20` stamp(int), `+0x28` work, `+0x30` x_SB, `+0x38`·`+0x40` 캐시⁻·⁺(double), `+0x60` η(int), `+0x64` SB 반복 한도(int), `+0x68` SB 비용(double), `+0x70` M. 새 표(`6ec3da`)는 η = 1, `+0x64` = 0, `+0x68` = 0, 캐시 포인터 null.

### 2.1 `6ef12f`(asm `0x5b7920`–`0x5b7b12`)

rdi = W, rsi = T, rdx = T2(null 가능), ecx = j, r8 = &dn, r9 = &up, xmm0 = x. x는 `0x5b792e`에서 `(%rsp)`에 저장된다(캡처는 이 칸을 읽는다).

```text
f = x − floor(x)
hit = T+0x20 != 0 && W+0x30 == stamp[j] && !(100.0 < W+0x38 − work[j]) && !(0.01 < |x − x_SB[j]|)   # comisd, NaN이면 miss
ψ⁻ = hit ? 캐시⁻[j]
   : (T2 != 0 && T2.cnt⁻[j] + T.cnt⁻[j] > 0) ? (T2.sum⁻[j] + T.sum⁻[j]) / (double)(T2.cnt⁻ + T.cnt⁻)
   : T.cnt⁻[j] > 0 ? T.sum⁻[j] / (double)T.cnt⁻[j] : 0.0
ψ⁺ = 같은 식(+ 쪽 칸, 캐시⁺)
dn = maxsd(ψ⁻, 1e-6) · f;   up = (1.0 − f) · maxsd(ψ⁺, 1e-6)
```

### 2.2 `6eed2e`(asm `0x5b77a0`–`0x5b7858`)

rdi = W(null 가능), rsi = N, rdx = T, ecx = j. I = N+0x18, M = I+0, L = I+8.

```text
N == M+0x790 이고 cnt⁻[j] > 0 이고 cnt⁺[j] > 0 이면 0
L != 0 && L+0x18 != 0 && W != 0 && T+0x20 != 0 && W+0x30 == stamp[j]
  && !(100.0 < W+0x38 − work[j]) && |xL[j] − x_SB[j]| <= 0.01 이면 0      # xL = L+0x18
cnt⁻[j] < η 또는 cnt⁺[j] < η 이면 1, 아니면 0
```

### 2.3 `6ee4ac`(asm `0x5b7540`–`0x5b759a`)

rdi = W, rsi = T, edx = j, xmm0 = x(leaf, 저장 없음). 반환 = §2.1의 hit. x는 반환 주소로 호출 지점을 가려 호출자 메모리에서 읽는다: `0x542d89`(`62f909`)는 `[r14 + rbp·8]`, `0x535f88`(`62a05d`)는 `[r14 + rbx·8]`. 두 지점 모두 바로 앞 `6ef12f`에 같은 칸을 넘긴다(asm `0x542d61`·`0x535f60`).

### 2.4 `6ee5d1`(asm `0x5b75a0`–`0x5b7746`)

rdi = env, rsi = W, rdx = T, ecx = j, xmm0–4 = x, f⁻, Δ⁻, f⁺, Δ⁺. 프롤로그가 `0x8/0x18/0x20/0x10/0x28(%rsp)`에 저장한다(캡처는 `0x5b75ea`에서 읽는다).

```text
T+0x20 == 0 이면: n = 열 수((T+0x70)+8)+0xe8)+0xc). n > 0 이면 다섯 배열 할당(실패 0x2711), stamp를 −1로 채움; 아니면 포인터 0
stamp[j] = W+0x30;  work[j] = W+0x38;  x_SB[j] = x
캐시⁻[j] = maxsd(Δ⁻, 1e-10) / (|f⁻| + 0.001);   캐시⁺[j] = maxsd(Δ⁺, 1e-10) / (|f⁺| + 0.001)
```

호출 지점 `62f909` `0x54287f`의 인자(asm `0x54281f`–`0x54287b`): x = `[rbx + r14·8]`, f⁻ = `[rsp+0x60]`, Δ⁻ = (`[rbp + r15·8]` − `[rsp+0xc8]`) · `[rsp+0xd8]`, f⁺ = `[rsp+0x18]`, Δ⁺ = (`[r12 + r15·8]` − `[rsp+0xc8]`) · `[rsp+0xd8]`. `64427c` 지점은 탐색 캡처에서 실행 여부를 본 뒤 필드를 정한다.

### 2.5 η·SB 반복 한도

- `62f909` 진입(C:123–150): η₀ = `T+0x60`, s₀ = `T+0x64`. η₀ < 0이면 `0x543677`–`0x543736`:

```text
it = 5e8ba8(M)(spill [rsp]);  t = timer[0] + (timer+0x28 != 0 ? *W : 0)   # adf00e(r8+0x300, [rsp+0x1e0])
0.01 · M+0x8c0 > t:  6edd89(T, 2e9); T+0x64 = −1                          # 0x54371c
아니면 c = (T+0x68 == 0) ? 2e9 : (int)(it / T+0x68)                       # cvttsd2si
  c <= 0: 6edd89(T, 1);  c < −η₀: 6edd89(T, c);  아니면 6edd89(T, −η₀)
```

- 반환(C:1167–1168, `0x542fab`): `6edd89(T, η₀)`; `T+0x64 = s₀`.
- 그 밖의 `6edd89` 호출자: `5bbf7f`·`5be289`·`646052`·`6a6563`(탐색 캡처에서 실행 여부 확인).
- `6edda1(M, T, a, b, p)`(`64da9f`): C 식 그대로(SBMAXITERS `M+0x3458`, `(M+0x620)+0x808`, `M+0x618`, MIPFocus `((M+8)+0x100)+10000`, 노드 수 `(M+0x620)+0x60`). 레지스터 인자 a·b·p와 읽는 칸을 캡처한다.

## 3. 비교 계약

| 필드·사건 | 비교 규칙 | 캡처 |
|---|---|---|
| `6ef12f` dn·up | 비트 | 진입 GPR, `0x5b794f` probe의 `[rsp]`(x), 반환 때 `*r8`·`*r9`. T·T2의 j 칸(cnt·sum), stamp[j], stamp == W+0x30일 때만 work·x_SB·캐시 칸 |
| `6eed2e` 반환 | 정확 | 진입: W null 여부와 W+0x30·+0x38, N == M+0x790, L·xL null 여부와 xL[j], j 칸, η |
| `6ee4ac` 반환 | 정확 | 진입 GPR과 호출 지점별 x |
| `6ee5d1` 쓴 칸 5개 | 비트 | `0x5b75ea` probe의 저장 인자, 반환 뒤 j 칸, 할당 여부·n·stamp 초기값(−1 개수) |
| `62f909` 지점 인자 | 비트 | `0x54287f` probe의 호출자 메모리 |
| 캐시 사슬 | 정확 | 읽는 쪽 stamp·work·x_SB·캐시 칸 = 그 표의 마지막 쓰기(없으면 할당 직후 stamp −1) |
| η 블록 판정·값 | 정확·비트 | `0x5436a0` probe(η₀, `T+0x68`, it, timer 칸, *W, `M+0x8c0`)와 뒤따르는 `6edd89` |
| `6edd89` 전부 | 정확 | 호출자·반환 주소·표 번호·값 |
| 반환 복원 | 정확 | `62f909` 진입·반환의 η·`T+0x64` |
| `6eed2e`의 η 사슬 | 정확 | 표 생성 스냅숏(η)과 `6edd89` 사건으로 만든 현재 η |
| `6edda1` 값 | 정확 | 진입 레지스터·읽는 칸, 반환 뒤 `T+0x64` |

- 부동소수는 u64 16진수로 저장해 비트 비교한다. 오차 허용 필드는 없다.
- 표는 생성 순서 번호로 부른다(06e-2와 같은 slot 이름).
- 시간: η 조정의 "시간"은 work 타이머(`adf00e`)라 결정적이다. Threads=1, NodeLimit으로 끝낸다.
- 재현성: 같은 사례를 독립 프로세스로 3회 실행해 gz 바이트가 같아야 한다.
- 비간섭: 출력 줄(`DONE status nodes`)과 `rd` 카운트(06e-2와 같은 형식)가 `bench/oracle/m2_06e2`의 같은 사례 run 1과 같아야 한다.
