# M2-06f-5 검증 계약과 결과: infeasible ray 수정 `6684cd`

작성 기준은 [스프린트 검증 기준](../15_sprint_verification.md)이다. 앞선 작업은 [M2-06f-4](mip_infeas_ray.md)(`95da98`, 기준 자료 `bench/oracle/m2_06f4`)다. M2 인수인계의 첫 다음 작업이고, 사용자의 "다음 스프린트 진행" 지시로 착수했다(2026-11-11).

## 1. 범위와 주장

- 작업 종류: 조사·오라클(읽기 전용 원본 캡처와 규칙 재생). Rust·Python 패키지는 바꾸지 않는다.
- 조사 질문:
  1. **수정 규칙.** `5fb8ec` C:2217이 부르는 `6684cd`(와 그 안의 `95ce25`)는 infeasible 노드 벡터 ray(`L+0x70`)와 `L+0x5c`·`+0x60`·`+0x68`을 어떻게 바꾸는가? 언제 바꾸지 않는가(변경 0회, `95ce25` 실패 뒤 복원)?
  2. **게이트.** `L+0x68 ≥ 1e-4`인 `95da98` 성공 중 `6684cd`가 불리지 않는 경우(06f-4 기준 run 1에서 14회: markshare_4_0 7, tr12-30 6, fhnw-binpack4-4 1)는 왜 안 불리는가? `6684cd`가 불릴 때 C:2208–2216 게이트 조건이 모두 성립하는가?
- 완료 후 주장할 것:
  - Q1: §2.3 규칙(C·asm 근거)을 Python으로 재생하면 §4 사례의 모든 `6684cd` 호출에서, 진입 때 캡처한 입력(§3)으로부터 반환 때 ray n+m칸, `L+0x5c`·`+0x60`·`+0x68`, 반환값, work가 비트까지 같다. `788a84` 질의 순서와 `95ce25` 진입 상태(ray·ρ·`L+0x68` 누적값)·실패 코드도 같다.
  - Q2: `L+0x68 ≥ 1e-4`인 성공 중 미호출 각각을 캡처한 사건(감싸는 `5ce67b`의 호출 지점, 이후 `5fb8ec` 진행)으로 분류하고, 분류마다 C 근거를 적는다. 분류하지 못한 미호출이 남으면 Q2는 미해결로 둔다.
  - 조사이므로 Rust 구현 일치 판정은 없다.
- 제외 범위와 후속:
  - flip 방식 1(`lp+0x3c == 1`: `f7dc1`·`7d3ce` 스케일 전환), 열 스케일 없음(C null), work 포인터 null, 원래 LP 열 수 n0 ≠ n: 관측되면 검사기가 범위 밖으로 실패한다.
  - 메모리 할당 실패(반환 `0x2711`), `5e6ed8`(`8950ca`, 매 후보마다 부름)의 부수 효과: C로만 본다. `5e6ed8`는 계산에 쓰는 값을 바꾸지 않는다고 가정하고, 재생 일치로만 간접 확인한다.
  - 수정 뒤 소비자 `68c35b`(conflict 저장)와 감쇠 `6ee1d3`: 06f-4가 비교했다. 여기서는 감쇠가 읽는 벡터가 이 재생 출력과 같은지만 06f-4 `pp`와 대조한다.
  - 병렬(Threads=1만), node file.
- 선행: main `bb77396`(M2-06f-4 병합 포함). 미커밋 선행 변경 없음.

### 2.1 호출 지점 `5fb8ec` C:2208–2228

```text

L ≠ 0, L+0x38 == 3, L+0x58 ≥ 0, L+0x68 ≥ 1e-4(0x3f1a36e2eb1c432c), L+0x70 ≠ 0 이면
  env+0x2a48 ≠ 0 이면 rc = 6684cd(P, N, work)   (P = {M, S}, rc ≠ 0 이면 반환)
  68c35b(L+0x60, (double)L+0x54, …, N, L+0x70, -1, 0, L+0x5c + 1, 0, 0, work)
```

### 2.2 기호

`P[0]` = M, `P[1]` = S. `lp = S+0xe8`(노드 LP): n = `lp+0xc`, m = `lp+8`, flip 방식 `lp+0x3c`, 열 행렬 `lp+0xf8`(열 시작, long)·`+0x100`(개수, int)·`+0x108`(행 첨자)·`+0x110`(값), sense `lp+0x388`(m 바이트), R `lp+0x3d8`, C `lp+0x3e0`, 스케일된 lb·ub `lp+0x390`·`+0x398`. 원래 LP `lp0 = (M+8)+0xe8`: m0 = `lp0+8`, n0 = `lp0+0xc`, 행 CSR `lp0+0x118`(시작)·`+0x120`(끝)·`+0x130`(열)·`+0x138`(값), rhs `lp0+0x380`. cut 행 t = i − m0: `cut_t = ((M+0x3240)+0x78)[t]`, `{idx = cut_t[0], val = cut_t[1], cnt = (int)cut_t[2], rhs = (double)cut_t[3], age = cut_t+0x38}`. 노드 N: 부모 `N+0x10`, I = `N+0x18`, 개수 c1 = `N+0x24`·c2 = `N+0x28`·c3 = `N+0x2c`, 기록 `N+0x30`: c3개 16바이트 `{sense 바이트, var int}`, 이어서 c1개 int(목록 1), c2개 int(목록 2). 시작 노드의 깊이 d = `I+0x2c`, 노드 bound lb⁰ = `I+0x80`, ub⁰ = `I+0x88`(n, 비스케일), 타입 `M+0x650`. L: s = `L+0x54`, `L+0x5c`, ρ = `L+0x60`, g = `L+0x68`, ray = `L+0x70`(n+m).
