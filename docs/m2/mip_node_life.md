# M2-06f-2 검증 계약과 결과: 조상 노드 정보 수명과 노드 LP 결과 벡터

작성 기준은 [스프린트 검증 기준](../15_sprint_verification.md)이다. 앞선 작업은 [M2-06e](mip_pseudocost.md)(원본 규칙·기준 자료)와 [M2-06f](mip_pseudocost_rust.md)(Rust `Pseudocost`, `bnb.rs` 미연결)다. M2 인수인계의 첫 다음 작업이고, 사용자의 "다음 스프린트 진행" 지시로 착수했다(2026-11-11).

## 1. 범위와 주장

- 작업 종류: 조사·오라클(읽기 전용 원본 캡처와 규칙 재생). Rust·Python 패키지는 바꾸지 않는다.
- 조사 질문:
  1. **조상 정보 수명.** 감쇠 `6ee1d3`은 부모 링크(`N+0x10`)를 따라 올라가다가 조상의 I(`A+0x18`)가 없으면 멈춘다(06e: 8,972회 중 7,238회가 여기서 끝남). 조상의 I와 N은 언제 사라지는가?
  2. **노드 LP 결과 블록 L(`I+0x08`).** 감쇠가 읽는 `L+0x38`·`L+0x54`·`L+0x58`·`L+0x18`과 벡터 `L+0x28`·`L+0x70`의 의미는 무엇이고, 어디서 만들어지는가?
  3. **Rust 판정.** Rust B&B(`crates/mip/src/bnb.rs`)가 `Pseudocost::decay`·`node_update`에 같은 입력을 줄 수 있는가? 모자라면 무엇이 필요한가?
- 완료 후 주장할 것:
  - Q1: §2.2의 해제 규칙이 §4 사례의 원본 실행을 재현한다. 노드 생성(`5ff358`)과 해제 요청(`5f9d4e` 진입)만으로 재생하면, 이어지는 `5fa560` 호출 열(노드, 단계)과 I·N 해제가 원본과 같다. 감쇠마다 조상 사슬(조상 노드 열과 끝난 이유)도 원본과 같다.
  - Q2: 세 벡터의 생성 함수(§2.3)는 C·asm 근거다. 감쇠가 고른 벡터를 마지막으로 쓴 함수가 §2.3 선택 규칙과 맞는지는 캡처로 확인한다. `12ef7f` 첫 출력이 환산비용이라는 의미는 C 근거(`1121ad`)다. 캡처로 확인하는 것은 `1121ad` 주 경로에서 기저 열 값이 0이라는 점까지다.
  - Q3: 입력별 판정표(§7)를 낸다. 조사이므로 Rust 구현 일치 판정은 없다.
- 제외 범위와 후속:
  - `95da98`(9.7 KB, dual simplex `cda5b` 호출)의 계산 내용: 게이트·출력 칸·성공 조건만 다루고, 해독은 후속으로 둔다.
  - 표 B·C, strong branching 경로 입력: M2-06e-2·06g.
  - 지연 목록(`68bdcf`·`68c1fd`)의 `I+0x70` 참조 수와 `+0x80`/`+0x88` 해제, node file, 병렬(Threads=1만).
  - plunge·꼬리 정리의 유지 판정: 06c.
- 선행: main `9bcb0e6`(M2-06f 병합 포함). 미커밋 선행 변경 없음.

## 2. 원본과 상태 경계

- Gurobi 13.0.3 `libgurobi130.so` SHA-256 `8e87fca221fdffc922331c8619426031b3e72dfd419446422f88af0cb0e98f9c`. 주소는 file offset이다. 인자 레지스터는 호출 지점 asm에서 확인했다(`objdump -d` 전체).

### 2.1 노드 생성 `5ff358(parent, M, &out)` (`0x5177f0`, C 전문 앞부분·asm `0x5177fe`–`0x517804`)

- 인자: rdi = 부모 N(Ghidra는 double로 잘못 표기), rsi = M, rdx = 출력 칸. 루트는 `out = &M+0x790`이다(`5daa82` `0x500107`).
- N(0x40 B)과 I(0xc0 B)를 할당하고 `N+0x00` = id(`M+0x620→+0x58` 카운터), `I+0x68` = 5(단계), `I+0x00` = M을 둔다. 부모가 있으면 depth = 부모 depth + 1, `I+0x78` = 부모 `I+0x10`, 부모 basis 복사(`69e299`)를 한다. 성공하면 `parent+0x22`(short 자식 수) += 1, `N+0x10` = parent, 부모 `I+0x6c`(아직 단계 5를 벗어나지 않은 자식 수) += 1이다.

### 2.2 해제 `5f9d4e(env, N, T, s)` (`0x516bc0`) → `5fa560(env, X, s)` (`0x516f10`)

C 전문을 읽었다. 단계 −1은 0으로 바꾼다. 단계 6은 해제가 아니라 L 생성이다(§2.3).

```text
X = N
loop:
  old = X.I ? X.I+0x68 : 1;  if X.I: X.I+0x68 = s
  5fa560(X, s)                          # 아래 표
  P = X.parent; P 없으면 끝
  s == 0 이면 P+0x22 -= 1
  P+0x22 == 0 이면 (X = P, s = 0, loop)  # 마지막 자식이 사라지면 부모도 단계 0
  P.I 없으면 끝;  s > 4 이면 끝;  old < 5 이면 끝
  P.I+0x6c -= 1;  0이 아니면 끝;  P.I+0x68 < 3 이면 끝
  X = P, s = 1, loop                    # 부모의 I만 해제(N은 유지)
```

| `5fa560(X, s)` | 루트(`X == M+0x790`) | 그 밖 |
|---|---|---|
| I 없음 | — | s == 0이면 N 해제 |
| s > 5 | 아무것도 안 함 | 아무것도 안 함 |
| 3 ≤ s ≤ 5 | 아무것도 안 함 | L(`I+0x08`)·cut 정보(`I+0xb8`) 해제 |
| 1 ≤ s ≤ 2 | 아무것도 안 함 | 위 + I 배열·I 해제, `N+0x18 = 0` |
| s == 0 | 전부 해제, `M+0x790 = 0`, N 해제 | 위 + N 해제 |

- 단계를 주는 쪽(호출 지점 asm의 ecx): `5fe9cd` 노드 처리 끝(자식 없음 0, 있음 3), 꼬리 정리·`68c1fd`·`6e7b32` 등 힙으로 옮김 4, 가지치기·버림 0, `5ce67b`·`64da9f`·`6a6563` L 생성 6, `5c9…`(−1). 함수 진입을 훅하므로 호출 지점 목록이 빠져도 캡처는 모두 본다.
- 이 규칙의 뜻(C 해석, Q1의 예측): 조상 P의 I는 **P 자신이 단계 3 이상으로 처리됐고, P의 자식이 모두 단계 5를 벗어났을 때**(처리됐거나, 힙으로 옮겨졌거나, 버려졌을 때) 사라진다. P의 N은 자식이 하나라도 남아 있으면 유지된다. 그래서 감쇠 사슬은 대개 형제가 모두 처리된 조상에서 끝나고, 루트의 I는 단계 0까지 남는다.

### 2.3 노드 LP 결과 블록 L(0xd0 B)

| 칸 | 쓰는 곳 | 의미 | 근거 |
|---|---|---|---|
| 블록 생성 | `5ce67b` C:246 `5f9d4e(N, 6)`(노드 LP를 풀 때마다, `0x4f10c5`). 이미 있으면 그대로 둠 | 생성 때 `+0x38 = 1`, `+0x58 = −1`, `+0x80`·`+0x84`·`+0x88`·`+0x8c`·`+0xb0`·`+0xb4`·`+0xb8 = −1` | C |
| `+0x38` | `5ce67b`(LP 뒤) | LP 상태(Gurobi 코드: 2 최적, 3 infeasible, 5 unbounded, 6 cutoff, 0x11 등) | C(`600d25`가 같은 칸으로 분기) |
| `+0x18` 블록, `+0x20`·`+0x28`·`+0x30` | `5d4427` C:122–140(최적 경로, `5ce67b` C:1358) | 한 할당 2(n+m) double: `+0x18` x(n), `+0x20` 행 활동(m), `+0x28` 환산비용(n), `+0x30` 행 쌍대값(m). `+0x28`·`+0x30`은 `12ef7f(lp, +0x28, +0x30)`(`0x4f6f9c`)가 채운다 | C |
| `+0x70`(cutoff) | `5ce67b` C:1259–1295(LP 상태 6, 루트 밖) | 길이 n+m. `12ef7f(lp, v, v+n)`(`0x4f42d3`)이 환산비용(n)·행 쌍대값(m)을 채운다. 행 쌍대값 중 \|π\| > 1e-13인 행에 `7889ec`가 참이면 해제한다 | C |
| `+0x70`·`+0x78`, `+0x54`·`+0x58`·`+0x5c`·`+0x60`·`+0x68`(infeasible) | `5ce67b` C:1183–1250(LP 상태 3, 루트 밖, lp+100 == 3, `M+0x346c ≠ 0`) | 둘 다 길이 n+m. `95da98(…, &L+0x58 r8, &L+0x54 r9, …)`(`0x4f46c6`)가 채운다. 실패하면 둘 다 해제하고 `+0x58 = −1` | C·asm(인자 레지스터) |
| `+0x3c` | 위 세 곳 | 행 수 m | C |

- `12ef7f`(`0x1bbe40`) → `1121ad`(`0x1a5170`): lp+0xe0(spx)가 없으면 해 구조(lp+0x1b0)의 `+0x20`(n)과 `+0x18`(m)을 복사한다. spx+0x28이 서 있으면 `23ac2b`로 간다. 주 경로는 열 j마다 다음과 같다. vstat ≥ 0(기저)이면 0, −2면 `−d[j]`, −1이면 `d[j]`, 그 밖이면 `c[j] + Σ a_ij·y_i`다. 이어 열 뒤집기 표시면 부호를 바꾸고, 열 스케일·목적 스케일로 나눈다. 기저 열이 0이므로 첫 출력은 기본해 x가 아니라 환산비용이다. 노트 13 표의 "기본해 계산"은 이 점에서 부정확하다.
- 감쇠 `6ee1d3`(06e §2.4)은 `+0x38 == 6 || +0x58 ≥ 0`이면 `+0x70`, 아니면 `+0x18`이 있을 때 `+0x28`을 쓴다. `+0x58 < 0`이면 s = 1, 아니면 s = (double)`+0x54`다. 감쇠는 현재 노드 N의 L만 읽는다. 조상의 L은 읽지 않는다(조상은 `I+0x34` 분기 변수와 `I+0x40` 방향만 읽는다).

### 2.4 시작·끝과 입력

- 사건 하나는 원본의 한 호출이다: `5ff358` 반환, `5f9d4e` 진입, `5fa560` 진입·반환, `12ef7f` 진입·반환, `95da98` 진입·반환, `5fe9cd` 감쇠 입구(`0x51679f`), `6ee1d3` 진입·반환.
- 노드는 생성 순서 일련번호로 부른다(주소는 출력하지 않는다). `5fa560(·,0)` 반환 때 N 주소의 연결을 끊는다. 벡터 출처는 주소 → (마지막으로 쓴 사건 번호, 호출 지점) 표로 도구 안에서만 들고 있다.

## 3. 비교 계약

`tools/mip_node_life_check.py`가 판정한다. 하나라도 실패하면 종료 코드 1이고 첫 차이(사례·사건 번호·노드·기준값·실제값·검사)를 출력한다.

| 검사 | 규칙 |
|---|---|
| L1 재현성 | 사례마다 원본 3회 gz 바이트가 같다. `ok`, `errors` 없음, `tool_sha256`이 현재 도구와 같다, 파라미터가 `{Threads 1, Seed 0, LogToConsole 0, NodeLimit 2000}`, manifest SHA-256과 같다 |
| L2 해제 재생 | `nn`·`rel` 사건만으로 §2.2 모형을 돌린다. `rel`마다 예측한 `old`가 캡처값과 같고, 바로 뒤 `fr` 열(노드·단계)이 예측과 같고, `fr` 반환의 I 유무가 예측과 같다. 단계 6은 `fr` 0개다. 루트 표시(`nn`의 출력 칸이 `M+0x790`)가 `fr`의 루트 표시와 같다. 생성되지 않은 노드의 `rel`·`fr`은 실패다 |
| L3 감쇠 사슬 | `dec`마다 모형 상태에서 부모를 따라 올라간 조상 열과 끝난 이유(`noI`: I 없는 조상, `nop`: 부모 없음)가 캡처의 조상 일련번호 열·이유와 같다. 현재 노드의 I·L 유무(`noI`·`noL`)도 모형과 같다(L은 마지막 `rel(·,6)` 뒤 단계 ≤ 5 해제가 없으면 있음) |
| L4 06e 대조 | `dgate`·`dec` 사건을 06e 칸(06e 도구와 같은 칸)으로 줄이면 사례별로 06e run 1과 같은 순서로 같다. 출력 줄이 같다 |
| L5 벡터 출처 | `dec`(L 있음)마다 §2.3 규칙으로 고른 벡터의 마지막 쓰기가 다음과 같다. `+0x38 == 6`이면 `12ef7f@0x4f42d3`, 그 밖에 `+0x58 ≥ 0`이면 `95da98`(반환 0, 같은 L), 그 밖이면 `12ef7f@0x4f6f9c`. 그 쓰기는 이 노드의 마지막 `rel(·,6)`보다 뒤다. `95da98` 진입의 r9 = r8 − 4다 |
| L6 환산비용 | `12ef7f`가 `1121ad` 주 경로(spx 있음, spx+0x28 = 0, spx+0x488 = 0)를 탄 호출에서 vstat ≥ 0인 열 j < n의 첫 출력이 모두 +0 또는 −0이다 |
| L7 분기 | 6사례 합계에서 단계 0·3·4·6 `rel`, 자식 수 연쇄(부모 단계 0), 부모 I 해제(단계 1), `old < 5`로 멈춤, 부모 단계 < 3으로 멈춤, 루트 `fr`(무시), 감쇠 끝 `noI`·`nop`, L5의 세 출처가 모두 1회 이상 |
| T 변조 | (`--self-test`) run 1 사본에 변조 6종(`fr` 단계, `fr` 삭제, `dec` 조상 일련번호, `dec` 끝 이유, 벡터 출처 지점, L6 기저 0 아닌 수)을 넣으면 각각 실패 |
| V 변이 | (`--self-test`) §2.2 모형의 한 절을 바꾼 변이가 아래 분기 수 규칙대로 거부·생존한다 |

V 기대는 공식 캡처 전에 탐색 캡처(§6.1, 판정 근거 아님)의 분기 수로 정하고, 이 표에 적은 뒤 공식 캡처를 한다. 기본 규칙은 "그 절이 결과를 바꾸는 분기 수 > 0인 사례에서만 거부"다.

| 변이 | 바꾼 절 | 거부 조건(그 사례의 분기 수 > 0) |
|---|---|---|
| W1 | `old < 5` 멈춤 제거 | 힙에서 꺼낸 노드(단계 4→3·0)가 부모 `+0x6c`를 다시 줄이는 해제 |
| W2 | 부모 단계 < 3 멈춤 제거 | 부모가 아직 단계 5인데 `+0x6c`가 0이 된 해제 |
| W3 | 자식 수 연쇄 제거(부모 N을 지우지 않음) | 마지막 자식 단계 0으로 부모가 단계 0이 된 해제 |
| W4 | `s > 4` 멈춤을 `s > 3`으로 | 단계 4 해제가 부모 `+0x6c`를 줄인 경우 |
| W5 | 부모 I 해제를 단계 1 대신 0으로 | 부모 I 해제(단계 1) |
| W6 | 루트 예외 제거 | 루트 `fr`의 단계 1–5 |

- 수치 비교: 이 작업의 비교 대상은 정수·포인터 동일성·부호 비트다. 06e 칸의 double은 u64 16진수로 비교한다.
- 시간·work·병렬: Threads=1, 종료는 NodeLimit 2000(06e와 같음).
- 원본 재현성: 같은 설정 3회 독립 실행의 gz 바이트 비교(L1).
