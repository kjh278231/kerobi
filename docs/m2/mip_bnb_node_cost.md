# M2-10a 노드별 복사·LP 준비·풀이 비용 계측 검증 계약과 결과

작성 기준은 [스프린트 검증 기준](../15_sprint_verification.md)이다.

## 1. 범위와 주장

- 작업 종류: 조사.
- 조사 질문: 현재 Rust B&B(`crates/mip/src/bnb.rs` `solve_started`)에서 노드 하나를 처리하는 비용이 어느 구간에 쓰이는가. 구간은 노드 선택(`retain`·최소 경계 스캔·종료 검사), 분기(`branch`의 `Model` 복사), 노드 LP(스케일 작업 공간 생성·엔진 생성·dual 풀이·무스케일 재확인), incumbent 검사, 루프 밖의 presolve·루트·복원이다. 결과로 모델·구간별 비용표와 데이터로 고른 개선 대상 하나를 M2-10b에 넘긴다.
- 보조 질문(M2-10b 입력): 부모 최종 basis로 자식 LP를 dual warm start(`solve_model_warm`)하면 반복 수와 시간이 얼마나 되는가. 반사실 측정이며 탐색 궤적에는 쓰지 않는다.
- 포함 전제: Threads 기본, NodeLimit 500, TimeLimit 없음(벽시각으로 종료 지점을 만들지 않음), 나머지 파라미터 기본값.
- 제외: 최적화 구현(M2-10b 이후), Gurobi 노드 처리 속도와의 비율 판정(서로 다른 일을 하므로 P3 패리티가 아님), `crates/lp` 수정(M1 활성 영역).
- 선행: main `7f86824`, 미커밋 선행 변경 없음.

## 2. 원본과 상태 경계

- 원본: 해당 없음. Rust 자체 비용 조사이며 원본 동작과의 동등성을 주장하지 않는다. Gurobi를 실행하지 않는다.
- 계측 경계: `solve_original` 진입부터 반환까지. 루프 구간은 `solve_started`의 `while` 한 바퀴를 위 구간으로 나눈다. 잔여(루프 벽시각 − 구간 합)를 따로 적는다.
- LP 내부 분할: `crates/lp`를 고치지 않고 `solve_model_run`(simplex.rs:1720)이 쓰는 pub 조각(`Spx::new`, `Engine::new`, `Engine::solve(1)`, `Spx::unscaled`, `Engine::resolve_unscaled`)을 같은 순서로 재생한다. 재생의 status·iter·obj 비트·x 비트가 매 노드 실제 호출(`solve_model_deadline`)과 같아야 분할을 인정한다. `deadline`은 private이지만 TimeLimit 없음이면 실제 호출도 `None`이다.
- 계측 코드: 임시 패치 `bench/oracle/m2_10a/profile.patch`(bnb.rs만). 측정 뒤 되돌린다. 하네스는 무시 테스트 `crates/mip/tests/bnb_profile.rs`.

해석:

1. **노드 비용의 대부분은 노드 LP다.** 500노드에서 91–99%, 2만 노드에서도 76–91%다. presolve·루트는 neos-860300의 presolve 5.5%를 빼면 1% 미만이다. `Model` 전체 복사(분기·복사)는 0.2–2.7%다. 복사는 노드당 nnz 123–38,040개를 옮기지만 LP보다 두 자릿수 이상 싸다.
2. **노드 LP 안에서는 dual 풀이가 80–95%다.** 스케일 작업 공간 생성(`Spx::new`)은 0.4–6.5%, 엔진 생성은 2% 미만, 무스케일 재확인(`Spx::unscaled`+`resolve_unscaled`)은 3.6–15.9%다.
3. **풀이 비용은 매 노드 cold start 때문이다.** 노드마다 slack basis에서 시작해 반복이 노드당 9.7–500회다. 부모 최종 basis로 dual warm start(`solve_model_warm`)하면 같은 노드 LP의 반복이 1.5–138배(중앙 약 8배) 줄고 시간은 1.4–7.9배(중앙 약 2.3배) 준다. 세 실행 모두 각 6,000 노드 전부 status가 같고 목적이 1e-6 상대 이내였다.
4. **warm start 뒤에는 LP 한 번의 고정 비용이 남는다.** 반복 비에 비해 시간 비가 작다. tr12-30은 warm 반복이 노드당 2.6회인데 warm LP가 노드당 1.7ms이고 그 85%가 `Engine::solve_warm` 안이다. 스케일·엔진·무스케일 재확인 고정분은 노드당 0.01–1.2ms다. `solve_warm` 안의 시작 분해·가중치 초기화 등의 분할은 `crates/lp`를 고치지 않고는 잴 수 없어 미측정이다.
5. **원본 근거**: 원본 노드 첫 LP(`5ccea5` C:204–345)는 노드에 저장된 basis `I+0x98/0xa0`을 `cda5b`에 넘긴다([M2-03c-2](mip_retry_basis.md) §104–106, nidda 사례). 노드 basis 재사용은 원본 동작이기도 하다. 다만 저장 basis가 부모의 최종 basis인지, 언제 저장·상속되는지는 M2-10b 범위다.

## 7. 판정과 인수인계

- 작업 수행 상태: 완료(조사).
- 동등성: 해당 없음(Rust 자체 비용 조사). Gurobi는 실행하지 않았다.
- 답: 노드 처리 시간의 대부분은 매 노드 cold start하는 노드 LP의 dual 반복이다. **개선 대상 하나는 노드 LP의 부모 basis 재사용(warm start)**이다. 이 측정 범위에서 노드 LP 시간이 1.4–7.9배 준다.
- M2-10b에 넘길 사실:
  - 반사실은 부모 최종 basis(Gurobi VBasis/CBasis 부호)를 자식 `Node`에 복사해 `solve_model_warm`으로 풀었다. 분기 bound 변경만 있는 자식이라 차원이 같고 `warm_none` 0이다.
  - warm 결과의 x는 비트 비교하지 않았다. 대안 최적해가 있으면 분기 변수가 바뀌어 Rust 탐색 궤적이 달라진다. 원본 궤적 동등성(P1)은 basis 저장·상속 규칙을 원본에 맞춘 뒤 판정해야 한다.
  - warm 뒤에는 `solve_warm`의 고정 비용과 무스케일 재확인(cold의 3.6–15.9%)이 다음 비중이다. 작업 공간·분해를 노드 사이에 유지할지는 원본의 노드 LP 수명(03d-7: 다이브 중 같은 D를 이어 씀)과 함께 정한다.
  - 열린 노드가 수만 개면 선택(`retain`+선형 스캔)이 6–19%로 커진다. 원본 노드 선택 구조(M2-06a·06b)와 함께 다룬다.
  - 열린 노드마다 `Model` 전체를 들고 있어 메모리는 열린 노드 수 × 모델 크기다. 이번 측정에서 시간 병목은 아니었다. 메모리는 재지 않았다.
- 미검증·미측정: `solve_warm` 내부 분할(분해·가중치), 원래 모델 직접 풀이 경로, 메모리, 5초 TimeLimit 실행 자체(NodeLimit로 고정), 500·2만 노드 밖의 열린 노드 규모.
