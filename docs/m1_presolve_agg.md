# M1 LP presolve: 집계 `519a52` / `37f484` 해독 노트

[m1_presolve.md](m1_presolve.md) §7 6단계(집계)의 해독이다. 2026-11-05에 의사코드와 asm으로 정적 해독했다. 오라클로는 아직 확인하지 않았다. 줄 번호는 `re/decomp/c/`의 각 함수 파일 기준이다(예: `37f484` L1251 = `00381f20_PRIVATE000000000037f484.c` 1251줄).

## 0. 범위와 가정

기본 파라미터의 일반 LP만 다룬다. 이때 상태 값은 다음과 같다.
- `+0xfc`=0(LP), `+0x150`(변수 타입)=NULL, `+0x278`=0, `+0x27c`=0(QC 수), `+0x100`=0, `+0x330`=0, `+0x08`≠4, `+0x170`(열 플래그)=0.
- `+0x278`은 `3a484d` L2383/L3486에서 QC·Q가 있을 때만 1이 된다. 그래서 LP에서는 `517fa8`이 돌지 않고 `519a52`만 돈다.
- 호출 조건(`390989` L897–899): Aggregate≠0 && (k==0 || Aggregate>1) && (local_38==0 || n < 20·m). 기본값에서는 pass 0에서 한 번만 돈다. PRELIMIT 카운트는 `519a52` 전체가 1이다(L918). 그래서 PRELIMIT로는 단계를 나눠 볼 수 없다.

파라미터 기본값은 Gurobi에 묻지 않고 바이너리의 파라미터 표에서 읽었다. 표는 `.data`에 있고, 항목은 {이름 포인터, 종류, min, max, 기본값}이다(예: PREPAIRAGG 이름 포인터 @0x2fb1838). `ac81d7`의 `accc50`이 이 표의 기본값을 env에 복사한다.

| 파라미터 | env | 기본값 | 쓰는 곳 |
|---|---|---|---|
| Aggregate | 0x242c | 1 | `390989` 가드 |
| AggFill | 0x2428 | −1. `390989` L168–175가 model+0xf0==NULL이면 10, 아니면 20으로 바꾼다 | fill 한도 F |
| GURO_PAR_AGGMULTLIMIT | 0x26c0 | 1e14 | 배율 한도 L |
| GURO_PAR_ZERO | 0x2498 | 1e-13 | 새 항목·소거 기준 Z |
| GURO_PAR_PREPAIRAGG | 0x2594 | 3 (범위 0–3) | 단계 C |
| GURO_PAR_PREQSUBST | 0x2584 | −1 | QC일 때만(`429382`) |
| NumericFocus | 0x2718 | 0 | 상대 피벗 비율 ρ |

## 1. 데이터 흐름: `519a52`

`519a52`는 CSR 상태를 MIP용 연결 리스트 행렬로 바꾼다. 그 위에서 `37f484`를 최대 5번 돌리고, 다시 CSR로 되돌린다.

```
519a52(state, env):                                           // 00480b60 L64–741
  CSR → 연결 리스트                                             L79–296
  53c507(tr, st): 현재 레벨 a-목록의 행·열 플래그 |= 0x20       L300
  ratio = 0.01 (Presolve<2 && state+8==4이면 0.1)               L301–303
  it = 0; base = rows_removed(+0x404)
  do {
    3ba5ac(env, st, 0, 0, −1)      // 진행 로그와 콜백뿐, 상태 불변   L306
    r = 37f484(st, env); r≠0이면 그대로 반환                      L310
    st+0xe0 = 2                                                 L314 (asm 0x481333)
    0x20 행과 0x20 열의 행을 모아 370047로 activity 재계산        L315–393
  } while ((double)m·ratio ≤ (double)(+0x404 − base)
           && (++it, flagged > 0) && (base = +0x404, it < 5))    L395–397
  +0x27c≠0 && PREQSUBST≠0이면 429382   (LP는 해당 없음)           L398
  연결 리스트 → CSR, st+0xe0 = 1                                 L405–694
```

- 첫 `37f484`는 `+0xe0`=1로 불린다. 2번째부터는 2다. 이 값이 후보 열 목록을 바꾼다(§3.2).
- `m` = `+0x10`(제거된 행 포함 전체 행 수)이다.
- `flagged` = 0x20 행 수 + 0x20 열 수다(아래 수집 단계).
- **`519a52` 자신의 작업량 항목은 μ를 곱하지 않는다.** 함수에 `+0x448` 참조가 없다(asm 확인). 호출하는 헬퍼(`53c507`, `370047`, `37f484`)는 μ를 곱한다.

### 1.1 노드와 리스트

노드는 32바이트다.

| 오프셋 | 내용 |
|---|---|
| +0x00 | double 값 |
| +0x08 | int 행 |
| +0x0c | int 열. −1이면 죽은 노드 |
| +0x10 | 행 안의 다음 노드 |
| +0x18 | 열 안의 다음 노드. free·pending 목록의 링크로도 쓴다 |

상태 필드:

| 필드 | 내용 |
|---|---|
| +0x160 / +0x158 | 노드 arena / 용량(노드 수) |
| +0x178 / +0x180 | 행 머리 / 열 머리 |
| +0x1a0 / +0x198 | free 목록 머리 / 개수 |
| +0x190 / +0x188 | pending 목록(열에서 빠졌지만 아직 행 리스트에 남을 수 있는 노드) 머리 / 개수 |
| +0x1b8 | `3b85ea`가 더 잡은 노드 청크 체인. `3b8c59`가 해제한다 |
| +0xd8 | nnz 카운터(아래 규칙대로만 바뀐다) |

노드 주소는 결과에 드러나지 않는다. 드러나는 것은 리스트 순서와 개수(+0x198, +0x188, +0xd8)다. 포트는 인덱스 arena로 충분하다. 다만 아래 개수 규칙은 그대로 따라야 한다.

### 1.2 CSR → 리스트 (L79–296)

1. `cnt_i = max(row_cnt[i], 0)`. 행 i의 노드 구간 시작은 앞선 행들의 cnt_i 합이다. used = Σ cnt_i.
2. W += 3·m.
3. `+0x1b8≠0`이거나 `+0x158 < used + +0x198`이면 `3b8c59` 뒤 arena를 (used + +0x198)개로 다시 잡는다. pass 0 첫 호출에서는 `+0x1b8`=0이다. `+0x158` = spare + 원래 nnz(`3a484d` L1115–1117, spare는 m1_presolve 부록 A 4번 식)이므로 다시 잡지 않는다.
4. 열 j = 0..n−1을 차례로 돈다. `col_cnt[j] ≥ 0`이면 CSR 슬롯 [beg, beg+`+0x48`[j])을 순서대로 본다. `ind ≥ 0`이고 `row_cnt[ind] ≥ 0`인 항목마다 행 구간의 다음 자리에 노드 {val, row, col=j}를 만들고, 열 리스트 끝에 붙인다. 이런 열마다 W += 7·`+0x48`[j](슬롯 수, 지운 슬롯 포함). 열 리스트 끝은 NULL이다. 죽은 열은 머리가 NULL이다.
5. W += 4·n.
6. 행마다 구간 안의 노드를 순서대로 +0x10으로 잇는다. 비지 않은 행마다 W += 4·(cnt_i − 1). 빈 행은 머리가 NULL이다. 끝에 W += 6·m.
7. 남은 노드는 free 목록이 된다. `+0x198` = `+0x158` − used, `+0x1a0` = 구간 끝 다음 노드다. free 노드는 col=−1이고 +0x18로 이어진다.
8. `+0x190` = `+0x188` = 0.
9. `+0xd8`은 건드리지 않는다. 그래서 `+0xd8`은 실제 노드 수가 아니라 이동 규칙(§2.3)으로만 움직이는 카운터다.

결과적으로 **행 리스트는 열 번호 오름차순이고, 열 리스트는 CSR 순서에서 살아 있는 항목만 남긴 것**이다. 죽은 행·열과 lazy 삭제된 항목은 여기서 사라진다.

### 1.3 반복마다 activity 재계산 (L315–393)

```
(br, Lr) = 53844d(tr)   // 현재 레벨 행 목록과 b 길이(+0x34+4L)
(bc, Lc) = 5384ca(tr)   // 열 목록과 b 길이(+0x64+4L)
list = +0x3b8, mark = +0x3a8
for i in Lr[..br]:  flag_r[i] & 0x20이면 flagged++, push i, mark
W += 4·br
for j in Lc[..bc]:  flag_c[j] & 0x20이면 flagged++,
    t = 0; 열 j의 노드(+0x18) 중 col≥0인 것마다 t++, 그 행이 표시 전이면 push·표시
    W += 4·t
W += 2·bc
370047(st, env, len, list); 표시 해제
```

- 0x20 비트는 여기서 지우지 않는다. 다음 `37f484`의 `53c9ee`가 지운다(§3.2).
- **`370047`은 CSR용 `4f79a1`과 다르다.** 행마다(`row_cnt ≥ 0`) `36fcb5`가 행 리스트 순서로 0에서부터 더한다.
  - a≤0이면 max에 lb·a(lb>−INF일 때, 아니면 inf_max++), min에 a·ub(ub<INF일 때, 아니면 inf_min++)를 더한다.
  - a>0이면 max에 ub·a, min에 a·lb를 더한다.
  - max는 gup, min은 gdn으로 더한다.
  - 행마다 W += 7·(방문 노드, 죽은 노드 포함)·μ.
  - 그다음 `+0x90 = gup(M, −rhs)`, `+0x98 = gdn(N, −rhs)`.
  - 끝으로 0 < `+0x98` < |rhs|·1e-13이면 `+0x98`=0, `+0x90` < 0이고 −`+0x90` < |rhs|·1e-13이면 `+0x90`=0.
  - 끝에 W += 8·len·μ.
  - `4f79a1`은 −rhs에서 시작해 CSR 순서로 더한다. 그래서 같은 행이어도 비트가 다를 수 있다.

### 1.4 리스트 → CSR (L405–694)

1. total = Σ_{col_cnt>0} col_cnt. W += 2·n.
2. `+0xd0` < total이면 CSR 배열을 다시 잡는다. 어느 경우든 `+0xd0` = total이다. 포트에는 해당 없다.
3. 행 i = 0..m−1: `row_beg[i]` = pos. 행 리스트를 순서대로 돌며 col≥0인 노드만 (col, val)로 쓴다. `+0x28[i]` = 쓴 개수. 행마다 W += 3·개수. 끝에 W += 4·m.
4. 열 j도 같다. 열 리스트 순서대로 (row, val)를 쓰고 `+0x48[j]` = 개수, W += 3·개수, 끝에 W += 4·n.
5. `+0xe0` = 1.

결과 CSR에는 틈도 지운 항목도 없다. 슬롯 수는 살아 있는 개수와 같다. 그 뒤의 CSR reduction(`5b488d`, `47c445`, `50de61`, 3b0917의 열 순서)은 이 순서를 그대로 읽는다. 그래서 **리스트 순서를 비트 단위로 재현해야 한다.** `row_cnt`/`col_cnt`(+0x60/+0x68)는 다시 세지 않고 `37f484`가 유지한 값을 쓴다.

### 2.1 구조

반환값(`local_140`):

- 0x2711(메모리).

### 2.2 설정 (L152–216, L463–464, L2535–2547)

- `ρ`(`local_1b8`) = NumericFocus==1이면 0.5, NumericFocus<2이면 0.01, 아니면 0.9. 기본은 0.01이다.
- `ρ2` = ρ·0.01. 곱셈 결과를 그대로 쓴다(0.01·0.01 ≠ 1e-4 비트).
- `pmin`(`local_1c8`) = 1e-6. 고정값이다.
- `tolA`(`local_1b0`, 피벗 최소 |a|) = 1e-6.
- `tolI`(`local_40`, `378c30`에 넘기는 최소 |a|) = FeasibilityTol(1e-6).
- prescan 패턴을 찾았거나 `+0x488` > 0이면 tolA = tolI = 1e-8(`0x3e45798ee2308c3a`)이다.
- 추적기 목록: 행 `(Rcnt, R)` = `538353`(a 길이, +0x28+4L), 열 `(Ccnt, C)` = `5383d0`(a 길이, +0x58+4L).
  - pass 0에서는 레벨 1 목록이 한 번도 압축되지 않는다. 그래서 a = m, n이고 목록은 0..m−1, 0..n−1 항등이다(`tracker.rs` 규칙).
  - `519a52` 안에서는 reset이 없으므로 5번 모두 같다.

### 2.3 노드 연산 (모든 단계 공통)

- **새 노드**는 `+0x1a0`의 머리에서 꺼낸다(+0x18 링크). `+0x198`−−, `+0xd8`++. 새 노드는 **행 리스트와 열 리스트의 맨 앞에 붙인다**. `row_cnt[i]`++, `col_cnt[k]`++.
  - 예외: 단계 A(`3791fd`)는 행마다 첫 fill에 열 j의 노드를 재사용한다(§4.4).
- **새 항목 조건**: 그 자리에 노드가 없고 |δ| ≥ Z일 때만 만든다. |δ| < Z인 항은 버린다.
- **기존 항목 갱신**:
  1. new = old + δ.
  2. 노드에 new를 쓴다.
  3. tol = max(1.0, 10·|δ|)·Z (`maxsd`).
  4. |new| ≤ tol이면 노드를 죽인다(col=−1). `row_cnt[i]`−−, `col_cnt[k]`−−.
  - 이 연산이 소거와 작은 값 제거를 겸한다. 다른 작은 값 제거는 없다.
- **열 압축**(`36f5c4`와 같은 꼴, 37f484·3791fd 안의 인라인 포함): 열 리스트에서 죽은 노드를 빼서 pending(`+0x190` 머리, +0x18 링크)에 넣는다. 노드마다 `+0x188`++, `+0xd8`−−. W += 2·(방문 노드)·μ.
- **행 압축**(인라인): 죽은 노드를 행 리스트에서 떼기만 한다. 개수 변화는 없다. W += 2·(방문)·μ.
- **`36f8e0(st, j)`**: 열 j의 모든 노드에 대해 다음을 한다. W += 3·len·μ. 열 머리는 호출자가 NULL로 둔다.
  - 살아 있으면 `row_cnt[row]`−−.
  - col=−1로 두고 pending에 넣는다. `+0x188`++, `+0xd8`−−.
- **행 지우기**(각 단계 끝): 행 r의 모든 노드 col=−1, `rowhead[r]`=NULL, `row_cnt[r]`=−3. 그 노드들은 열 리스트에 남는다. `col_cnt`는 이미 줄여 두었다.
- **GC `53d3d9(tr, st)`** (136줄):
  1. pending 목록을 free 목록 앞에 잇는다. W += (pending 길이−1)·μ. `+0x198` += `+0x188`, pending을 비운다.
  2. 추적기 열 b-목록(+0x70+8L, 길이 +0x64+4L)에서 플래그 0x10인 열마다 비트를 끈다. 열 리스트를 압축하는데, 죽은 노드는 바로 free로 보낸다(`+0x198`++, `+0xd8`−−). 열마다 W += 2·방문·μ. 끝에 W += 3·b·μ.
  3. 행 b-목록(+0x40+8L, 길이 +0x34+4L)에서 0x10인 행마다 비트를 끈다. 행 리스트를 압축하는데, 살아 있는 노드를 `row_cnt`개 이은 뒤 끊는다. 행마다 W += 2·방문·μ. 끝에 W += 3·b·μ.
- **GC가 불리는 곳**:
  - 단계 A, B, C에서 free가 모자랄 때(각 단계의 식).
  - `37f484` 끝에서 `+0x408` 또는 `+0x404`가 호출 시작보다 늘었을 때(L2492–2496).
  - `3791fd`에서 free가 0이면 대신 `3b85ea(env, st, max(m, 3000))`이 노드를 더 잡는다. `+0x198` += N이고 작업량은 없다.
- **`+0xd8`의 규칙**:
  - 새 노드면 +1.
  - 노드가 열 리스트에서 빠질 때(pending이나 free로 갈 때) −1.
  - `519a52` 생성과 재구성은 건드리지 않는다.
  - 그래서 GC 시점과 어느 열이 압축됐는지가 `+0xd8`에 남는다. `+0xd8`은 나중에 `3c5595` 진척도, `50495e` 밀도 판정, `3ff744` 작업량에 쓰인다. 포트는 free·pending 개수까지 시뮬레이션해야 한다.

### 2.4 추적기 표시와 플래그 비트

추적기 플래그 바이트(행 +0x18, 열 +0x20)에 두 비트를 새로 쓴다.
- **0x10**: 리스트에 죽은 노드가 있을 수 있음. `53dc48`(행)/`53dc6e`(열)가 검사하고 `53d3d9`가 끈다.
- **0x20**: 집계에서 바뀜. `53dc94`(행)/`53dcba`(열)가 검사한다. `53c507`이 켜고 `53c72d`/`53c9ee`가 끈다.

표시 함수(레벨 1·2 큐에 넣는 방식은 `tracker.rs`의 `mark`와 같다. 끝에 flag |= 0x30):

| 함수 | 크기 | 역할 | 작업량 |
|---|---|---|---|
| `53d18c(tr, st, r)` | 319 B | 행 r 리스트의 살아 있는 열마다 표시 | 4·방문·μ |
| `53d2b0(tr, st, j)` | 314 B | 열 j 리스트의 살아 있는 노드의 행마다 표시 | 5·방문·μ |
| `53d139(tr, j)` | 148 B | 열 j 하나 표시 | 없음 |

`53c507` / `53c72d`(각 310 B)는 a-목록의 행·열 전부에 0x20을 켜고 끈다. W += 2·(행 a)·μ + 2·(열 a)·μ.

### 2.5 행 캐시 (단계 A·B)

- `37f484`는 m 크기의 행 캐시를 잡는다(L466–510).
  - `local_1e0`(calloc): 행의 max mult_hi. 0이면 무효다.
  - `local_1d8`: min mult_lo.
  - `local_1e8`: max|a|.
  - `local_180`: min|a|.
  - `local_178`(calloc): 단계 A의 행 max|a|.
  - LP에서 `local_170`(정수용)과 `local_168`(QC용)은 NULL이다.
- 행 내용이 바뀌면 그 행의 `local_1e0`(와 있으면 `local_170`)을 0으로 무효화한다.
- `3791fd`는 `local_178`도 0으로 둔다(§4.4 3단계).

## 3. 준비 단계

### 3.1 prescan (L224–461; `+0xfc`==0 && `+0x488`==0, 즉 presolve에서 첫 호출만)

R 순서로 행을 본다(1000행마다 `a83b2f`). `row_cnt`==2이고 '='인 행 r에서 시작한다.
1. 처음 두 live 항 (c1,a1), (c2,a2)를 찾는다. W += 3·(두 번째 live 항까지 진행한 칸 수)·μ.
2. 한 계수는 |a|<1e-6(열 t), 다른 계수는 ||a|−1|≤1e-10이어야 한다.
3. col_cnt[t]==3. t의 열 리스트에서 r이 아닌 live 행을 차례로 본다. 각 행이 row_cnt==2이고 '<'가 아니면 중단한다. 앞의 둘을 r1, r2로 잡는다. W += 5·방문·μ.
4. r1에서 t가 아닌 첫 live 항이 ||a|−1|≤1e-10이면 그 열을 x로 둔다. r2의 첫 비-t live 항도 같은 x이고 ±1이어야 한다. 각각 W += 3·방문·μ.
5. col_cnt[x]==3, lb[x] ≤ −INF, ub[x] ≥ INF.
6. x의 열 리스트에서 `row_cnt`>2인 첫 live 행 r3를 찾는다. 그 계수가 ±1이고, r3의 live 항 중 |a|>1e4인 개수가 row_cnt[r3]−1이면 찾은 것이다. W += 3·방문·μ.

결과:
- 찾으면 그 행에서 멈춘다. `local_190`=1, W += 5·(행 인덱스)·μ. tolA = tolI = 1e-8이다.
- 끝까지 없으면 W += 5·Rcnt·μ, `+0x488` = −1. 그 뒤로는 prescan을 다시 하지 않는다.
- Netlib에서는 1e-13 < |a| < 1e-6 계수가 드물어 거의 안 걸릴 것이다(미확인).

### 3.2 후보 열 목록과 분류 (L512–750)

Cnt = n이고 `+0xe0` ≤ 1이면 **전체 경로**다. pass 0의 첫 호출이 여기에 해당한다.
1. lb/ub를 `+0x398`/`+0x3a0`에 복사한다(`local_lb`, `local_ub`).
2. `+0x3b8`에 0..m−1을 쓰고 W += m·μ.
3. `3707ac(st, env, list, m, +0x398, +0x3a0, 1, &cnt)`를 부른다(§6.3).
4. cnt>0이고 NumericFocus==0이면 한 번 더 부른다. 0이 아닌 반환은 바로 끝낸다.
5. `+0x3b8`에 열 0..n−1을 쓰고 W += n·μ.
6. 열마다 분류한다(`col_cnt>0`이고 `col_flag==0`인 열만). 결과는 `+0x168`에 둔다.
   ```
   need = (lb>−INF && local_lb[j] ≤ lb+0.01) || (ub<INF && ub−0.01 ≤ local_ub[j])
   cls  = need ? (lb>−INF ? (ub<INF ? 0 : 2) : 1) : 3
   ```
   - 0: 양쪽 bound가 필요(검사 필요).
   - 1: lb=−∞, ub 유한.
   - 2: lb 유한, ub=+∞.
   - 3: 암시적 자유.
   - W += 7·n·μ.
7. `53c72d`.

`+0xe0`==2(`519a52`의 2–5번째 호출)이면 **`53c9ee(tr, st, &Cnt, +0x3b8)`** 경로다(768 B).
1. 열 a-목록에서 0x20인 열을 순서대로 넣는다. 0x20을 끄고 `+0x3a8`에 표시한다.
2. 행 a-목록에서 0x20인 행마다 행 리스트의 살아 있는 열 중 표시되지 않은 것을 넣는다. 0x20을 끈다. 행마다 W += 3·방문·μ.
3. 표시를 지우면서 `col_cnt ≥ 0`인 열만 남긴다.
4. 작업량: 열 목록 길이 W += 3·μ, 행 a 길이 W += 3·μ, 결과 길이 W += 3·μ.
5. 분류는 유한성만 본다: lb>−INF면 (ub<INF ? 0 : 2), 아니면 (ub<INF ? 1 : 3). W += 6·Cnt·μ.

(`+0xe0`==0의 `53af0f` 경로는 LP 집계에서 쓰이지 않는다.)

## 4. 단계 A: 등식 행으로 자유 열 대입

### 4.1 후보 정렬 (L757–940)

`+0x1c8`(m+2개, 0으로 시작), `+0x1d0`(열별 추정치), `+0x1c0`(정렬 결과)을 쓴다.

후보 목록 순서로 열 j마다:
1. `+0x1d0[j]`=−1.
2. `col_cnt[j]`=c>0, flag==0, mult_lo[j] ≥ 1/L, mult_hi[j] ≤ L이어야 한다.
3. lim = n+1. c>2이면 `lim = (int)min((F+2.0)/(c−2) + 3.0001, n+1)`.
4. best = lim. 열 리스트(+0x18)를 순서대로 본다. 살아 있고 |a| ≥ tolA인 노드만 본다.
   - '=' 행이고 row_cnt[r] < best일 때:
     - row_cnt==1이면 **즉시 포기**한다(best=lim으로 되돌림).
     - 아니면 `377cb6(st, env, node, 0, …)`이 1이면 best = row_cnt[r].
5. W += 7·c·μ.
6. best≠lim이고 (c−2)·(best−2) ≤ F+2이면(double 비교):
   - `est = c<2 ? 0 : (c−2)·(best−1)+1`(int 계산 후 double).
   - est ≤ m이면 `+0x1d0[j]=est`, 버킷[est+1]++.

후보가 끝나면 W += 6·Cnt·μ.

`local_188`을 n개 잡는다. 버킷 1..m+1에 누적합을 만들고 W += (m+1)·μ. 다시 후보 순서로 est≥0인 열을 `+0x1c0[버킷[est]++]`에 넣고, `local_188[j]` = 그때의 col_cnt를 기록한다. W += 5·Cnt·μ.

결과는 **est 오름차순의 안정 계수 정렬**이고, 길이는 T = 버킷[m]이다.

### 4.2 열마다 피벗 고르기 (L943–1140)

정렬 순서로 열 j마다(1000개마다 `a83b2f`):
1. c = col_cnt[j] > 0, flag==0, c − local_188[j] < 2·local_188[j] + 10000이어야 한다.
2. 분류 검사(§6.2): cls 0은 `378c30__0` && `__1`, cls 1은 `__0`, cls 2는 `__1`, cls 3은 통과.
3. lim = n+1. c>2이면 `lim = (int)((F+2.0)/(c−2) + 3.0001)`(n+1과 min을 하지 않는다).
4. 열 리스트를 본다.
   - colmax = 모든 live |a|의 최대.
   - |a| ≥ tolA, '=', row_cnt ≤ lim인 항목을 (key=row_cnt, node)로 모은다(K개).
   - 그중 row_cnt==1이 있으면 포기한다.
   - W += (6·방문 + 2·K)·μ. 포기할 때는 6·(그 노드 앞 방문 수)다.
5. K≥2면 `aa15c2(K, keys, nodes)`로 정렬한다. 동률 순서는 알고리즘이 정한다(§6.4).
6. 고르기. ratio_best = 0, cnt_best = lim.
   ```
   for (cnt, node) in 정렬순:
     if cnt > cnt_best: break
     rmax = local_178[r] (0이면 행 리스트 live |a| 최대를 구해 저장, W += 3·방문·μ)
     if (cnt ≠ cnt_best || rmax/|a| < ratio_best)
        && ((|a| ≥ ρ·colmax) || (|a| ≥ ρ·rmax) || (|a| ≥ rmax·ρ2 && cnt < 3)):
        if 377cb6(st, env, node, 0, …):  ratio_best = rmax/|a|, pivot = node, cnt_best = cnt
   W += 4·(끝까지 본 항목 수)·μ
   ```
   - 처음에는 ratio_best=0이므로, cnt == lim인 행은 먼저 뽑힌 피벗이 없으면 받지 않는다.
   - 식 순서: `ρ·colmax`는 colmax에 ρ를 미리 곱한 값과 비교하고, `rmax·ρ2`는 rmax에 ρ2를 곱한다.
7. 피벗이 있으면 need = col_cnt[j] + cnt_best + F다.
   - free(`+0x198`) ≤ need이면 GC를 하고(L1144), 그래도 need < free가 아니면 건너뛴다.
8. 대입 준비(L1155–1172):
   - pivot.col = −1.
   - 행 r 압축(W += 2·방문·μ).
   - `36f5c4(st, j)`: 열 j 압축. 피벗 노드는 pending으로 가고 `+0xd8`−−.
9. `3791fd(a, env, st, local_170, local_1e0, local_178, local_148, local_150, local_158, r, j)`(L1251). xmm0 = 부호 있는 피벗 a(asm 0x383962 확인).
10. 그 뒤 행 r의 모든 노드 col=−1, W += 2·방문·μ, `rowhead[r]`=NULL(L1255–1268).

단계 끝에 W += 10·T·μ(L1293).

### 4.3 수식

열 j가 '=' 행 r(계수 a)에서 `x_j = c0 + Σ_k (−a_rk/a)·x_k`, c0 = rhs_r/a로 바뀐다. j의 bound는 버린다. 분류 검사가 bound가 암시된다고 보장한다. **남는 열의 bound는 바꾸지 않는다.**

### 4.4 `3791fd` (9,483 B, `0037fa10`) 순서

인자 p7/p8/p9 = `local_148`(int[m]), `local_150`(double[m]), `local_158`(노드 포인터[m])는 열 j의 저장 공간이다. scatter 배열은 `+0x1b0`이다.

1. **레코드**: `39b9e0(c0=rhs_r/a, a, env, st, 0, j, r, rowhead[r], row_cnt[r]−1)` → type 2(§7.1). r의 다른 열만 들어간다. `+0x408`++, `+0x404`++.
2. **시간 확인**: `+0x408 % 10000 == 0`이면 `3ba5ac`.
3. **행 r 캐시 무효화**: `local_170/1e0/178[r]` = 0.
4. **목적 상수**: `objcon = obj[j]·(rhs_r/a) + objcon`. 몫은 1단계와 같은 값이다.
5. **행 r 루프**(+0x10 순서, 모두 live, j 없음). 각 (k, a_rk)마다 `col_cnt[k]`−−, `obj[k] = obj[k] − (obj[j]·a_rk)/a`, `S_row += col_cnt[k]`(줄인 뒤 값). W += 4·len·μ.
6. **표시**: `53d18c(r)`, `53d2b0(j)`. 열 j의 행 r 노드는 이미 pending이므로 r은 표시되지 않는다.
7. **열 j 루프**(+0x18 순서). 각 (i, a_ij)마다:
   - d = (rhs_r·a_ij)/a.
   - `S_col += row_cnt[i]`.
   - rhs_i −= d.
   - 행 i 캐시를 무효화한다.
   - x_j의 기여를 j의 lb/ub로 뺀다:
     - a_ij ≤ 0: lb>−INF면 max = gup(max, −(a·lb)), 아니면 inf_max−−. ub<INF면 m' = gdn(min, −(a·ub)), 아니면 inf_min−−.
     - a_ij > 0이면 max에 ub, min에 lb를 쓴다.
   - 그다음 `min = gdn(m', d)`, `max = gup(max, d)`. rhs가 d만큼 줄었으므로 둘 다 +d다.
   - W += 5·len·μ.
8. **제거**: `row_cnt[r]`=−3, `obj[j]`=0, `col_cnt[j]`=−3−r. 열 j를 U개 배열로 저장한다(p9=노드, p7=행, p8=값). W += 6·U·μ. `colhead[j]`=NULL.
9. **fill**: S_row ≤ S_col이면 B1, 아니면 B2(asm 0x380268).
   - **B1** — 행 r의 (k, a_rk)를 바깥 루프로 돈다.
     1. 열 k가 0x10이면(6단계 덕분에 늘 그렇다) 인라인 압축한다(pending으로). 비트는 끄지 않는다.
     2. 열 k 노드를 행 번호로 scatter한다(살아 있는지 검사 없음). W += 2·s·μ.
     3. t = 0..U−1마다 v = ((−p8[t])·a_rk)/a로 upd(p7[t], k, v, t)를 한다.
     4. W += 16·s·μ. s는 scatter 수다(asm 0x381392, U가 아니다).
     5. 열 k의 live scatter를 지운다. W += 2·len·μ.
     6. 끝에 W += 5·len_r·μ.
   - **B2** — 저장한 t(행 i, a_ij)를 바깥 루프로 돈다.
     1. 행 i를 인라인 압축한다(떼기만 함).
     2. 행 i 노드를 열 번호로 scatter한다. j 자신의 노드도 들어간다.
     3. 행 r의 k마다 v = ((−a_rk)·a_ij)/a로 upd를 한다.
     4. W += 16·len_r·μ. 행 i 정리, W += 2·len·μ.
     5. 끝에 W += 5·U·μ.
   - **upd(i, k, v, t)**. e = scatter 항목이다.
     - e가 없으면:
       - |v| < Z이면 버린다.
       - p9[t]≠NULL이면 그 노드(원래 (i,j))를 **재사용**한다. p9[t]=NULL로 두고(B2는 scatter[j]도 지운다), 행 i 안의 자리와 `row_cnt[i]`는 그대로다.
       - 아니면 free 노드를 쓴다. free가 0이면 `3b85ea(env, st, max(m,3000))`. 행 i 맨 앞에 붙이고 `row_cnt[i]`++.
       - 공통: col=k, val=v, 열 k 맨 앞에 붙이고 `col_cnt[k]`++. 그리고 v·bound(k)를 activity에 더한다.
         - v≤0이면 max에 lb·v, min에 ub·v.
         - v>0이면 max에 ub·v, min에 lb·v.
         - bound가 무한이면 inf++다.
     - e가 있으면:
       1. 옛 기여를 뺀다(7단계 규칙, 무한이면 inf−−).
       2. new = old+v.
       3. §2.3의 소거 규칙을 적용한다. 소거면 다시 더하지 않는다. 아니면 새 기여를 더한다.
       4. scatter를 지운다.
   - B1과 B2는 live 리스트 순서, 계수, activity가 같다. 다른 것은 작업량, 압축되는 리스트, `+0xd8`, `+0x188`이다.
     - 새 열 항목은 열 k 앞에 t 역순으로 붙는다.
     - 행 i의 첫 fill은 j의 자리를 쓰고, 이후 fill은 행 r 역순으로 행 앞에 붙는다.
10. **안 쓴 j 노드 해제**: t 순서로 p9[t]≠NULL이면 `row_cnt[row]`−−, col=−1, pending에 넣는다(`+0x188`++, `+0xd8`−−). W += 3·U·μ.
11. 0을 반환한다.

## 5. 단계 B: 부등식 행 → 슬랙 (L1288–1430, L2555–3890)

조건: DualReductions≠0 && PreCrush<2. 아니면 Cnt=0이 되고 W += 0이다.

### 5.1 열마다 고르기

같은 후보 목록(`+0x3b8`, Cnt) 순서로 j마다:
1. c = col_cnt[j] > 0, flag==0, 연속형, mult_lo[j] ≥ 1/L, mult_hi[j] ≤ L.
2. `lim = c<3 ? n : (uint)((F+1.0)/(c−2.0) + 1.0001)`. lim<2이면 건너뛴다.
3. 분류 검사: **cls 0은 LP에서 건너뛴다**(L1336–1344). cls 1은 `__0`, cls 2는 `__1`, cls 3은 통과.
4. 열 리스트를 본다.
   - colmax = live |a| 최대.
   - live 항목 중 `row_cnt==1`인 행이 하나라도 있으면(어떤 sense든) 포기한다.
   - '<' 행이고 |a| ≥ tolA, row_cnt ≤ lim인 것을 (row_cnt, node)로 모은다(K개). '=' 행은 무시한다.
   - W += (3·방문 + 4·K)·μ.
5. K≥2면 `aa15c2`로 정렬한다.
6. 고르기. best=0, cnt_best=n+1.
   ```
   for (cnt, node) in 정렬순:
     if cnt > cnt_best: break
     thr = (cnt < cnt_best) ? ρ·colmax : best
     if thr < |a| && 377cb6(st, env, node, 0, …):  best=|a|, pivot=node, cnt_best=cnt
   W += 3·(끝까지 본 항목 수)·μ
   ```
7. need = col_cnt[j] + cnt_best + F + 1. free ≤ need이면 GC를 하고(L2656), 그래도 need < free가 아니면 건너뛴다.

단계 끝에 W += 9·Cnt·μ(L1427).

### 5.2 대입 (L2662–3887)

수식: 열 j(자유)와 '<' 행 r(계수 a, s = sign(a), a<0이면 −1)에서 새 변수 x'_j ≥ 0을 j 자리에 둔다.

`x_j = rhs_r/a − Σ_k (a_rk/a) x_k − s·x'_j`

행 r은 사라지고 열 j는 슬랙으로 남는다.

순서:
1. r = pivot.row. `inf_min[r]`, `act_min[r]`을 기억한다(MIP 전용 ub에만 쓴다).

### 6.2 `378c30__0` / `__1` (323/302 B): bound가 암시되는가

인자는 `(xmm0=tolI, st, env, j, 0|1, W)`이다. tolI는 |a| 하한이다. bound 여유는 env FeasibilityTol(ft)이다. 열 j 리스트에서 live이고 |a| ≥ tolI인 노드만 보고, 처음 맞는 노드에서 멈춘다. W += (μ·8)·(멈출 때까지 방문 수).

- **`__0`(ub가 암시됨)**: base = (lb>−INF ? −lb : 0), f = (lb ≤ −INF).
  - a>0(아무 sense): inf_min[i]==f여야 하고, v = act_min[i]/(−a).
  - a<0: '='이고 inf_max[i]==f여야 하고, v = act_max[i]/(−a).
  - 맞음 = `base − v ≥ (−ub) − ft`.
- **`__1`(lb가 암시됨)**: base = (ub<INF ? ub : 0), f = (ub ≥ INF).
  - a<0(아무 sense): inf_min==f, v = act_min/a.
  - a≥0: '='이고 inf_max==f, v = act_max/a.
  - 맞음 = `base − v ≥ lb − ft`.
- 여기서 act_*는 그 시점의 상태 activity다. 단계 A·B의 인라인 갱신 결과를 읽는다.

### 6.3 `3707ac` (5,651 B): bound 사본 한 번 전파

단계 C·D는 activity를 갱신하지 않는다(계수·rhs 변경, C의 ub, D의 lb/ub 모두). 그 행들은 `53d18c`/`53d2b0`으로 0x20이 켜져 있으므로 `519a52`의 `370047`이 다시 계산한다. 단계 A·B는 activity를 인라인으로 갱신하고, 같은 호출의 뒤 후보에서 `378c30`이 그 값을 바로 읽는다. 그래서 인라인 갱신도 비트 단위로 맞춰야 한다.

## 9. postsolve 레코드

모두 `ac68d7(env, st+0x368, size)`로 arena에 잡고 `+0x370` 목록 머리에 넣는다. 공통으로 +0x00 int type, +0x08 데이터 포인터(=rec+0x18), +0x10 다음 레코드다. 크기 식은 u64 wrap으로 계산한다(cnt=0이면 (−1)&~7이 감긴다).

### 9.1 type 2 (`39b9e0` LP 분기, 1,182 B)

인자는 `(xmm0=c0, xmm1=a, env, st, mode, j, r, list, cnt)`다. cnt = 기록할 live 노드 수, P = (4·cnt−1)&~7, Lc = col_cnt[j]−1(push 시점)이다.

| 오프셋 | 내용 |
|---|---|
| +0x18 | int j |
| +0x1c | int r |
| +0x20 | double c0 |
| +0x28 | double a |
| +0x30 | double obj[j] (push 시점) |
| +0x38 | int cnt |
| +0x40 | int* ind = rec+0x68 |
| +0x48 | double* val = rec+0x70+P |
| +0x50 | int mode' = (mode==0 ? Lc : −mode) |
| +0x58 | Lc ≥ 1일 때 int* colrow = rec+0x70+P+8·cnt |
| +0x60 | Lc ≥ 1일 때 double* colval = colrow + ((4Lc−1)&~7) + 8 |

- 크기 = P + 8·cnt + 0x70. Lc ≥ 1이면 0x10 + 8·(((4Lc−1)>>3) + Lc − 1)을 더한다.
- 행 부분: list(+0x10)의 live 노드마다 ind=col, val = (−a_rk)/a를 쓴다. k≠j이면 t = |a_rk/a|로 `mult_lo[k] = min(mult_lo[k], mult_lo[j]·t)`, `mult_hi[k] = max(mult_hi[k], mult_hi[j]·t)`. W += 5·방문·μ.
- 열 부분(Lc>0): 열 j의 live 노드 중 행≠r인 것을 (row, 원래 a_ij)로 쓴다. W += 6·방문·μ.
- `+0x408`++, `+0x404`++.
- 포트의 `PostRec::Subst`와 필드가 같다. `4f4d0a`(`push_subst`)와 달리 배율 갱신이 있고, 작업량 계수가 다르며, 리스트를 걷는다.

| 단계 | c0 | a | cnt | j 항목 |
|---|---|---|---|---|
| A (`3791fd`) | rhs/a | a | row_cnt−1 | 없음 |
| B | rhs/a | a(부호 있음) | row_cnt | val=−s |
| D | b/a_e | a_e | 1 | 없음 |

### 9.2 type 11 (`3a0e1b`, 130 B), 크기 0x28

+0x18 int r, +0x1c int j, +0x20 double |a|. 단계 B에서만 만든다. 행 r의 쌍대 상태를 슬랙 열 j에서 되찾는 데 쓴다(`m1_postsolve.md` §2의 11).

### 9.3 type 6 (`39d3d9`, 238 B), 크기 0x50

| 오프셋 | 내용 |
|---|---|
| +0x18 | uint code (bit 1: lb_k 바뀜, bit 2: ub_k 바뀜, col_flag[k]&0x80이면 \|8) |
| +0x1c | int e |
| +0x20 | int k |
| +0x24 | int r |
| +0x28 | double b |
| +0x30 | double a_e |
| +0x38 | double a_k |
| +0x40 / +0x48 | flag 0x80일 때만 lb[k], ub[k]. LP에서는 쓰지 않는다 |

단계 D에서 code≠0일 때만 만들고, type 2보다 먼저 넣는다.

### 9.4 type 21 = 0x15 (`39d14c` LP 분기, 1,593 B)

Lt = (col_cnt[e1]−1) + (col_cnt[e2]−1)(push 시점, 행 r 포함 개수 기준), Q = (4·Lt−1)&~7이다. 크기 = Q + 8·Lt + 0x90이다.

| 오프셋 | 내용 |
|---|---|
| +0x18 | int r |
| +0x1c | int col_cnt[e1]−1 |
| +0x20 | int col_cnt[e2]−1 |
| +0x24 | int e1 |
| +0x28 | int e2 |
| +0x2c | int k1 |
| +0x30 | int k2 |
| +0x38 | double f1 |
| +0x40 | double f2 |
| +0x48 | double a_e1 |
| +0x50 | double a_e2 |
| +0x58 / +0x60 | obj[e1] / obj[e2] |
| +0x68 / +0x70 | ub[e1] / ub[e2] |
| +0x78 | int* ind = rec+0x88 |
| +0x80 | double* val = rec+0x90+Q |

- ind/val에는 e1의 live 노드 중 행≠r인 것, 그다음 e2의 것을 (row, a)로 쓴다. 각 열마다 W += 6·방문·μ(그 열의 col_cnt−1 > 0일 때만).
- 배율: `mult_lo[k1] = min(mult_lo[k1], mult_lo[e1]·f1)`, `mult_hi[k1] = max(mult_hi[k1], f1·mult_hi[e1])`. k2/e2/f2도 같다.
- `+0x408` += 2, `+0x404` += 1.
- postsolve(`35fd68`)는 아직 해독하지 않았다.

## 10. 작업량 요약

μ가 붙지 않는 것은 `519a52` 자신의 항목뿐이다(§1). 나머지는 위 각 절에 적었다. 순서가 비트에 영향을 주므로 포트는 각 절의 순서대로, 원본이 따로 더하는 항은 따로 더한다(`agg.rs`).

2026-11-06 오라클로 확인했다. PRELIMIT=k_agg 작업량이 Netlib 64/64에서 비트 일치하고, 11개 모델(afiro, sc50a, 25fv47, degen3, ganges, scfxm1, pilot4, fit1p, bnl1, sctap2, maros)은 호출 지점 trace(`37f484`, `3707ac`, `3791fd`, `39b9e0`, `53d3d9`, `370047` 등 진입·퇴장의 W)로 이벤트마다 같다. 확인하면서 바로잡은 점:
- "방문"은 죽은 노드를 포함한 리스트 칸 수다. 예외는 `519a52` §1.3의 열마다 4·t(살아 있는 노드만)다. 중간에 멈추는 걷기(prescan, `378c30`, `3773aa`, `395c97`의 p 쪽, `53d3d9` 행 압축, 단계 B·C 모으기, 단계 D의 e 찾기)는 멈춘 노드를 세지 않는다.
- `53c9ee` 마지막 항은 결과 길이가 아니라 **col_cnt≥0으로 거르기 전** 목록 길이다. 세 항 모두 k·(μ·3) 꼴이다.
- `395c97` 마지막 3·μ 항은 p 쪽이 실패해도 q 리스트 전체 길이다.
- 단계 A·B에서 row_cnt==1로 포기하면 K를 0으로 되돌린 뒤 (6·방문+2·K)·μ / (3·방문+4·K)·μ를 더한다.
- prescan의 t 열 걷기는 row_cnt≠2이거나 '='인 행에서 멈춘다(§3.1의 "'<'가 아니면"은 반대로 적었다). col_cnt[t]==3이라 멈추면 늘 r2가 없어 다음 행으로 간다. 항: 3·(둘째 live 위치), 5·(t 걷기), 3·(r1 건너뛴 칸), 3·(r2 건너뛴 칸), 3·(x 걷기), 3·(r3 전체), 끝에 5·Rcnt(찾으면 5·행 인덱스).
- `3707ac` L418–680의 계수 1 항은 열 플래그 0x80 경로라 LP에서 돌지 않는다. 행 끝 6·row_cnt는 D>1e13로 건너뛴 행에는 없다.
- `3773aa` L127의 3·k 항은 정수 열(`local_170`)에서만 돈다.
- 단계 C 끝 항은 2·(실패 표시한 열 수)·μ다.

곱셈 꼴(μ=1이면 비트에 영향 없음. Netlib은 모두 μ=1이라 μ≠1은 확인하지 못했다):
- (μ·c)·k: `36fcb5`(7), `370047`(8), `3773aa`(4), `378c30`(8), `53d18c`(4), `53d2b0`(5), `395c97`(3/4/3), `39d14c`(6), prescan(3/5).
- k·(μ·3): `53c9ee`.
- (k+k)·μ: 리스트 압축(`36f5c4`와 인라인), `53c507`/`53c72d`, `53d3d9` 압축, 3791fd scatter·정리, 단계 A·D 행 지우기, 단계 C 실패 표시.
- (k·c)·μ: 나머지(`3707ac`, `39b9e0`, `36f8e0`, `3791fd`의 4/5/6/16/3, 단계 A–D 본문).
- 단일 add 둘: 단계 A ((6·방문+K)+K)·μ, 단계 B (3·방문+4·K)·μ.

## 12. 포팅 순서 제안

1. 인덱스 arena 리스트와 §1.2/§1.4 변환을 만든다. 집계 없이 변환만 했을 때 CSR이 그대로 돌아오는지 본다. 결과 CSR에서 lazy 항목이 사라지는 효과는 있다.
2. free·pending·`+0xd8` 카운터와 GC를 만든다.
3. 단계 D(가장 단순) → C → A(`3791fd`) → B 순서로 만든다. PRELIMIT로는 `519a52` 전체만 볼 수 있으므로, 각 단계는 끈 채로 비교할 수 없다. 오라클은 `--param GURO_PAR_PREPAIRAGG=0`(단계 C 끔), `DualReductions=0`(B, C 끔)으로 일부를 가를 수 있다. DualReductions는 다른 reduction에도 영향을 준다.

## 13. 미확인

- 작업량은 §10대로 확인했다. 확인하지 못한 경로: 단계 C 병합(`39d14c`, trace한 11개 모델에서 한 번도 불리지 않았다), 단계 중간 GC(11개 모델 모두 GC는 `37f484` 끝 한 번뿐), `3b85ea` 노드 추가, prescan이 패턴을 찾는 경로(포트는 assert), μ≠1.
- `ac68d7` arena의 청크 크기와 첫 정렬(`m1_postsolve.md` §3과 같은 문제).
- type 6/21의 postsolve 의미(`365159` :472, `35fd68`).
- `519a52` 뒤에 남는 0x10/0x20 비트를 다른 LP reduction이 읽는지. `53dc94`/`53dcba`의 다른 호출자를 확인하지 않았다.
- `3791fd`의 B1/B2가 리스트 순서를 같게 만든다는 것은 코드 읽기에 근거한 추론이다. 실행으로 확인하지 않았다.
- 단계 D 특수 패턴(작은 계수 열 집계)의 세부 작업량. 기본 경로에서는 prescan이 패턴을 찾을 때만 돈다.
- `3a484d`의 spare 식에서 `uVar63`의 정체(부록 A 4번은 max(m,n)으로 적었다). LP에서 `uVar84`(추가 max 항)가 0인지도 확인하지 않았다.
- `390989` 가드의 `local_38`(축소 모드)이 일반 LP에서 0인지(state+8≠4이면 0으로 보임).
