# 교훈 기록

작업 단위마다 남기는 **교훈** 모음이다. 교훈은 다음 작업이 다시 발견하지 않아도 되는 지식을 말한다. 작업 기록(`docs/m*/`)은 한 작업의 계약과 결과이고, 교훈은 여러 작업에 걸쳐 재사용할 사실만 짧게 추린 것이다. 근거와 수치는 작업 기록에 두고 여기서는 링크만 건다.

## 언제 읽나

원본 함수·구조체 오프셋·Frida 훅·Herdr·검사기를 다루기 전에 해당 파일을 읽거나 함수 이름(`5ce67b` 등)으로 grep한다.

## 언제 쓰나

작업 단위를 마치기 전, 인수인계를 갱신할 때 함께 쓴다. 작업 중에 시간을 쓴 막힘이나 실패한 접근이 있었다면 바로 적어도 된다. 해당 없는 범주는 건너뛴다.

## 파일

| 파일 | 담는 것 |

| [tooling.md](tooling.md) | Frida·Herdr·Gurobi 실행·검사기·git worktree의 함정, **실패한 접근**과 그 대안 |
| [process.md](process.md) | 계약·점유·병합·검토 절차에서 얻은 교훈 |

## 항목 형식

```
- **한 줄 사실 또는 규칙.** 왜·어떻게 재사용하는지 1–2문장. (작업번호, [근거](../m2/작업기록.md#절))
```

- 주제별 `##` 아래에 넣는다. 같은 주제가 이미 있으면 새 항목을 덧붙이지 말고 기존 항목을 고친다.
- 근거 수준을 표시한다. 원본 실행으로 확인한 것은 "캡처", 디컴파일만 읽은 것은 "C", 추정은 "추정"으로 적는다.
- 틀린 것으로 드러난 항목은 지우거나 바로잡고, 바로잡은 작업번호를 함께 남긴다.
