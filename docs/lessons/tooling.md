# 도구·환경 교훈과 실패한 접근

- **누적 순서 검증에는 역순의 합이 다른 비트가 되는 입력을 먼저 계산한다.** 2^54 뒤1 두 개는 정순과 역순이 모두2^54라 Rust 역순 변이가 생존했다. 작은 항을 세 개로 늘리면 역순은2^54+4가 되어 구분된다. A행의 `PInf+(v-w)` 재결합도 먼저 PInf=1을 만들고 v=2^54·w=2^54-4를 쓰면5 대4로 구분된다. 기존 실패는 보존하고 원본 명령10사례×3회로 보강해 Rust33변이를 모두 거부했다. 원본 캡처·Rust 변이. (M3-04c-18, [결과](../m3/primal_push_recompute_rust.md#6-실행-결과))

- **원본 명령 구간에 fake frame을 공급할 때는 memcpy 길이 슬롯과 스택 맨 앞의 실제 쓰기도 복원한다.** 재계산 +0x1f10=m*8 누락은 rhs와 basic 복사를 길이0으로 만들어 검사기가 basic 불일치로 거부했다. round는 PInf를 [rsp]에 쓰므로 [rsp]의 반환주소를 쓰는 ret stub 대신 cleanup으로 직접 jump하고 원래 스택을 복구했다. asm 보존에는 `dc.py --asm --max 10000`을 명시해 기본200줄 잘림을 피한다. 원본 asm·실패/수정 후 캡처. (M3-04c-17, [계약/결과](../m3/primal_push_recompute_oracle.md))

- **외부 backend 재생에서 예상 reply의 소비량과 실제 호출 인자를 trace로 비교하면 제어 오류를 출력 차이로 판별할 수 있다.** ret1 반복 누락이나 품질 호출 누락을 테스트 예외만으로 잡지 말고, 소비 횟수·별칭·호출 순서를 함께 출력한다. M3 factor 변이30종은 모두 cargo 재생 성공 뒤 첫 출력 차이로 거부했다. 저장 재생·변이. (M3-04c-16, [결과](../m3/primal_push_factor_rust.md#6-실행-결과))

- **원본 캡처에 없는 중간값(L·R 단계 결과)이 필요하면 Rust 상태 덤프를 기준 자료로 고정하고 원본과 현재 코드 양쪽에 묶는다.** 임시 계측은 패치 파일로 남기고 되돌린다. 검사기는 덤프 해시와 패치 해시를 고정하고, 덤프의 원본 대응 부분(U 원소·순서)을 원본 캡처와 비트 대조하며, 덤프에 Rust 규칙을 적용한 결과가 현재 빌드 스냅숏과 같은지 확인한다. (M1-02a-1, `tools/m1_tau_check.py` U·I·R)
- **부동소수 배열을 비트로 비교하면 +0/−0 차이가 첫 차이로 잡힌다.** 값 비교(`!=`)는 둘을 같다고 본다. 첫 분기 판정은 값 기준으로 정의하고 부호 있는 0 차이는 따로 출력한다. 비트 재현 규칙(G)은 비트 그대로 둔다. (M1-02a-1)

- **제자리 배열 변경을 매 호출 전체로 적으면 캡처가 회당 수십 MB가 된다.** `10f448` 첫 판은 nidda 1회 45MB(gz)였다. 진입 상태가 같은 객체의 직전 반환 내용과 같으면 그 사건 번호만 적고(포인터는 후보 찾기에만, 같음은 내용 전체 비교), 반환은 바뀐 열의 위치 치환과 다른 길이만 적어 12MB로 줄였다. 같은 입력의 gz 파일은 바이트 동일이라 git에는 한 번만 저장된다. (M2-03d-13) Rust 재생 입력도 같은 참조 압축을 쓰고 Rust가 자기 반환 상태를 이어 쓰면 입력이 작다(4,306회 중 전체 기록 479). 모든 반환을 비교하므로 첫 차이 위치는 그대로다. (M2-03d-14)
- **오라클이 변경분만 기록하면 후속 Rust 재생에 필요한 진입 값이 빠질 수 있다.** 03d-13은 rhs의 바뀐 행만 적어 03d-14는 진입 rhs를 합성하고 변경 행·+0만 대조했다. 오라클을 설계할 때 후속 재생 입력(진입 상태 전체 또는 그 해시)까지 남길지 계약에 적는다. (M2-03d-14)
- **참조를 바꾸는 변조는 대상의 내용이 원래 참조와 같으면 무변조가 된다.** `before_ref`를 build 1로 돌린 변조가 통과했다(같은 D에서 교환 없는 재생성이 이어져 내용이 같았다). 열 수가 다른 D의 build를 가리키게 바꿔 거부를 확인했다. 변조 대상은 내용이 달라지는지 먼저 본다. (M2-03d-13)
- **피벗 k의 원본 진입 상태(LU·τ)는 스냅숏 0..k가 같으면 같은 입력이고, 스냅숏 k+1은 피벗 k의 출력이다.** `RSOLVER_SNAP` 스냅숏 k+1의 `tau`·`urow`·`t`는 피벗 k의 갱신 전 값이다. "같은 경로" 조건을 스냅숏 k+1까지 걸거나 w 비교를 갈라지는 피벗의 출력 스냅숏까지 넓히면 경계가 하나 어긋난다(M1-02d 첫 실행에서 두 번 틀림). [M1-02d](../m1/m1_02d_tau.md).
- **저장 오라클 `vstat`는 재분해 뒤 기저 위치를 단계 순서로 다시 매긴 값이다.** 재분해 입력(원소 순서가 달린 상태)을 Rust로 다시 만들려면 스냅숏 k−1 `vstat`에 피벗 k−1 교환(위치 r ← q)을 적용한 직전 기저를 쓰고, Rust 단계 순서로 매긴 위치가 스냅숏 k `vstat`와 같은지 확인한다. 스냅숏 k를 그대로 인수분해하면 U 집합·값은 같아도 원소 순서가 달라 판별력이 없다. 임시 덤프는 `_core.row_costs(vstat)`(=`Lu::factor`)에 env 훅 패치로 붙이면 된다. [M1-02a-2](../m1/m1_02a2_urow.md).
- **출력 변조는 원본 기대값이 있는 필드에 넣는다.** M2-06b는 Rust가 매 스냅숏 배열을 쓰지만 원본 배열은 pop이 있는 선택에만 있다. 첫 변조가 배열 없는 스냅숏을 골라 거부되지 않았다. 변조 위치는 Rust 출력이 아니라 기대값 목록에서 고른다. (M2-06b)
- **clippy `double_comparisons`는 C의 `a < b || a == b`를 `a <= b`로 바꾸게 한다.** 부동소수에서도 NaN 포함 같은 결과라 그대로 따른다. 코드 변이 패턴(`MUTANTS`)의 원문도 함께 바꾼다. (M2-06b)

- **표·배열 상태를 추적하는 오라클은 생성 스냅숏 → 사건별 전후 → 해제 직전 전체 스냅숏으로 사슬을 닫는다.** 모든 사건의 "전" 값이 재생 상태와 같아야 하고 해제 스냅숏도 같아야 하므로, 훅하지 않은 쓰기가 있으면 반드시 드러난다. 이 검사가 38모델 sweep에서 4모델의 숨은 경로를 잡았다. (M2-06e)
- **규칙 변이의 기대는 "그 절이 실제로 결과를 바꾼 분기 수 > 0인 사례에서만 거부"로 검사기에 고정하면 NodeLimit이 달라도 유지된다.** 단순 실행 횟수로 세면 틀린다(대칭 동률은 같은 항목끼리의 동률이 대부분이라 S1이 생존). 효과 있는 경우만 세는 카운터를 둔다. 38모델 sweep 16변이에서 규칙과 실제 거부가 모두 같았다. (M2-06e, `tools/mip_pseudocost_check.py` `VARIANTS`)

- **재생 드라이버의 기대 스냅숏은 숫자 키로 정렬한 뒤 문자열로 만든다.** M2-06f 첫 실행은 `sorted('11:…', '8:…')` 문자열 정렬로 해제 스냅숏에서 실패했다(Rust는 j 순으로 출력). Rust 결함으로 오인하지 않게 첫 차이의 항목 번호를 먼저 본다. (M2-06f, [§6](../m2/mip_pseudocost_rust.md#6-실행-결과))
- **원본이 고른 입력만 캡처돼 있으면, 고르지 않은 쪽은 결과를 바꾸는 값(NaN 등)으로 채워 Rust의 선택 오류를 드러낸다.** M2-06f 감쇠는 `L+0x28`/`L+0x70` 중 원본이 읽은 벡터 값만 있어, 다른 쪽을 NaN으로 두면 잘못 고를 때 부호 제외가 사라져 결과가 달라진다. 두 벡터를 같은 캡처 값으로 채우면 선택이 틀려도 결과가 같아 드러나지 않는다. 선택을 반대로 한 변이 R1이 6사례 모두 거부됐다(캡처). (M2-06f)

- **β·w 첫 차이에서는 캡처 ρ를 Rust 합산 규칙으로 더해 보면 "벡터 차이"와 "합산 차이"가 한 번에 갈린다.** 원본 β가 나오면 ρ(BTRAN)를 의심한다. 그다음 Rust 덤프와 캡처 U로 Uᵀ·eta·Lᵀ 단계를 나눠 재생한다. 단 캡처에 원본 중간값이 없으면 "Rust = 내 원본 모형" 대조는 원본 근거가 아니다. 판정은 재생한 최종 ρ가 캡처와 비트로 같은지로 한다. (M1-02i, [§6](../m1/m1_02i_eta.md#6-실행-결과조사))

- **합산 순서 재생에 Python `sum()`을 쓰지 않는다.** Python 3.12부터 float `sum()`은 보정 합(Neumaier)이라 순차 `+`와 끝자리가 다르다. 재생기는 `for x in t: a += x`처럼 명시적으로 더한다. (M1-02l, 실행으로 확인)
- **원본 내적의 정렬 선처리처럼 주소에서 나오는 입력은 주소 대신 `ptr & 0xf`와 풀 기준 오프셋만 캡처하면 3회 바이트 동일로 고정된다.** (M1-02l)

- **Rust `RSOLVER_SNAP`은 재분해가 일어난 반복을 같은 `iter`로 두 번 쓴다(재분해 전 갱신 수, 뒤 0).** FTRAN 시점 상태와 비교하려면 반복마다 마지막 줄을 쓴다. 첫 줄로 비교하면 재분해 시점 차이를 잘못 찾는다. (M1-02j)
- **원본 상태와 Rust 상태가 이미 갈린 뒤의 "첫 차이 앞당겨짐"은 회귀 근거가 아니다.** boeing1은 기준선도 반복 300에서 xB·d·w가 달랐다. pathcmp 변화만 보지 말고 statecmp로 그 전 상태가 같은지 먼저 본다. (M1-02j)

- **상태 변이가 생존하면 그 상태가 관측 가능한지부터 본다.** M1-02m에서 U 열 꼬리 부분 안의 순서를 바꾼 변이는 살아남았다. 꼬리 부분 순서는 이후 맞바꿈 규칙에서도 접두 부분·출력·값에 닿지 않는다. 같은 연산에서 접두 쪽을 건드리는 변이로 바꿔 판별력을 보였다. (M1-02m)

- **원본 진입 상태와 Rust 입력이 모두 같은데 출력이 다르면, 그 함수 안 부수효과 순서를 C 줄 순서와 대조한다.** M1-02n은 Rust 갱신 입력(q·t·p·l·n′·LU+0xe8·빈 열·LU+0xf0)을 임시 덤프해 원본 `05b257` 진입 캡처와 순서대로 맞췄다. "입력 같음, 출력 다름"인 첫 갱신에서 판정이 읽는 상태(빈 열·LU+0xe8)를 앞 단계가 먼저 바꾸는지 보니 바로 원인이었다. 스냅숏은 FTRAN 시점만 담으므로 갱신 안 입력은 덤프로 본다. (M1-02n, [근거](../m1/m1_02n_update.md#6-실행-결과))
- **원본 저장 순서가 Rust 코드 순서와 다르면 양을 묶음별로 모아 끝에서 원본 순서로 내보낸다.** 상태 변경 코드를 원본 순서로 재배치하면 이미 맞춘 경로(pathcmp)가 흔들릴 수 있다. 판단에 늦게 정해지는 값이 필요한 저장(0xf1f37의 local_40)은 재료만 모아 두고 끝에서 판정한다. 이렇게 하면 조기 종료(원본이 앞쪽 저장 뒤 끝내는 경우)도 버퍼를 잘라 옮기기 쉽다. (M1-02r)
- **재분해 단위 덤프에 반복 표식을 달아야 정렬이 끊긴 뒤의 갱신 구간을 비교할 수 있다.** 마지막 정렬 재분해 뒤 갱신은 다음(어긋난) 재분해 줄에 섞인다. 저장마다 k를 넣고 원본 k < 다음 재분해 k로 자르면 degen2 피벗 0–355 전체를 비교할 수 있다. 원본 k(`8b473` 순번)와 Rust `iter`(pivot 시점)는 같다. (M1-02r)
- **work 지점을 옮기기 전에 watchpoint 캡처의 양 `(v − prev)/x148`을 지점·k별로 풀어 보면 입력 해석을 계약 전에 거를 수 있다.** 두 지점 양의 비(0xc0410/3 = 0xc06c7/7), (m+n)의 배수, 정수 역산(S·nInf·c0)으로 C 해석과 Rust 상태 대응을 미리 확인했다. 그래도 첫 실행에서 C 루프 카운터 위치(if/else 밖 증가)는 놓쳤다. 카운터가 증가하는 줄을 블록 단위로 확인한다. (M1-02s)
- **비간섭 검사(새 도구 사건을 뺀 투영 = 이전 자료)는 기존 사건을 건드린 변조를 먼저 잡아, 목표 검사(재생)의 판별력을 가린다.** 변조가 거부됐다는 것만 보지 말고 어느 검사가 거부했는지(오류 코드 접두)를 확인하고, 기존 사건을 바꾸는 변조는 재생 함수에 직접 넣는다. 목표 0회 입력은 비교 기준도 같이 변조해야 분기 범위 검사까지 닿는다. (M2-06e-2, [§6](../m2/mip_pseudocost_bc.md#6-실행-결과))
- **여러 함수가 같은 꼬리 코드를 가지면 Rust 변이 대상 문자열이 겹쳐 `count == 1` 검사에 걸린다.** 공유 helper로 뽑은 뒤 함수별 변이는 그 함수에만 있는 앞뒤 줄(작업 단위 식, 다음 함수 주석)까지 넣어 앵커를 잡고, 들여쓰기 변경 뒤에는 대상 수를 먼저 출력해 확인한다. 리팩터링은 이전 작업 도구의 `--mutate-rust` 대상도 깨뜨리므로 같은 판정 변이를 새 기록에서 옛 재생 비교와 함께 돌려 대신한다. (M3-04c-9)
- **trace 변조 자기 검사는 기준(원본 쪽)에 그 필드가 있는 단계를 고른다.** Rust trace에는 frame이 늘 있지만 04b-1 캡처에는 없어 비교기가 그 필드를 건너뛴다. 첫 단계를 고르면 변조가 비교 밖이 되어 '미검출'로 끝난다. 대상은 `'frame' in want`로 고른다. (M3-04c-10)

## Rust 비용 계측

- **work만 복원하는 작업에서 반환 목록을 얻으려고 수치 커널을 바꾸면 전체 경로가 달라질 수 있다.** M1-02v에서 bound flip의 dense L 풀이를 sparse L로 바꾸니 kb2·degen2 저장 비교는 통과했지만 maros·perold 반복 수가 달라졌다. 기존 수치 결과를 보존하고 반환 표현 판별용 L/R 목록 계산을 분리했다. 커널과 표현의 통합은 해당 커널 검증 작업에서 수행한다. (M1-02v, [실패와 수정](../m1/m1_02v_iteration_work.md#6-실행-결과))

- **이 기계(WSL2)에는 perf·valgrind가 없다. Rust 구간 비용은 `Instant` 누적을 넣은 임시 패치로 잰다.** 계측 없는 실행의 상태·노드·반복·경계 비트와 같은지 먼저 확인하고, 시간 종료 대신 NodeLimit로 같은 일을 시킨다. (M2-10a, [기록](../m2/mip_bnb_node_cost.md#6-실행-결과))
- **다른 영역 크레이트(`crates/lp`)를 고치지 않고 내부 단계를 나눠 재려면 래퍼 함수를 pub 조각으로 재생하고 매 호출 결과를 비트 비교로 `assert`한다.** `solve_model_run`은 `Spx::new`·`Engine::new`·`solve`/`solve_warm`·`Spx::unscaled`·`resolve_unscaled`로 재생돼 status·iter·obj·x가 비트까지 같았다. `Engine::new`는 `trace_on`이 기본 true이므로 꺼야 같은 일을 한다. (M2-10a)
- **`cargo test`의 작업 디렉터리는 크레이트 폴더다.** 하네스에 넘기는 모델 경로는 절대경로로 만든다. 상대경로면 첫 실행이 파일 없음으로 바로 실패한다. (M2-10a)

## git worktree

- **이 컴퓨터(coco0912)의 worktree에는 git 사용자 신원이 설정돼 있지 않아 `git commit`이 `Author identity unknown`으로 실패했다.** 전역 설정을 바꾸지 않고 기존 이력과 같은 신원을 `git -c user.name=… -c user.email=… commit`으로 커밋마다 넘겼다. (M3-04c-5)
- **`session.py claim … && claim shared && git worktree add …` 한 줄은 shared 점유 실패에서 멈춰 worktree가 생기지 않는다.** 그 뒤 Write 도구로 worktree 경로에 파일을 쓰면 git 저장소가 아닌 일반 디렉터리가 생긴다. 점유와 worktree 생성을 나눠 실행하고 `git -C <worktree> status`로 확인한다. (M2-03d-5)
- **ignore된 `target/`(재생성할 수 있는 탐색 출력)이 남아 있으면 `git worktree remove`에 `--force`가 필요하다.** 미커밋·미추적 파일이 그것뿐인지 먼저 확인한다. (M2-03c-2)

- **GRBgetdblattr는 PLT 주소 `0xbcc70` 대신 실제 export `0x7a3820`에 훅을 붙인다.** PLT 계측은 DONE 전 프로세스 종료를 일으켰고 export 훅으로 해결했다. 실패 캡처 `explore_pk1_final.json.gz`를 보존했다. (M2-06g-2, [§6](../m2/mip_sb_restore.md#6-실행-결과))
- **bound 복원 검사에 실제 분기 bound 적용도 연결한다.** solve 전후와 최종 bound만 비교하면 후보 bound를 전부 부모 값으로 바꾼 기록이 통과한다. restore의 열·방향과 solve 진입 bound를 연결해 선택 열이 엄격히 조여졌는지 검사한다. 독립 검토에서 재현·수정했다. (M2-06g-2, [§7](../m2/mip_sb_restore.md#7-판정과-인수인계))
