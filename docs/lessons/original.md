# 원본 사실

형식과 근거 표시는 [README](README.md)를 따른다. 주소는 `libgurobi130.so` file offset이며 디컴파일 파일 이름의 앞 숫자와 같다.

## MIP 노드의 basis 저장

- **노드 정보 `I = N+0x18`의 basis 필드.** `+0x94` 저장 시 행 수, `+0x98` vbasis(VBasis 코드 0/−1/−2/−3), `+0xa0` cbasis(0/−1, 보통 `+0x98` 같은 블록의 열 수 뒤), `+0xa8` dual norm(없으면 null), `+0xb0` 압축 basis. 캡처·C. (M2-03c-2, [§2](../m2/mip_retry_basis.md#2-원본과-상태-경계))
- **압축 basis 형식.** 열마다 2비트(0..3 → 0, −1, −2, −3), 이어서 저장 행마다 1비트(1 → −1)이다. 32비트 단어의 MSB부터 끊김 없이 채우며 단어 수는 `(행 + 2·열 + 31) >> 5`다. decode할 때 현재 행이 더 많으면 나머지 행은 0(basic)이 된다. 재구현은 `tools/mip_retry_basis_check.py`의 `decode`가 원본 출력과 같다. 캡처. (M2-03c-2)
- **basis 수명 주기.**
  1. LP 상태가 2이면 `5d4427`, 9이면 `5d3deb`이 `113d92`로 노드 `I+0x98/0xa0`에 저장한다. HasDualNorm이면 `I+0xa8`도 저장한다.
  2. `69d237(node)`이 압축해 `I+0xb0`에 쓰고 `I+0x98`를 해제한다.
  3. `69e299(child, ?, parent)`가 부모의 압축 basis를 복사한다. 부모가 풀린 배열을 갖고 있으면 그 배열을 복사한다.
  4. `5ce67b`는 진입하자마자 `I+0x98`를 해제하고(C:262–275), `69d7ea`로 `I+0xb0`를 푼다.
  
  캡처·C. (M2-03c-2)
- **부모가 null이고 깊이가 0인 비루트 노드는 `8e4682` 경로를 의심한다.** `8e4682`는 donor 노드와 같은 `M`에 `5ff358(0, M)`으로 부모 없는 노드를 만든다. 이어서 donor의 풀린 basis를 복사·압축한 뒤 `5ce67b`를 부른다. C(생성 자체는 캡처하지 않았다). (M2-03c-2)
- **일반 분기 자식도 부모 basis를 물려받는다.** 노드 생성 `5ff358`은 부모가 있으면 `69e299(child, 0, parent)`로 basis를 복사하고, 분기 `627f3e`가 이 함수를 부른다. C. (M2-03d-1, [§2](../m2/mip_retry_rust_boundary.md#2-원본과-상태-경계))

## LP basis 내보내기·적재

- **VBasis가 필요하면 원본 `113d92(lp, vb, cb)`의 출력을 쓴다.** CBasis는 `ws+0x168[n+i] < 0 ? −1 : 0`이다. VBasis는 `12f01a`→`113674`를 거치며, 열 플래그(`lp+0xe8 → +0x408`)·`ws+0x1d8` bit0·`lp+0x64`에 따라 달라진다. 그래서 `ws+0x168`에서 손으로 바꾼 값은 원본과 다를 수 있다. 자연 호출을 훅하거나, Frida 콜백 안에서 직접 부른 결과를 합성으로 표시해 쓴다. C·캡처. (M2-03c-2)
- **`spx+0x168` 형식.** 값이 0 이상이면 basic 행 위치이고, −1 하한, −2 상한, −3 free/superbasic, −4 고정이다. 단 `325b4`로 적재한 직후에는 VBasis 코드가 그대로 들어 있고, 위치는 분해할 때 매긴다. 캡처. (M2-03c-2, `../re/notes/13_simplex.md`)
- **`cda5b`는 basis 인자를 조건부로만 적재한다.** `2f7e1`을 부른 뒤 `ws+0xf0 == 1`이고 vbasis·cbasis가 둘 다 있을 때만 `325b4`로 적재한다(C:182–190). 인자가 없으면 `lp+0x238` warm basis 경로를 쓰며, 이 값은 `10acb2(lp, vb, cb)`가 쓴다. 캡처. (M2-03c-2)
- **`2f7e1`은 끝난 workspace의 `ws+0xf0`(상태)를 1로 되돌린다.** 상태 12인 workspace에서 다시 풀면 basis를 새로 적재하고 다시 분해한다. 캡처. (M2-03c-2)
- **`036ade`(0xd4190)는 LU 분해다.** 분해 횟수를 세는 훅 지점으로 쓴다. (M1 노트 §6, M2-03c-2)

## MIP 재풀이 (`5ce67b`)

- **상태 12 재풀이는 실패한 LP의 마지막 basis가 아니라 노드에 저장된 시작 basis에서 다시 시작한다.** 첫 LP와 같은 `I+0x98/0xa0` 포인터를 넘긴다. method는 `param_3[3] == 0`이다(C:925; nidda에서는 0). 캡처. (M2-03c-2)
- **재풀이 뒤의 basis export는 LP 상태에 달려 있다.** LP 6(cutoff)이면 export가 없고, LP 2이면 `5d4427`이 노드에 저장한다. 루트에서는 이어서 `68341b`("DegenMoves")가 `10acb2`로 그 basis를 `lp+0x238`에 넣고 Method 0 LP를 푼다. 캡처. (M2-03c-2)
- **`GURO_PAR_FEASHELPER == -2`(즉시 상태 3)는 공개 파라미터 범위 밖이다.** 자연 5→12 재분류는 정확한 산술에서 일어날 수 없다. C. (M2-03c-1, [§10](../m2/mip_linear_child_trace.md))
- **재풀이 method는 첫 LP의 실제 method가 아니라 `param_3[3]`을 다시 읽어 뒤집는다(`(param_3[3]==0)`, C:926).** 첫 LP는 노드 basis가 있으면 `param_3[3]`, 없으면 `param_3+0x10`을 쓰고, `param_7≠0`이면 적응 선택으로 바뀔 수 있다(C:351–455). C(캡처는 nidda 한 점, 첫 1→재풀이 0과 모순 없음). (M2-03d-1, [§2](../m2/mip_retry_rust_boundary.md#2-원본과-상태-경계))
- **재풀이 뒤에도 상태 12이면 노드 basis(`I+0xb0`·`I+0x98`)를 해제하고 `600d25`로 노드 3을 만든다(C:2244–2257).** 다음 LP는 basis 없이 시작한다. C. (M2-03d-1, [§2](../m2/mip_retry_rust_boundary.md#2-원본과-상태-경계))
- **03c 재풀이 오라클의 두 사례는 일반 B&B 노드가 아니다.** nidda 노드 8287(253×464, 부모 null·깊이 0, 노드 basis는 `8e4682`의 donor 복사)은 재시작 뒤 본 탐색에서 RINS(`8ad3a3`→`8bc185`→`8d1e5d`→`8e3397`→`8e4682`)가 정수 50개를 모두 고정해 푼 연속부 LP다. env+0x2728=2이다. gmu(53×110)는 깊이 2 `5bbf7f` sub-MIP(모델 200×81)의 루트 LP다. 실제 B&B 경로 검증에는 쓸 수 없다. 캡처. (M2-03d-1·03d-3, [§6](../m2/mip_retry_node_lp.md#6-실행-결과))
- **MIP 노드 LP의 모델 행은 모델 파일 행과 비트 단위로 같지 않다.** Presolve=0이어도 '>' 행은 부호를 뒤집어 '<'로 두고(nidda 100행), 일부 행은 정수배로 나눈다(1행 λ=1/5). 비영 패턴과 유리수 배수 관계는 정확히 유지된다. 정수 'I'[0,1] 열은 'B'가 된다. Rust LP 재생 입력은 모델 파일이 아니라 캡처한 LP를 써야 한다. 캡처. (M2-03d-3, [§6](../m2/mip_retry_node_lp.md#6-실행-결과))
- **재풀이 판단 시점(`0x4f53a8`)에 노드 LP의 `D`가 제자리에서 scale돼 있을 수 있다.** gmu에서는 `D+0x3d8/0x3e0`가 있었고, 다음 노드 LP 호출에서는 원래 값으로 돌아왔다. 공개 API로 LP를 읽으려면 scale 배열이 없는 시점(노드 LP의 `cda5b` 진입)에 읽는다. 캡처. (M2-03d-3)

- **원본 행 방향 U(LU+0xb0/0xb8/0xd0/0xc8)의 행 안 순서: 갱신은 "마지막 원소로 채우는 삭제 + 끝에 붙이기", 재분해 직후는 singleton 행(kernel 열 원소) = 재분해 전 기저 위치 오름차순, kernel 행 = 활성 행 목록 머리부터(위치 오름차순으로 앞에 넣고 fill도 앞에 넣어, fill 없으면 내림차순).** 근거 `05b257` C:556–567·C:970–1037(row eta이면 LU+0x180 +1, 행 r 비움)·C:1302–1304, `1da0b2` C:530–560, `036ade` C:600–690·C:2258–2265·C:2366–2393. singleton 행의 U 값은 `1da0b2` C:530–560(단계 1–3 행, C:530 앞에 U 값 쓰기 없음)과 C:657–677(단계 4 행, 활성 사본)에서만 쓰여 모두 열 위치 오름차순이다(단계 1·3 열은 앞 행에 원소가 없음, C만, kb2는 t = singleton 수). `09e47c`는 읽기만 한다. 행 U가 주 출력이고 열 U는 036ade L5420–5470에서 전치로 만든다. Rust는 M1-02d부터 `factor_tol`·`update`(`swap_remove`)가 이 순서를 만든다(kb2 피벗 0–21 캡처와 일치). [M1-02a-2](../m1/m1_02a2_urow.md), [M1-02d](../m1/m1_02d_tau.md).
