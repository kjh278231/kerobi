# 원본 사실

- **primal push 재계산은 두 진입점에서 새 factor header로 같은 분류를 수행하고, m=0도 dense FTRAN을 1회 호출한다.** C/asm과 자연8회·합성120사례 캡처. basic은 유한 하한만 빼며 폭0도 v<h 절을 먼저 지나므로 양의 h 경계에서는 X가 아니다. PInf는 basis 위치 순서의 순차 합이다. (M3-04c-17, [계약/결과](../m3/primal_push_recompute_oracle.md))

형식과 근거 표시는 [README](README.md)를 따른다. 주소는 `libgurobi130.so` file offset이며 디컴파일 파일 이름의 앞 숫자와 같다.

## MIP pseudocost 표 (`6edfcf`·`5fb8ec`·`6ee1d3`·`6ef22e`)

(M2-06e, [§2.3](../m2/mip_pseudocost.md#23-노드-갱신-5fb8ec-c546594-asm-0x5112770x511407-0x514e470x514ea5))

## MIP 노드의 basis 저장

- **노드 정보 `I = N+0x18`의 basis 필드.** `+0x94` 저장 시 행 수, `+0x98` vbasis(VBasis 코드 0/−1/−2/−3), `+0xa0` cbasis(0/−1, 보통 `+0x98` 같은 블록의 열 수 뒤), `+0xa8` dual norm(없으면 null), `+0xb0` 압축 basis. 캡처·C. (M2-03c-2, [§2](../m2/mip_retry_basis.md#2-원본과-상태-경계))
- **압축 basis 형식.** 열마다 2비트(0..3 → 0, −1, −2, −3), 이어서 저장 행마다 1비트(1 → −1)이다. 32비트 단어의 MSB부터 끊김 없이 채우며 단어 수는 `(행 + 2·열 + 31) >> 5`다. decode할 때 현재 행이 더 많으면 나머지 행은 0(basic)이 된다. 재구현은 `tools/mip_retry_basis_check.py`의 `decode`가 원본 출력과 같다. 캡처. (M2-03c-2)
- **basis 수명 주기.**
  1. LP 상태가 2이면 `5d4427`, 9이면 `5d3deb`이 `113d92`로 노드 `I+0x98/0xa0`에 저장한다. HasDualNorm이면 `I+0xa8`도 저장한다.
  2. `69d237(node)`이 압축해 `I+0xb0`에 쓰고 `I+0x98`를 해제한다.
  3. `69e299(child, ?, parent)`가 부모의 압축 basis를 복사한다. 부모가 풀린 배열을 갖고 있으면 그 배열을 복사한다.
  4. `5ce67b`는 진입하자마자 `I+0x98`를 해제하고(C:262–275), `69d7ea`로 `I+0xb0`를 푼다.
  
  캡처·C. (M2-03c-2)
- **부모가 null이고 깊이가 0인 비루트 노드는 `8e4682` 경로를 의심한다.** `8e4682`는 donor 노드와 같은 `M`에 `5ff358(0, M)`으로 부모 없는 노드를 만든다. 이어서 donor의 풀린 basis를 복사·압축한 뒤 `5ce67b`를 부른다. C(생성 자체는 캡처하지 않았다). (M2-03c-2)
- **일반 분기 자식도 부모 basis를 물려받는다.** 노드 생성 `5ff358`은 부모가 있으면 `69e299(child, 0, parent)`로 basis를 복사하고, 분기 `627f3e`가 이 함수를 부른다. C. (M2-03d-1, [§2](../m2/mip_retry_rust_boundary.md#2-원본과-상태-경계))

## MIP 노드 선택 용기 (`6e8eb3`·`6e5802`·`6e460c`)

## LP FTRAN 희소 L·R (`21b9de`·`09d112`·`21f83a`)

- **`21b9de`(희소 L)는 세 경로다. LU+0x128 < 0(L 레벨 없음, m < 250 등)이면 Kahn FIFO, 0 ≤ LU+0x128 < 0.1m이면 레벨 버킷(최소 입력 레벨부터, 버킷 안은 넣은 순서, 새로 닿은 행은 그 레벨 끝), `m − e4 ≥ 6`·`10(m − e4)² > m`·LU+0xe4 위 L 원소 > `10(m − e4)`이면 e4 아래 Kahn + 꼬리 순차(경로 B).** 출력은 `|v| ≥ tol`만, 작은 값은 전파하지 않는다. 출력 순서가 α_q 목록의 LU+0xf8 = −1 행 순서를 정한다. L 레벨(LU+0x118, `036ade` C:5764–5830)은 열 앞으로 `lev[i] = max(lev[i], lev[j]+1)`, 조건은 Lᵀ 레벨과 같다. LU+0xe4 = Rust `n_singleton`. (M1-02j, 캡처: degen2 A2 695·kb2 A1 19 비트, 경로 B 캡처 0회·Rust 판정상 Netlib maros-r7·pilot·pilot87·wood1p에서 참, [근거](../m1/m1_02j_lsolve.md#6-실행-결과조사))
- **R 단계의 희소 쪽은 L 출력 순서를 그대로 두고 값이 생긴 eta 대상 행을 끝에 붙이며, 끝에 `|x| ≥ tol`만 남긴다(`09d112` C:1376–1553, `21f83a` 출력은 입력 벡터 쪽에 써진다).** R은 −1 행을 더하지 않는다. (M1-02j, C·캡처 `21f83a` 128회)
- **경로가 오래 같아도 내부 순서는 일찍 다를 수 있다. 정확한 동률에서만 드러난다.** degen2 α_q 목록은 피벗 3부터 달랐지만 경로 첫 차이는 동률(점수·w·|xB| 비트 동일) 피벗 288이었다. 첫 차이를 볼 때 그 피벗의 후보 점수가 동률인지부터 확인한다. (M1-02j)

## LP U 열 저장 (`05b257`·`036ade`)

- **U 열은 [꼬리 행 | 접두 행]으로 저장되고 경계(U+0x78 = LU+0x98)는 행이 t를 넘을 때마다 맞바꿈으로 유지된다.** 새 열은 대각 자리를 마지막으로 채운 spike 목록 순으로 꼬리 행을 앞에서, 접두 행을 끝에서부터 쓴다(C:1228–1260). 행 eta로 r을 지울 때 접두면 열 끝 원소가, 꼬리면 꼬리 끝 원소가 빈칸을 채우고 접두 끝 원소가 접두 맨 앞으로 간다(C:979–1019). eta 없이 r이 접두를 나가면 접두 첫 원소와 맞바꾸고(C:871–899), 접두로 들어오는 행은 꼬리 끝 원소와 맞바꾼다(C:1040–1069). 접두 부분 순서가 H2 출력 순서를 정하므로 값이 맞아도 이 상태가 다르면 순서가 틀린다. (M1-02m, C+캡처, [근거](../m1/m1_02m_usolve.md#7-구현같은-branch-둘째-단계-범위-확대))
- **LU+0xf0에서 여러 행이 함께 빠지는 순서는 옛 열의 저장 순서다.** `05b257` C:535–551이 나가는 열을 저장 순으로 돌며 U 행이 빈 행을 목록에서 뺀다(마지막 원소가 빈 슬롯을 채움). 열 순서를 원본대로 두자 degen2 FTRAN 앞 f0 차이 피벗이 71 → 8로 줄었다. (M1-02m, 캡처)

## dual simplex BFRT (`1c35c5`·`48d5f`)

- **NONDEGENFLIP(`spx+0x3fc`)이 켜지면 BFRT는 진입을 고른 뒤 flip 구간을 다시 훑어 |α|/w′가 더 큰 flip 후보로 진입을 바꾼다(C:1500–1610).** 조건은 `0 ≤ d_t ≤ θ_q·α_t − 1e-3`(1000·OptTol로 추정), w′에는 `((θ_qα_t − d_t)/OptTol)^0.25` 항이 붙는다. 기본값 0이어도 재분해 직후 `48d5f`가 (`0x338 > 2` 또는 m < 3·반복 또는 `0x178 ≠ 0`)이면 −1로 켜고, 그 뒤로 꺼지지 않는다. BFRT 코퍼스의 "교차가 앞에서 일어나는" 불일치 14건이 이것이었다. 입력 배열만 같고 진입이 다르면 spx의 비배열 플래그부터 캡처한다. 캡처+C. (M1-02e, [§6](../m1/m1_02e_bfrt.md#6-실행-결과))

(M1-02e)
- **`036ade` 커널은 남은 활성 n이 조밀해지면 조밀 LU로 넘어간다(조밀 전환).** singleton이 없어 Markowitz 탐색에 들어가기 전마다 채움 추정(기저 열 길이 합에서 시작해 Markowitz 피벗마다 `(r−1)(c−1) − 2`, r·c는 개수−1 저장값)이 `0.36·n²`을 넘고 `4m < n²`, `n > 50`, `m + n² < 2e9`이면 활성 열 개수를 다시 세어 `0.325·n²`을 넘을 때 전환한다(C:1526–1626). 조밀 배열은 열 우선 n×n이고 **열 = 활성 행 오름차순(반환 순열 x20 쪽), 행 = 활성 위치를 열 개수 bucket 0부터 각 순환 목록 head에서 +4 링크(Rust `prv`)로 걸은 순서(x28 쪽)**다. 즉 Bᵀ 배치라 행 방향 나눗셈이 Rust의 L 승수(열 방향)다. n < 1001(또는 n² ≤ m)이면 MKL이 아닌 **자체 SSE2 LU**(C:3968–4920)를 쓰고, 그 밖은 CPU별로 갈리는 MKL `dgetrf_small` 변형이다. 자체 LU는 4행 블록 left-looking(2-lane, 열 시작 주소가 16바이트에서 어긋나면 1개 peel)과 4 미만 꼬리(8-lane, scratch 정렬 peel, 합은 `(A+B)+(C+D)`) 뒤 피벗 행에서 첫 최대 |a| 열 교환이다.
