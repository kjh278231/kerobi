## MIP 노드 힙 키

- **힙 키 `I+0x50`은 `627f3e`와 그 하위 `6406da`·`63c7ae`의 5경로에서 쓴다.** 06a의 "4곳"은 불완전했다. `5ff358`의 다른 호출자 C에는 직접 쓰기가 없다(하위 함수 경유는 미조사). 일반 경로(A)는 `b + min(n/max(1,M+0xa4),1)·2⁻⁴⁸·max(|b|,1)`이고 부모 depth > 100·ncols면 `max(|key|,1)·2⁻⁴⁵`를 더한다. n은 부모 LP의 `+0x80`(스택 `rsp+0x10`과 같음). `M+0x40 == −1e100`이면 키는 n 자체다. 38모델 sweep에서는 A와 B(neos-860300)만 실행됐다. 캡처·asm. (M2-06b-2, [§2](../m2/mip_node_key.md#2-원본과-상태-경계))
- **`M+0xa4`는 루트 LP 분수 수, `M+0x40`은 목적 계수 간격이다.** `654502` C:302가 루트 LP를 풀 때마다 `M+0xa4`를 갱신한다(실행 중 값이 바뀜: tr12-30 161 → 116). `5daa82` C:1649–1787이 `M+0x40`을 만들고 목적이 0이면 −1e100이다(fhnw-binpack4-4). 목적이 있는 모델도 sub-MIP M에서는 −1e100일 수 있다(bppc4-08·mas76 nest 2). 노트 11의 "+0xa4 = 분산 작업 수"는 다른 구조체다. 캡처·C. ## MIP pseudocost 표 (`6edfcf`·`5fb8ec`·`6ee1d3`·`6ef22e`)

- **노드 LP 뒤 pseudocost 일반 갱신은 `5fb8ec` C:546–594이고, 노트 15의 "찾지 못함"은 틀렸다.** 부모가 있고 상태 ≠ 7, 분기 변수 ≥ 0, 부모 목적 > −1e100이면 상태 1·2는 `(lp − p)·w`, 상태 4·5는 cutoff < 5e99일 때만 `w·(cutoff − p)`를 `6edfcf`로 넣는다. `w = pow(0.8/(depth+1), cutoff < 5e99 ? 0.1 : 0.2)`(Python `math.pow`와 비트 일치). `6edfcf`는 `max(Δ,1e-10)/(|f|+0.001)`을 첫 회는 `max(sum,g)`, 이후는 더한다. 캡처 11,157회. (M2-06e, [§2.3](../m2/mip_pseudocost.md#23-노드-갱신-5fb8ec-c546594-asm-0x5112770x511407-0x514e470x514ea5))
- **pseudocost sum은 cnt를 바꾸지 않고도 바뀐다.** 루트 끝 `64da9f`가 대칭 orbit(`M+0x32a8`)이 있으면 `6ef22e`로 클래스마다 평균이 가장 큰 열의 cnt·sum을 모든 열에 복사한다. 감쇠 `6ee1d3`(실패·목적 상승 노드의 조상)도 sum만 줄인다. 같은 실행에서 M을 다시 만들면 `6ec3da`가 앞 M의 표 A 평균을 cnt 0으로 시드한다(6사례 6회 모두 nest 1). 표를 재현하려면 네 경로가 모두 필요하다. 캡처. (M2-06e, [§2.4–2.5](../m2/mip_pseudocost.md#25-대칭-궤도-전파-6ef22eallocmt-공식-캡처-전-탐색에서-찾음))

(M2-06e, M2-06f-2, [§6](../m2/mip_node_life.md#6-실행-결과))
- **감쇠가 읽는 노드 LP 벡터는 현재 노드의 L(`I+0x08`)뿐이다.** `L+0x28`(+`L+0x30`)은 최적 LP의 `12ef7f` 환산비용(n)·행 쌍대값(m)이다(`5d4427`). `L+0x70`은 LP 상태 6(cutoff)이면 같은 `12ef7f` 출력이고(`5ce67b` `0x4f42d3`), infeasible이면 `95da98`가 채우며 성공 시 `L+0x58 ≥ 0`, `L+0x54`가 부호다(내용은 그 뒤 `6684cd`가 고칠 수 있음, 아래 06f-4 항목). `12ef7f`→`1121ad`는 기저 열에 0을 쓴다(노트 13의 "기본해 계산"은 틀린 이름). 출처는 캡처 7,400회, 의미는 C. (M2-06f-2, [§2.3](../m2/mip_node_life.md#23-노드-lp-결과-블록-l0xd0-b))

## MIP 노드의 basis 저장

- **노드 정보 `I = N+0x18`의 basis 필드.** `+0x94` 저장 시 행 수, `+0x98` vbasis(VBasis 코드 0/−1/−2/−3), `+0xa0` cbasis(0/−1, 보통 `+0x98` 같은 블록의 열 수 뒤), `+0xa8` dual norm(없으면 null), `+0xb0` 압축 basis. 캡처·C. (M2-03c-2, [§2](../m2/mip_retry_basis.md#2-원본과-상태-경계))
- **압축 basis 형식.** 열마다 2비트(0..3 → 0, −1, −2, −3), 이어서 저장 행마다 1비트(1 → −1)이다. 32비트 단어의 MSB부터 끊김 없이 채우며 단어 수는 `(행 + 2·열 + 31) >> 5`다. decode할 때 현재 행이 더 많으면 나머지 행은 0(basic)이 된다. 재구현은 `tools/mip_retry_basis_check.py`의 `decode`가 원본 출력과 같다. 캡처. (M2-03c-2)
- **basis 수명 주기.**
  1. LP 상태가 2이면 `5d4427`, 9이면 `5d3deb`이 `113d92`로 노드 `I+0x98/0xa0`에 저장한다. HasDualNorm이면 `I+0xa8`도 저장한다.
  2. `69d237(node)`이 압축해 `I+0xb0`에 쓰고 `I+0x98`를 해제한다.
  3. `69e299(child, ?, parent)`가 부모의 압축 basis를 복사한다. 부모가 풀린 배열을 갖고 있으면 그 배열을 복사한다.
  4. `5ce67b`는 진입하자마자 `I+0x98`를 해제하고(C:262–275), `69d7ea`로 `I+0xb0`를 푼다.
  
  캡처·C. (M2-03c-2)
- **부모가 null이고 깊이가 0인 비루트 노드는 `8e4682` 경로를 의심한다.** `8e4682`는 donor 노드와 같은 `M`에 `5ff358(0, M)`으로 부모 없는 노드를 만든다. 이어서 donor의 풀린 basis를 복사·압축한 뒤 `5ce67b`를 부른다. C(생성 자체는 캡처하지 않았다). (M2-03c-2)
- **일반 분기 자식도 부모 basis를 물려받는다.** 노드 생성 `5ff358`은 부모가 있으면 `69e299(child, 0, parent)`로 basis를 복사하고, 분기 `627f3e`가 이 함수를 부른다. C. (M2-03d-1, [§2](../m2/mip_retry_rust_boundary.md#2-원본과-상태-경계))

## MIP 노드 선택 용기 (`6e8eb3`·`6e5802`·`6e460c`)

- **전역 힙은 키 `I+0x50`의 최소 힙이고 동률에 보조 키가 없다.** 삽입은 부모 ≤ 키에서 멈추고, pop은 두 자식이 같으면 오른쪽, 내릴 키 ≤ 작은 자식이면 멈춘다. 같은 키 비트가 흔하다(markshare_4_0 pop 216 중 215). Rust 힙이 원본 선택을 따르려면 이 세 규칙을 그대로 써야 한다. 캡처. (M2-06a, [§8.2](../m2/mip_node_select_spec.md#82-힙-키와-동률))
- **새 incumbent 뒤 `6e460c`가 힙에서 bound ≥ cutoff를 안정 삭제하고 마지막 인덱스부터 0까지 sift-down으로 재힙화한다.** 순차 삽입 재구성·끝 원소 채우기와는 배열이 다르다. sub-MIP(중첩 2)도 상위 트리에 이 호출을 한다. 캡처. (M2-06a)
- **plunge 목록의 형제는 선택 때마다 `6e8eb3` 꼬리(`0x5b46f4`–`0x5b49ca`)에서 정리된다.** 선택 노드는 끝 원소와 맞바꿔 빠지고, 조상(`5fb13c`, 깊이 d′)이 다른 형제는 목록 순으로 힙에 넣거나(`5f9d4e(·,4)` + `6e5802`) 버린다. 실행에서 힙 삽입의 거의 전부가 이 경로였다(`index.tsv` 크기가 작아 반환 주소가 `raw:5b47b7`로 나온다). 순서는 캡처(M2-06a). 유지 판정은 M2-06c가 9,864호출 재생으로 확인했다. 조상 비교 깊이 d′ = depth − δ이고, δ는 k ≤ `M+0x2c`이면 2, k mod 23 == 7이면 6, 그 밖은 `clamp(trunc(log(0.2·depth+1)/log 2), 3, 10)`이다. bound 문턱은 `5f9a41(M) ≠ 0`일 때만 1e100보다 작다. 기본 설정에서는 0이고 PoolSearchMode=2에서 선다. 그 안의 비교 `5e7796 > 5e8239(M,2) − 1e-10`은 1,964회 모두 참이라 판별되지 않았다. 제거 노드는 `5e7204(M)` > bound면 힙, 아니면 버린다. 캡처. (M2-06a, M2-06c, [§2.3](../m2/mip_plunge_rule.md#23-규칙-312-점수와-꼬리asm))
- **plunge 규칙 번호의 k(`W+0x30`)는 선택 수가 아니라 힙 pop 누계다.** 그래서 k는 수십–수백에 머물고 규칙은 한 plunge 동안 고정된다. 홀수 k의 3/12 난수는 진입 때 `(u64)(k_entry + W+0x28)`로 시드한 지역 슬롯 `0x70(%rsp)`에서 `a7b54f`로 한 번 뽑는다(< 0.9면 3). 전역 RNG 상태는 쓰지 않는다. 규칙 단계는 pop 뒤 k를 쓰고 시드는 진입 k를 쓴다. 규칙 3·12 점수는 `depth ∓ (est − minEst)/1e8`이고 엄격 > 비교에 제외 항목(`I+0x41`)은 건너뛴다. 캡처. `W+0x28`은 `5c239f`가 노드 루프마다 `(*W)+0x60`에서 복사한다(C:104–105, `5c37fd`·`5c3438`은 이전 값 + 1.0). `(*W)+0x60`을 쓰는 곳은 미확인. C. (M2-06c, M2-06d, [§2.2](../m2/mip_plunge_rule.md#22-규칙-번호asm-0x5b33260x5b3553-c381461), [06d §2.3](../m2/mip_plunge_rust.md#23-w0x28-쓰는-곳정적-확인만))
- **plunge 규칙 1·6은 "첫 최심 항목의 조부모(`5fb13c`, maxd − 2)와 같은 조상인 항목"만 고르고, 2는 엄격 최소 est, 5는 `a7b4d6` 정수 mod n이다.** 6은 그중 최소 est, 1은 −depth − (est − minEst)/1e8의 최대(얕은 형제 우선)이며 best는 조상이 일치할 때만 갱신한다. minEst·work 3n은 dispatch 전에 모든 규칙에서 계산한다. 본문 work는 1: 3n+4n, 2: 3n, 4: 7n, 5: 0, 6: 3n+3n, 7: 5n. 캡처 재생(7,465선택·9,864 work). ## LP FTRAN 희소 L·R (`21b9de`·`09d112`·`21f83a`)

- **`21b9de`(희소 L)는 세 경로다. LU+0x128 < 0(L 레벨 없음, m < 250 등)이면 Kahn FIFO, 0 ≤ LU+0x128 < 0.1m이면 레벨 버킷(최소 입력 레벨부터, 버킷 안은 넣은 순서, 새로 닿은 행은 그 레벨 끝), `m − e4 ≥ 6`·`10(m − e4)² > m`·LU+0xe4 위 L 원소 > `10(m − e4)`이면 e4 아래 Kahn + 꼬리 순차(경로 B).** 출력은 `|v| ≥ tol`만, 작은 값은 전파하지 않는다. 출력 순서가 α_q 목록의 LU+0xf8 = −1 행 순서를 정한다. L 레벨(LU+0x118, `036ade` C:5764–5830)은 열 앞으로 `lev[i] = max(lev[i], lev[j]+1)`, 조건은 Lᵀ 레벨과 같다. LU+0xe4 = Rust `n_singleton`. (M1-02j, 캡처: degen2 A2 695·kb2 A1 19 비트, 경로 B 캡처 0회·Rust 판정상 Netlib maros-r7·pilot·pilot87·wood1p에서 참, [근거](../m1/m1_02j_lsolve.md#6-실행-결과조사))
- **R 단계의 희소 쪽은 L 출력 순서를 그대로 두고 값이 생긴 eta 대상 행을 끝에 붙이며, 끝에 `|x| ≥ tol`만 남긴다(`09d112` C:1376–1553, `21f83a` 출력은 입력 벡터 쪽에 써진다).** R은 −1 행을 더하지 않는다. (M1-02j, C·캡처 `21f83a` 128회)
- **경로가 오래 같아도 내부 순서는 일찍 다를 수 있다. 정확한 동률에서만 드러난다.** degen2 α_q 목록은 피벗 3부터 달랐지만 경로 첫 차이는 동률(점수·w·|xB| 비트 동일) 피벗 288이었다. 첫 차이를 볼 때 그 피벗의 후보 점수가 동률인지부터 확인한다. (M1-02j)
- **희소 U 커널 `21686f`·`21841f`의 α_q 출력은 [−1 행 입력 순] + [꼬리 U 위치 내림차순] + [접두 행]이고 접두 순서는 경로가 정한다.** `m ≤ nnz·D²`(S1)나 `D²·(접두+꼬리 입력) > LU+0xec + m − t`(S2)이거나 `2.5·b8 > LU+0xec`(H1)이면 LU+0xf0 목록 순, 아니면(H2) "구간 2" 순: 접두 입력을 입력 순으로, 이어 꼬리 출력 순으로 각 열의 접두 부분 [+0x78, +0x70)을 저장 순으로 훑어 처음 닿은 행. b8 = 접두 입력 수 + Σ 꼬리 출력 열의 접두 부분 길이. 두 커널이 같은 규칙이고 탈락 검사는 `tol < |x/d|` 하나뿐이다. (M1-02m, 캡처 degen2·kb2 274호출 비트 일치, [근거](../m1/m1_02m_usolve.md#6-실행-결과조사))

## LP U 열 저장 (`05b257`·`036ade`)

- **U 열은 [꼬리 행 | 접두 행]으로 저장되고 경계(U+0x78 = LU+0x98)는 행이 t를 넘을 때마다 맞바꿈으로 유지된다.** 새 열은 대각 자리를 마지막으로 채운 spike 목록 순으로 꼬리 행을 앞에서, 접두 행을 끝에서부터 쓴다(C:1228–1260). 행 eta로 r을 지울 때 접두면 열 끝 원소가, 꼬리면 꼬리 끝 원소가 빈칸을 채우고 접두 끝 원소가 접두 맨 앞으로 간다(C:979–1019). eta 없이 r이 접두를 나가면 접두 첫 원소와 맞바꾸고(C:871–899), 접두로 들어오는 행은 꼬리 끝 원소와 맞바꾼다(C:1040–1069). 접두 부분 순서가 H2 출력 순서를 정하므로 값이 맞아도 이 상태가 다르면 순서가 틀린다. (M1-02m, C+캡처, [근거](../m1/m1_02m_usolve.md#7-구현같은-branch-둘째-단계-범위-확대))
- **LU+0xf0에서 여러 행이 함께 빠지는 순서는 옛 열의 저장 순서다.** `05b257` C:535–551이 나가는 열을 저장 순으로 돌며 U 행이 빈 행을 목록에서 뺀다(마지막 원소가 빈 슬롯을 채움). 열 순서를 원본대로 두자 degen2 FTRAN 앞 f0 차이 피벗이 71 → 8로 줄었다. (M1-02m, 캡처)
- **분해 직후 U 열은 U 위치 내림차순이다.** `05b257` C:2570–2600은 분해 뒤 열 끝만 다시 쓰고 경계는 `036ade`가 둔 것을 쓴다. degen2 분해 9회의 모든 열에서 확인했으나 그 모델은 분해 직후 U 위치 = 기저 위치라 두 순서를 가르지 못했다. (M1-02m, 캡처)
