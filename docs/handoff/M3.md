- 검사기 초안은 입력 해시·형식·사건 순서·준비 배열을 확인하며 합성 오류 주입 10건을 거부했다. 복사·변환 식 및 경로별 중첩 검증이 미완성이어서 검사기 명령은 항상 실패한다. 원본 반복 캡처는 다른 원본 실행의 잠금을 기다리고 있다.
- 준비 배열 위치의 ELF 근거와 재실행 명령은 작업 기록에 있다. 시작 전 해시를 고정해 종료 시 변경을 검사하도록 수정했다. R에서 S로의 식 검사 초안과 부모 호출 중첩 검사도 추가했으나 실제 원본 캡처로 검증하기 전이며 검사기 CLI는 계속 실패로 둔다.
- 최초 잠금 충돌 기록 `bench/oracle/m3_crossover_entry/lock-collision-initial.json`은 목표 0건이다. 고정 파라미터·시작 벡터·도구 해시와 명시적 null을 검사기에 추가했으나 원본 검증은 계속 미실행이다.
- 대조군 검사 인터페이스를 별도 추가하고 변환 불일치의 첫 배열 인덱스·비트를 출력하도록 했다. 합성 오류 주입 15건은 종료 0이고 실제 대조군은 미실행이다.
- 공개 `VBasis`·`CBasis`를 완료 마커에 추가했다. API가 제공하지 않는 경우 null이며 내부 vstat와 별도다. 실제 실행은 여전히 잠금 대기 중이다.
- 캡처 메타데이터에 OS·아키텍처·커널·Node 버전을 추가했다. 도구 해시가 변경되므로 실제 캡처 3회는 최종 도구가 고정된 뒤 수행한다.
- 합성 self-test에 비균일 스케일·flip·sense와 ±0 부호 비트 사례를 보존했다. 원본 비교는 아니다.
- 목표 및 대조군 비교 명령은 서로 다른 캡처 파일 세 개를 요구한다. 아직 세 독립 실행은 미실행이다.
- 첫 실제 독립 3회 캡처: barrier·PDHG는 각 mode 0 목표 1건, 기록 비교 일치. `Crossover=0` 대조군 목표 0건·3회 일치, 별도 대조 검사 종료 0. warm은 PStart/DStart 설치 및 status 2이나 목표 0건, 목표 검사 종료 1이다. 입력·출력과 명령은 작업 기록과 `bench/oracle/m3_crossover_entry/`에 있다. warm 원본 분기 추적이 다음 작업이며 전체 오라클은 미완료다.
- warm Method=1은 원본 C 990–1009줄에서 dual start만 보존해 상태가 4가 되어 목표에 도달하지 못했다. Method=2로 바꾸고 모든 경로를 새 도구 해시로 다시 세 번 실행했다. warm mode 1, barrier·PDHG mode 0 각 1건씩이며 대조군은 0건; 경로별 세 기록은 진단 로그 외 모든 필드가 일치했다. CLI 합격 검사 검토와 변조 검사가 남았다.
