# M1 작업 노트 (LP 엔진 포팅)

M1 진행 중에 알아낸 사실과 작업 방법. 확정된 내용은 해당 설계 문서(04, 10)로 옮긴다.

## 1. 비교 기준선

| 디렉터리 | 설정 | 용도 |
|---|---|---|
| `bench/gurobi/` | 기본값(Method=-1, presolve 켬), Threads=1, WorkLimit 60 | 최종 P1 |

## 2. 상태 오라클 (`tools/spx_oracle.py`)

- SIMPLEX 콜백 안에서 `model+0xe0`(spx)을 읽어, 지정한 반복마다 스칼라와 배열을 JSON으로 남긴다. double은 `float.hex()`라 비트 단위로 비교한다.
- 반복 0에는 스케일(`colscale`, `rowscale`), 스케일된 행렬(`beg/len/ind/val`), `b`, `sense`도 남긴다.
- 반복 0까지 이미 끝난 단계: setup(`02f7e1`), 스케일링(`07d3ce`), dual 초기화(`0534f7`, crash 기저 포함), 첫 분해, 첫 `048d5f`. 배열별로 어느 단계가 틀렸는지 가른다: 스케일 → 07d3ce, `c/l/u` → 02f7e1, `vstat` → 0534f7, `d/xB` → 048d5f·1bae9c.
- Gurobi는 한 프로세스만 돌 수 있다(`gurobi_guard.pth`). 다른 세션이 쓰는 중이면 기다렸다 재시도한다.

## 3. 관찰한 사실

- 무한 bound는 내부에서 1e30이다. dual simplex는 이 값을 실제 bound처럼 써서, dual 위반 열을 1e30 쪽에 둔다(인공 bound 방식 phase 1). afiro 반복 0의 목적 −1.8e30 = Σ(음의 reduced cost)·1e30.
- dual 초기 기저는 slack 기저가 아니다(25fv47: 반복 0에 구조 변수 188개가 기저). `0534f7`의 crash 경로를 포팅해야 한다.
- 스케일 인자는 2의 거듭제곱이다. afiro는 열 1.0, 행 {0.25, 1}; 25fv47은 1/32..4.
- 스케일링 경로 선택(`07d3ce` L1490–1625): ScaleFlag=-1(자동)이고 LP·dual이면 모델 등급 D[0]이 4(network)가 아닌 한 **ScaleFlag 3 경로**로 간다. 결과를 D+0x3d0에 캐시한다.
- ScaleFlag 3 경로(L2826~): 최대 10패스. 표시된 열(음수 값)마다 `max_i |a_ij·r_i|`를 구해 역수를 취하고, 열 bound 크기(1..1e30 사이 유한값)와 `sqrt`로 섞은 뒤 [0.5, 2) 밖이면 2의 거듭제곱으로 반올림하고, 직전 값 대비 배율(`local_108`) 한도로 자른다. 음수 부호는 "이번 패스에 갱신 대상" 표시다.
- `07d3ce`는 스케일 전에 모델 데이터 D를 직접 바꾼다: 상한만 있는 열(하한 −inf, 상한 유한)은 x' = −x로 뒤집고(목적·계수·bound 부호, D+0x3c=1), 저장된 스케일이 있으면 다시 적용한다.
- 의사코드에서 `ilogb()`·`scalbn()`의 인자가 빠진 곳이 많다. 해당 지점은 objdump로 인자를 확인한다.

## 4. 스케일링 해독 결과 (`07d3ce`, 2026-11-05)

**변환 규약(64개 전부 비트 일치로 확인)**: spx 행렬 `a'ᵢⱼ = σᵢ·aᵢⱼ·rᵢ·sⱼ`, `b'ᵢ = σᵢ·bᵢ·rᵢ`, `c'ⱼ = cⱼ·sⱼ·objscale`, `l'ⱼ = lⱼ/sⱼ`, `u'ⱼ = uⱼ/sⱼ`(±1e30은 그대로). σᵢ는 `>` 행이면 −1, 아니면 +1이다. sense 문자 배열은 원래 문자를 그대로 둔다. 남은 미지수는 r, s, objscale(관찰값 1, 2, 256)뿐이다.

**ScaleFlag 3 경로(LP·dual 자동 선택)**:
- 배열: `S`(열 n개)와 `R`(행 m개)을 이어 붙인 한 버퍼. 초기값 S = −1(갱신 표시), R = 1.
- 열 패스: 표시된 열마다 `old = −S[j]`, `cmax = maxᵢ |aᵢⱼ·R[i]|`, `s = cmax==0 ? 1 : 1/cmax`. bound 사용 패스면 `bmag = max(1, |l|, |u|)`(1e30 미만인 bound만)이고 `s = sqrt(s·bmag)`. `0.5 < s < 2`면 1, 아니면 `scalbn(1, ilogb(s))`(내림, asm 0x1171ab). 직전 값 대비 배율 f로 자르고 잘렸으면 changed=1. `S[j] = −s`.
- 반복: `iter < 1` 또는 changed면 iter++. iter > 9면 끝. f = (iter == 9) ? 1e100 : 2.0. 행 패스: `rowmaxᵢ = maxⱼ |aᵢⱼ·|S[j]||`, `0.5 < rowmax < 2`면 1, 아니면 `scalbn(1, ilogb(1/rowmax))`, R의 직전 값 대비 f로 자름. iter > 2면 bound를 쓰지 않는 열 패스(LAB_00216dee), 아니면 bound 사용 열 패스(LAB_00216dea).
- 행 패스 특수 규칙: 열 상한이 INFBOUND 이상이고 값이 1e8을 넘으면 rowmax를 `max(1e8, sqrt(…))`로 줄인다(sqrt 인자는 asm 확인 필요).
- 변화 없고 iter ≥ 1이면 L3355의 마무리 열 패스(iter < 3일 때만)를 거쳐 끝난다. 마무리 세부는 미해독.
- 끝: 모든 스케일을 [2⁻⁴⁷, 2⁴⁷]로 자른 뒤 행렬·벡터에 적용한다.
- 확정(오라클 대조): 첫 열 패스 f = 2. changed 표시는 시작과 행 패스 앞에서만 지운다(열 패스는 지우지 않는다). 마무리 열 패스는 bound도 배율 제한도 없다. objscale: 스케일된 0 아닌 |c|의 max·min으로 `max<10 && min>0.1`이면 1, 아니면 `t = sqrt(max(1e-6,min)·max)`, `t ≤ 1`이면 `x = min(100/max, 0.1/t)`, `x ≤ 2`면 1 아니면 2^⌊log₂ x⌋. `t > 1`이면 1.
- 미해독(벤치 표본 없음, 코드에 `shortcut:`): 행 패스의 1e8 특수 규칙, objscale의 `x > 10000` 분기와 `t > 1` 분기.

**포팅 속도 관찰**: 이 함수 하나(5,900줄)의 기본 경로를 해독하는 데 asm 대조가 여러 번 필요했다. 의사코드는 `ilogb`/`sqrt` 인자를 잃고, SIMD 루프는 `auVar` 조각으로 쪼개진다. 줄 단위 옮겨 쓰기는 이 속도로 M1(핵심 dual 경로만 의사코드 약 4만 줄)을 감당할 수 없다. 방식 결정이 필요하다(09 §4).

## 5. dual 시작 기저 해독 (진행 중)

- slack 범위: `<` 행 [0, 1e30], `=` 행 [0, 0](비기저면 상태 −4). (`>` 행은 음수화되어 `<`처럼 다룬다.)
- 초기 비기저 상태(`1e7531@0xeaaa0` L400–420): `u−l > FIXTOL`이면 `c_j < 0 ? −2(상한) : −1(하한)`, 아니면 −4. slack은 행 순서대로 기저.
- `1e7531` L520–700의 crash는 SIMPLEXCRASH ∈ {−1, 2}이고 `n > 100`, `m > 0.125n`, 자유 열 수 > 0.8m일 때만 돈다(점수 `5·len/prev + max/|a| < 6`). afiro 같은 작은 모델에는 해당 없음.
- `0534f7` L600–900: 비기저 자유 열(l ≤ −INF, u ≥ INF)을 상태 −3으로 표시하고 하나씩 기저로 피벗한다(FTRAN `9cf9b` + LU 갱신 `05b257`).
- `0534f7` L901–1300: 두 번째 피벗 루프(BTRAN `9e288`, LU 갱신). 관찰상 **기저에 있는 고정 slack(`=` 행)을 비용 0인 구조 열로 바꾼다**: afiro는 `=` 행 8개 → 구조 열 8개, sc50a는 20개 중 17개. `=` 행을 뒤에서부터 보고, 들어온 열이 닿는 다른 `=` 행으로 이어 간다(사슬). dual ratio test(비용 0 → 비율 0)로 보인다(추정).
- 반복 0의 `vstat` 값(기저 위치)은 다시 번호가 매겨져 있다: 구조 열이 위치 0..k−1, slack이 그 뒤에 행 순서로. LU 재분해가 기저 머리를 재배열하는 것으로 보인다(추정).
- 결론: B단계(시작 기저)는 LU·FTRAN·BTRAN·LU 갱신(C단계) 위에서만 비트 단위로 재현된다. **순서를 C → B → D로 바꾼다.**

## 6. LU 분해 해독 메모 (`036ade@0xd4190`, C단계)

- 인자(관찰): `param_1` 0 허용치(ZERO), `param_2` Markowitz 허용치, `param_3` spx, `param_5` 차원 m, `param_6` 구조 열 수 n(기저 원소 번호 < n이면 구조 열, 아니면 slack), `param_7..10` 열 CSC(시작/길이/행/값), `param_11` 기저 머리(행 위치 → 변수), `param_12` LU 배열 묶음, `param_15` 저장소(+0 시작, +1, +2 용량, +3 예산, +4).
- 시작: LU+0x180/+0x184/+0x18c(eta 수, 갱신 수)를 0으로. 기저 비영 수 `nnzB = Σ(구조 열 길이) + slack 수`.
- 큰 피벗 문턱 `local_120`: 아직 반복이 없고(spx+0x2a0 + spx+0x20 == 0) WARMBASIS(spx+0x160) ∈ {1, 2}이면 INFBOUND, 아니면 1e99.
- 채움 예산: `avg = nnzB/m`. m < 500이면 `avg²`, m < 3000이면 `avg·sqrt(…)`, m < 10000이면 `avg·sqrt(sqrt(…))`(인자는 asm 확인), 그 이상은 avg 그대로. `budget = max(cap/5, 2·m·min(그 값, m/2 + 2))`.
- 순열 배열 두 개(param_12[3], [2])를 −1로 채운 뒤 singleton 단계 `1da0b2`를 부른다. 그다음 Markowitz(앞의 노트 13 §3.6)와 조밀 전환(채움 > 0.36·n², n > 50 → MKL dgetrf).
- 확인(2026-11-05): 오라클 기저로 `xB = B⁻¹(b − N·x_N)`(slack 계수 +1, 비기저는 상태대로 l/u)를 numpy로 풀면 상대 오차 ≤ 3e-15로 맞지만 마지막 비트는 몇 개 다르다(afiro 27/27, sc50a 47/50, adlittle 50/56 비트 일치). 비트 일치에는 LU·FTRAN의 정확한 포팅이 필요하다.
- 검증 계획: 오라클의 반복 0 `vstat`로 같은 기저를 만들고, 내 LU로 계산한 `xB`가 오라클 `xB`와 비트 단위로 같은지 본다(시작 기저 crash와 떼어 LU·FTRAN만 시험).

### 6.1 singleton 단계 `1da0b2@0xdf800` 구조 (해독)

1. 행 개수 `rc[i]`: 기저의 구조 열 원소로 센다. slack이 기저인 행은 `rc += 1 + m` 표시를 단다.
2. `rc ≤ m`인 행만 행 방향 사본(시작 `local_b0`, 위치 `local_100`, 열 번호 `local_98`, 값 `local_a0`)을 만든다. 열 번호는 기저 위치다.
3. **행 singleton**: `rc == 1`인 행을 스택에 쌓고(행 번호 오름차순으로 넣고 뒤에서 꺼냄) 하나씩 피벗한다. 행 r의 아직 피벗 안 된 열 c를 고르고, 대각 = 그 값, 순열 기록(`param_16` 피벗 행, `param_17` 기저 위치, `param_18[r]`, `param_19[c]` = 단계 번호). 열 c의 다른 행 원소는 L 원소 `a/피벗`으로 L 저장소 **끝에서부터 거꾸로** 쌓고, 그 행의 `rc`를 줄여 1이 되면 스택에 넣는다. L 저장소가 넘치면 −1로 빠져나간다.
4. 구조 원소가 하나도 없는 slack 행(`rc == m+1`)의 slack은 대각 1.0으로 바로 피벗한다(기저 위치 순서).
5. 남은 기저 위치를 순서대로 훑는다: 길이 1인 구조 열(그 행이 활성이고 미피벗)이면 그 값으로, slack이면(`rc -= m`) 1.0으로 바로 피벗한다(열 singleton).
6. 활성 부분행렬을 다시 세운다: 열 개수 `local_108`, 행 방향 사본, 이미 피벗한 행의 U 행 저장(`local_70` 시작, `local_80` 열, `local_78` 값). **열 singleton** 스택(`cc == 1`)으로 피벗하며 U 행 원소를 덧붙인다.
7. 남은 활성 크기가 50 이상이고 LU2X2BLOCK(spx+0x4e4)이 허용하면, 개수 2인 행을 해시로 짝지어(`1d9af1`) 2×2 블록 피벗을 한다. 큰 쪽 |a|를 피벗으로 쓰고, 소거 뒤 값이 `|·| ≥ 1e-10`일 때만 받아들인다.
8. 나머지는 `036ade`의 Markowitz 단계로 넘어간다.

### 6.2 FTRAN `2207de@0x120740` 구조 (해독 중)

- 희소 벡터 `{int nnz; int* idx (+8); double* val (+0x10)}`, `nnz < 0`이면 조밀.
- 조밀 입력: LU+0x20 순열로 값을 옮겨 담은 뒤 조밀 L 커널 `214344(m, LU+0x20, v)`.
- 희소 입력: 인덱스를 LU+0x30 순열로 바꾼다. `m < nnz·LU[0x104]`이거나 LU[0x128] ≥ 0.1·m이면 조밀 커널, 아니면 희소 L 커널 `21b9de`.
- 다음 R 단계: row eta(개수 LU+0x180, 목록 LU+0x198, 원소 {?, len, idx*, val*})를 차례로 적용한다.
- 다음 U 단계: 조밀 `2126cd`, 희소 `21686f`(두 번째 RHS용 `21574d`).
- 조밀 L 해법 `214344`(해독): L 열 k = 0..LU[0xb8]에 대해, 그리고 k = LU[0xc4]..m−1에 대해 `|x[k]| > ZERO`이면 그 열의 원소마다 `x[i] = x[i] − l·x[k]`(시작 LU+0x38 long, 행 LU+0x48, 값 LU+0x40). 한 열 안의 갱신은 서로 다른 i라 순서가 비트에 영향을 주지 않는다. 비트를 정하는 것은 **피벗 순서, 승수 `a/피벗`, 열 처리 순서, ZERO 건너뛰기**뿐이다. 따라서 LU는 줄 단위 이식 없이도 피벗 순서·동점 처리·승수 계산만 같으면 비트 일치를 기대할 수 있다(U 해법이 열 방향인지 확인 필요: 행 방향 내적이면 합산 순서도 맞춰야 한다).
- 커널은 희소 입력을 조밀 작업 배열에 흩뿌린 뒤 풀고, 작업량 `*param_6 += m + 2·nnz`를 더한다. 해법 루프의 연산 순서는 다음에 읽는다(LU+0x38/0x40/0x48: L 구조, LU+0x68/0x70/0x80/0x88: U 구조로 추정).
