# M1-02w 재분해 LU+0x108 차이 검증 계약과 결과

작성 기준은 [스프린트 검증 기준](../15_sprint_verification.md)이다. 기준 main `d09db91`, 미커밋 선행 변경 없음. 작업자는 이 세션(Claude Code, "다음 스프린트 진행해 너가 작업자야" 지시. M2-06h-7은 다른 세션이 점유 중이라 M1 다음 작업). branch `work/m1-02w`, worktree `../rsolver-m1-02w`.

## 1. 범위와 주장

- 작업 종류: 조사(원인이 작고 원본 비교가 닫히면 같은 branch에서 구현, 아니면 후속 번호).
- 조사 질문: stair(Method=1, Presolve=0) e_r 185 직전 재분해에서 원본과 Rust가 같은 피벗으로 재분해했는데 LU+0x108만 다르다(LU+0x110·t 같음, [M1-02k §6.1](m1_02k_btran_ut.md#61-첫-실패와-추가로-드러난-차이)). 원인이 U 구조 차이인가, `036ade` C:5725–5740 식 차이인가.
- 답의 형식: (1) 원본 행 방향 U로 Σlen(rows t..m)/(m−t)+1을 계산해 원본 LU+0x108과 비교(식 확인), (2) 원본·Rust 행 U 대조(구조 차이 위치), (3) 차이가 나는 재분해 단계(조밀 전환·`local_70`·풀 부족 재호출 등)를 Rust 재현으로 특정.
- 제외: LU 풀이 work(M1-02t), pilot 정확도(M1-02y-2), `48d5f`·`8b473` 분기(M1-02u).

## 2. 원본과 상태 경계

- Gurobi 13.0.3, `libgurobi130.so` SHA-256 `8e87fca221fdffc922331c8619426031b3e72dfd419446422f88af0cb0e98f9c`.
- 식: `036ade` C:5725–5740. LU+0x108 = (start[m] − start[t])/(m − t) + 1(t < m, 아니면 1.5), `param_12` = LU+0x20이라 start = LU+0xb0(`param_12[0x12]` = `local_d8`, 행 U 시작 배열), `local_308` = &start[m](C:5180·5209), t = LU+0x100(`param_12[0x1c]`의 int). Rust `Lu::finish`는 Σ`urow[k].len()`(k ∈ [t, m))을 쓴다.
- 비교 지점: k번째 dual e_r BTRAN(`221173` via `9e376`, 반환 0xc51dd)의 `21a941` 진입에서 행 U(LU+0xb0/0xb8/0xd0/0xc8)·대각 LU+0x50(`tools/m1_urow_dump.js`), Rust는 같은 e_r 번호의 `RSOLVER_UROW_PROBE`. 원본 LU+0x108·0x110 비트는 M1-02k 캡처(`bench/oracle/m1_02k/stair_syn_*.json.gz`).

## 6. 실행 결과

- 실행 commit: 기준 main `d09db91` + 이 branch. x86-64 Linux(WSL2). Gurobi는 M2-06h-7 세션과 번갈아 썼다(`tools/gurun.sh` 잠금 대기).
- **식 확인**: 원본 덤프에서 Σlen(rows t..m)/(m − t) + 1 = (start[m] − start[t])/(m − t) + 1 = 원본 LU+0x108 비트. 행 시작은 단조이고 end = start + len, 빈칸 0. Rust `Lu::finish`의 `mean(t..m)`과 같은 식이다. 그래서 차이는 **U 구조**다.
- **구조 차이의 위치**: 대각 차이는 위치 303–355(마지막 53단계)에 모이고 행 차이 189(열 위치 차이 188 + 값만 1)는 그 열들을 가리키는 행이다(예: 행 40 원본 [315] ↔ Rust [343]). 원본 `tools/m1_pool_size.js`가 이 재분해에서 조밀 전환 진입(0xd88bf, 활성 n = 53)을 기록했다. Rust M1 `factor_block`은 조밀 전환을 끈 채(M3-04c-21i 계약) Markowitz로 끝까지 가므로 피벗 순서와 채움이 다르다.
- **Rust 재현**: 임시 패치로 M1 재분해를 `Lu::factor_dense(cap)`로 돌리면 cap = 142,294(원본 F+0x158)에서 e_r 185의 r·eta·t·LU+0x108이 같고 행 U·대각 356행이 비트 일치한다. stair 전체도 바뀐다: `m1_btran_check` stair 356/356(끝까지, `KNOWN_D` 비운 사본), pathcmp stair 356피벗 **완전 일치**(기존 빌드는 피벗 211에서 첫 차이, `bench/oracle/m1_01e/stage2/pathcmp.txt`), IterCount 356 = 원본, `m1_diag_peel_check` stair 갱신 일치 179 → 337/347, `m1_lt_check`(stair 범위를 356으로 둔 사본)은 e_r 347 출력 값 0번째에서 175 ulp 차이로 실패(원본 `bf978ba2c1f8e2c6`, Rust `bf978ba2c1f8e217`; 피벗 337 조밀 재분해 뒤, 원인 미조사). 출력 `explore/cap142294/`. 표 `explore/local_f8.txt`(`bench/oracle/m1_02w/local_f8.py`). 이 숫자는 stair에 맞춘 cap 하나로 낸 재현이며 다른 모델은 같은 빌드에서 cap이 틀리다.
- **cap이 값에 미치는 경로**: cap = 1,000,000·1,000,001에서는 구조는 같고 조밀 영역 값이 달랐다(대각 18·행 33, 살펴본 대각 4개는 1–4 ulp; 그 출력은 남기지 않았다). 조밀 배열 정렬이 첫 채움 `local_f8 = max(cap/5, min(m/2+2, d²)·2m)`의 짝홀로 정해지기 때문이다([교훈](../lessons/original.md) `036ade` 조밀 배열 주소). 피벗 185에서 d = nnz(B)/m = 2824/356(M1-01e 원본 head로 계산)이고 nnz(B) 항이 44,803(홀수)으로 cap/5 = 28,458보다 커서 정렬을 정한다. cap 1,000,000은 200,000(짝수)이 이겨 틀렸고, 1,000,005(200,001 홀수)는 우연히 맞았다. cap 자체보다 "어느 항이 이기는가"가 중요하다. 재분해별 두 항: `explore/local_f8.txt`.
- **풀 크기 수명(64모델 탐색)**: F+0x158은 실행 첫 `036ade` 진입에 이미 정해져 있고(`0534f7` C:150의 0x158 쓰기는 S의 다른 필드), 바뀐 경우는 grow15·grow22의 `036ade` 풀 부족 −1 재호출뿐이다. FT 갱신의 풀 부족 ×1.5(`05b257` C:802–846)는 64모델에서 한 번도 없었다(모든 호출에서 진입 값 = 직전 호출의 반환 값, 반환 ≠ 진입은 rc = −1일 때만임을 64모델 전체에 assert). 초기값 규칙은 찾지 못했다(afiro 1,607, adlittle 6,421, stair 142,294 …; agg2·agg3은 m·n이 같고 nnz +16에 +738이라 nnz에 비선형). 쓰는 함수도 정적 grep(`+ 0x158) =`, `0x2b`)으로는 못 찾았다.
- 실행하지 못한 것: 원본 3회 재현(조사), 조밀 전환을 켠 빌드의 전체 회귀(구현 범위), stair e_r 347 차이의 원인, perold·pilot4·grow15·grow22의 Rust 재현(cap·풀 부족 수명 필요).
- 계약 변경: 없음. "원인이 작으면 구현"은 초기 F+0x158 규칙이 없어 충족하지 못했다(§7).

## 7. 판정과 인수인계

- 작업 수행: **완료(조사)**. 답: 식은 원본과 같고, stair e_r 185의 LU+0x108 차이는 **M1 재분해가 `036ade` 조밀 전환을 끈 채 도는 U 구조 차이**다. 원본 F+0x158을 준 `factor_dense`로 바꾸면 그 지점의 U 전체(356행)가 비트 일치한다(Rust 재현 증거). 동등성 판정은 하지 않는다(조사).
- 구현이 이번 범위를 넘는 이유: 조밀 배열 정렬이 F+0x158에 달렸는데 M1은 그 값을 모른다(초기 규칙 미확인). 원본 값을 상수로 넣는 구현은 원본 동작 복원이 아니다.
- 후속:
  - **M1-02w-2**(조사): M1 초기 F+0x158 규칙. 첫 단계는 `0xe7c50`(`0534f7`)·`0xf15c0`(`05b257`) 첫 진입에서 F = S+0x470의 +0x158을 읽어 쓰기 지점을 좁히고, 그 함수의 C로 식을 세운 뒤 `bench/oracle/m1_02w/pool/` 64모델 값으로 대조한다.
  - **M1-02w-3**(구현): M1 재분해를 `Lu::factor_dense`(풀 크기 F+0x158 수명, `crossover_refactor::refactor`의 풀 부족 재호출 루프 재사용)로 바꾼다. 대상 5모델(stair·grow15·grow22·perold·pilot4)을 원본 3회 재현 기준으로 대조하고, §3 회귀 규칙(stair가 `KNOWN_D`에서 빠지며 `m1_btran_check`·`m1_diag_peel_check`·`m1_lt_check` 범위 확장)을 따른다. stair e_r 347 차이도 여기서 본다. M3 인수인계의 "M1 `Lu`에 조밀 전환·`local_70` 켜기"와 같은 일이다. 현재 pathcmp 첫 차이는 grow15 365·grow22 256·perold 365로 그 모델들의 첫 조밀 재분해(1020·697·697)보다 앞이라 다른 원인이 먼저 있고, pilot4는 첫 분해(피벗 0)부터 조밀 전환이며 첫 차이가 134다.
