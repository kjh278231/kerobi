# M1-02w 재분해 LU+0x108 차이 검증 계약과 결과

작성 기준은 [스프린트 검증 기준](../15_sprint_verification.md)이다. 기준 main `d09db91`, 미커밋 선행 변경 없음. 작업자는 이 세션(Claude Code, "다음 스프린트 진행해 너가 작업자야" 지시. M2-06h-7은 다른 세션이 점유 중이라 M1 다음 작업). branch `work/m1-02w`, worktree `../rsolver-m1-02w`.

## 1. 범위와 주장

- 작업 종류: 조사(원인이 작고 원본 비교가 닫히면 같은 branch에서 구현, 아니면 후속 번호).
- 조사 질문: stair(Method=1, Presolve=0) e_r 185 직전 재분해에서 원본과 Rust가 같은 피벗으로 재분해했는데 LU+0x108만 다르다(LU+0x110·t 같음, [M1-02k §6.1](m1_02k_btran_ut.md#61-첫-실패와-추가로-드러난-차이)). 원인이 U 구조 차이인가, `036ade` C:5725–5740 식 차이인가.
- 답의 형식: (1) 원본 행 방향 U로 Σlen(rows t..m)/(m−t)+1을 계산해 원본 LU+0x108과 비교(식 확인), (2) 원본·Rust 행 U 대조(구조 차이 위치), (3) 차이가 나는 재분해 단계(조밀 전환·`local_70`·풀 부족 재호출 등)를 Rust 재현으로 특정.
- 제외: LU 풀이 work(M1-02t), pilot 정확도(M1-02y-2), `48d5f`·`8b473` 분기(M1-02u).

## 2. 원본과 상태 경계

- Gurobi 13.0.3, `libgurobi130.so` SHA-256 `8e87fca221fdffc922331c8619426031b3e72dfd419446422f88af0cb0e98f9c`.
- 식: `036ade` C:5725–5740. LU+0x108 = (start[m] − start[t])/(m − t) + 1(t < m, 아니면 1.5), `param_12` = LU+0x20이라 start = LU+0xb0(`param_12[0x12]` = `local_d8`, 행 U 시작 배열), `local_308` = &start[m](C:5180·5209), t = LU+0x100(`param_12[0x1c]`의 int). Rust `Lu::finish`는 Σ`urow[k].len()`(k ∈ [t, m))을 쓴다.
- 비교 지점: k번째 dual e_r BTRAN(`221173` via `9e376`, 반환 0xc51dd)의 `21a941` 진입에서 행 U(LU+0xb0/0xb8/0xd0/0xc8)·대각 LU+0x50(`tools/m1_urow_dump.js`), Rust는 같은 e_r 번호의 `RSOLVER_UROW_PROBE`. 원본 LU+0x108·0x110 비트는 M1-02k 캡처(`bench/oracle/m1_02k/stair_syn_*.json.gz`).
