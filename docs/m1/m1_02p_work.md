# M1-02p 검증 계약과 결과: dual simplex work 누적의 출처와 재분해 work 조건의 입력

작성 기준은 [스프린트 검증 기준](../15_sprint_verification.md)이다. [M1-02n](m1_02n_update.md) §8의 후속이다. 사용자의 "다음 스프린트 진행해. 너가 작업자야" 지시로 착수했다(2026-11-11). M2는 다른 세션이 M2-06c-3을 점유해 M1을 골랐다([시작 절차](../handoff/README.md) §1-3).

## 1. 범위와 주장

- 작업 종류: 조사 + 오라클 구축(새 읽기 전용 캡처). **Rust 구현은 하지 않는다.** 재분해 work 조건은 분해 시작부터 판정까지의 work 합 전체를 쓰므로 일부 커널만 옮기면 판정에서 관측할 수 없다. 쓰기 지점이 약 70곳 20함수라 한 주에 검증할 수 없어 함수 묶음별 후속 번호로 나눈다.
- 조사 질문(degen2·kb2, Method=1 Presolve=0 Threads=1):
  - **Q1 출처**: dual 실행(`06268b` 진입부터 반환까지) 동안 work double(`06268b` param_2)에 쓰는 명령은 무엇인가. 실행한 집합(캡처)과 정적 상위 집합(`06268b`에서 work 포인터를 받는 함수를 따라간 전이 폐포)을 구하고, 두 모델에서 실행되지 않은 쓰기를 따로 적는다.
  - **Q2 규칙**: 지점마다 더하는 양의 식, 입력, 실행 조건, 부동소수 연산 순서. 저장 명령이 있는 곳과 양을 계산한 곳이 다르면 asm으로 피연산자를 거슬러 올라간다.
  - **Q3 필드**: spx+0x150·0x158·0x3d0의 쓰는 곳과 의미를 캡처로 비트 확인한다(02n은 C로만 적었다).
  - **Q4 Rust 범위**: 지점 → 식 → 입력 → Rust 대응 → 그 입력이 degen2 피벗 0–355에서 같다는 기존 검사기 근거. 근거 없는 입력은 후속 작업에서 따로 검사해야 한다.
- 포함: degen2·kb2 dual 실행 전체의 모든 work 쓰기, `06268b`가 부른 `05b257` 전부(진입·반환), LAB_001f6eb5 판정 전부.
- 제외와 후속: Rust work 누적 구현(함수 묶음별 후속 번호, §8), Q2 식의 입력별 캡처 대조(이번에는 C·asm 해석과 증분 값 대조까지), primal(`0b2cdf`)·barrier work, `06268b` 밖의 work(진입 값은 입력 상태로만 기록).
- 선행: main `97b1d44`(M1-02n 병합). 미커밋 선행 변경 없음.

## 2. 원본과 상태 경계

- Gurobi 13.0.3 `libgurobi130.so` SHA-256 `8e87fca2…0e98f9c`, 주소는 file offset(ghidra − 0x100000). 모델 `../re/bench/data/netlib/degen2.mps.gz`, `kb2.mps.gz`.
- 시작: `06268b(param_1, double *work)` `0xf6a00` 진입. 종료: 그 반환. work 포인터는 dual 실행 내내 같다(판정 지점 r12와 `05b257` 둘째 인자가 같은지 사건마다 확인).
- 관측: work 8바이트에 쓰기 하드웨어 watchpoint(Frida 17 `Thread.setHardwareWatchpoint`, 모든 스레드, `06268b` 진입에서 걸고 반환에서 해제). 트랩 pc는 저장 명령 **다음** 명령이다. 예외 처리기는 장착 중의 `single-step`·`breakpoint` 예외만 받고 나머지는 원래 처리로 넘긴다.
- 호출 문맥: 쓰기 함수(탐색에서 저장이 나온 20함수 + `1c090a`)의 진입·반환에 Interceptor 스택을 두고, 쓰기 때 가장 안쪽 함수와 그 호출 지점을 기록한다(backtrace를 쓰지 않는다).
- 판정 지점과 피벗 번호는 [M1-02n](m1_02n_update.md) §2와 같다(LAB_001f6eb5 `0xf6eb5`, `8b473` 호출 지점 `0xc58d5`).
- 읽기 전용. 주소는 저장하지 않는다(라이브러리 내 offset만).

[lessons/tooling.md](../lessons/tooling.md)는 watchpoint를 진단 전용으로 적었다. 이번에는 쓰기 집합 자체가 답이라 기준 캡처로 쓴다. 대신 아래 N(02n 캡처와 판정별 work 비트 동일)·C(사슬)·M(3회 바이트 동일)을 합격 조건으로 둔다.

## 3. 비교 계약

캡처 도구 `tools/m1_work.js`, 검사기 `tools/m1_work_check.py`.

| 검사 | 규칙 |
|---|---|
| M 입력 | degen2·kb2 각 3회 gz SHA-256 고정·바이트 동일, 정상 종료(`DONE`), 바이너리·모델·도구 해시, errors 없음 |
| N 비간섭 | 판정 사건 열 (k, 갱신 수, 이유, work, spx+0x150, spx+0x158, spx+0x3d0)이 02n 캡처 run 1과 같다(비트). 출력 줄(상태·IterCount)이 같다 |
| C 사슬 | E(진입 값) 다음 W 열이 work의 모든 변경이다: 각 D·U 사건의 work = 직전 W 값(없으면 E), L = 마지막 W, 포인터 같음(`wp`). W의 예외 종류는 둘 중 하나, 함수 스택이 비지 않음 |
| S 쓰기 집합 | W의 (트랩 pc, 함수)별 실행 수가 `bench/oracle/m1_02p/sites.tsv`와 같다. 표에 없는 pc는 실패 |
| F 필드 | 0x150: 재분해한 `05b257` 호출(진입 이유 ≠ 0)마다 반환 0x150 = 그 호출 안 `036ade` 첫 work 쓰기 직전 값, 그리고 = 진입 work인지 센다. 0x158: 그 호출 안 `036ade` 마지막 쓰기 뒤 값 d에서 Δ = d − 0x150, 옛 0x158 ≤ 0이면 Δ, 아니면 (Δ + 옛)·0.5(env+0x2454 ≠ 0이고 env+0x2728 < 2일 때만, 아니면 그대로)가 반환 0x158과 비트 같다. 재분해가 아닌 호출과 판정 사이에서는 0x150·0x158 불변. 0x3d0: 모든 판정에서 모델의 A 비영 원소 수와 같다 |
| R 판정 | 판정마다 work 술어를 이 캡처 값으로 계산해 02n 규칙의 이유와 같다(02n R 재확인), 갱신 수 % 10 = 9인 판정의 여유 rhs/lhs 최솟값·최댓값 출력 |
| G 분해 | 재분해 사이 구간마다 함수별 증분 합(정보). 구간 합 = 구간 끝 값 − 시작 값은 C로 보장되므로 따로 판정하지 않는다 |
| T 변조 | (`--self-test`) 바이너리 해시 0, 빈 사건, W 하나 삭제(사슬), W 값 한 비트, 표에 없는 pc, 0x158 반환 한 비트, 0x150 반환 한 비트, 0x3d0 + 1, 판정 work 한 비트. 모두 거부. 모델 변이 2종(0x158 평균에서 0.5 생략, Δ 기준을 `05b257` 진입 work로)은 거부 또는 판별 불가를 기록 |

- 정수·순서는 정확 비교, double은 IEEE 비트(hex)로 저장해 비트 비교한다.
- Q2 식은 C·asm 해석이다. 캡처로는 지점별 증분 값과 실행 수만 확인한다. 식의 입력을 캡처하지 않은 지점은 "식 미검증"으로 표시한다.
- 합격(조사·오라클): M·N·C·S·F·R·T 통과, Q1–Q4 답 또는 답하지 못한 이유 기록.

### 6.2 Q2 지점별 규칙

지점마다 식·입력 C 줄·조건·연산 순서는 [부록 A](m1_02p_formulas.md)(C·asm 해석, 하위 에이전트 둘이 지점별로 저장 명령과 피연산자 사슬을 asm에서 읽음)에 적었다. 요약:

- 꼴은 거의 모두 `(정수·반정수 식)·x148 + w`이다. 예외적으로 `w + (4C)·x148`(`1c35c5` 0xc8b67), `(x148·7)·F + w`(`1c8477` 0xce1ef), `w + (f·3)·m`(`9e60b`) 순서가 있다. 곱 묶음이 다르면 x148 = 1.3에서 끝자리가 달라지므로 원본 묶음을 지켜야 한다.
- LU 풀이(`9e288`·`9e376`·`9d112`)는 LU+0x200에 커널들이 모은 값을, `2207de`는 지역 누적을 **LU+0x1f8**(spx+0x148 사본, `251b4f`가 잠시 1.0으로 바꿨다 되돌림)로 곱해 한 번 더한다. 이 넷만 증분/x148이 반정수가 아니다(degen2 `9d112` 477/634, `9e376` 291/634, `9e288` 444/460, `2207de` 94/113. 커널 안 나눗셈 항, 예 `21b9de` L255). 그래서 이 넷은 커널 안 합산 순서까지 맞춰야 한다. 나머지 65지점은 매번 반정수 단위였다.
- 일부 저장은 조건이 거짓이면 건너뛰고 부분합을 레지스터로 다음 저장에 넘긴다(`15d2d`, `2896a3`, `05b257` 재분해 뒤 경로, `1bae9c` 0xc26ec–0xc2842). Rust는 저장 단위가 아니라 더하는 순서를 맞추면 된다.
- 캡처로 식까지 확인한 지점(Q, 비트): `534f7` 2·nnz(A), `05b257` 0xf48ae 3m·LU+0x1f8, 0xf4f9b 9m, `9e60b` 0x1329c1 3m·LU+0x1f8, `1ca57` 0xbf981 (m+n)(2 + [spx+0x338 ≠ 0]), `1bae9c` 0xc391f m. `1ca57`의 spx+0x338은 같은 호출 안 `1bae9c` 뒤에 바뀌므로(kb2 피벗 15부터 1) 쓰기 순간 값을 캡처했다. LU+0x1f8 = spx+0x148(비트)은 판정 시점에서 확인했다.
- 해석만 한 곳: `48d5f`(0xe7000)·`8b473`(0x120114)는 여러 분기 항의 합인데 반복마다 어느 분기인지 추적하지 않았다. `036ade` 0xd85e6 Markowitz 누적의 분기별 항, LU 커널(`221173`·`21a941`·`214344`·`21b9de`·`21686f`·`2126cd`·`21574d`·`21f83a`·`21841f`) 안 누적은 C만 읽었다.

### 6.4 Q4 Rust 범위

Rust에는 dual work 누적이 없다(`crossover.rs`에만 같은 꼴 `*work += units·work_coef`가 있다). 모든 증분의 입력은 원본이 결정적으로 정하는 개수(열·행 길이, 목록·벡터 nnz, 위치 차, 반복 횟수)라 Rust가 같은 자료 구조 상태를 가지면 옮길 수 있다. 입력별 근거는 아래와 같다(degen2 피벗 0–355, kb2 전체가 기존 검사기 범위).

## 7. 판정과 인수인계

- 작업 수행 상태: 완료(조사·오라클).
- 동등성: 조사라 구현 동등성 판정 없음. 오라클 범위(쓰기 집합·사슬·필드·모델 상수 식)는 통과.
- 남은 한계: Q2 식 대부분은 C·asm 해석이며 캡처로 확인한 식은 6지점이다. 두 모델 밖(quad, m > 10000, presolve 켬, Threads > 1)과 미실행 쓰기(§6.5)는 미검증. watchpoint 예외 처리기는 장착 중 `breakpoint`·`single-step` 예외를 모두 work 쓰기로 받는다(다른 int3가 섞이면 S가 실패한다).

## 8. 후속 작업

work 비교 오라클은 이 캡처의 W 열(지점, 쓴 뒤 값)이다. Rust가 같은 순서로 (지점 표식, 값)을 내면 첫 다른 쓰기에서 지점과 입력을 바로 알 수 있다. 진입 값(degen2 46,145.0)을 시작값으로 준다.

- **M1-02q**(구현): Rust dual work 누적 틀(지점 표식 열 스냅숏)과 분해(`036ade` 5)·재분해 뒤(`05b257` 5, `9e60b` 3)·모델 상수 지점. 합격은 재분해마다 0x150·0x158 비트와 해당 W 비트. Markowitz 누적 분기를 먼저 캡처로 확인한다.
- **M1-02r**(구현): FT 갱신 `05b257` 16지점(위치 차 p − s 포함).
- **M1-02s**(조사·구현): 반복 커널 `a4109`·`1c35c5`·`28c93`·`1c8477`·`2896a3`·`15d2d`·`16b0a`와 재분해 뒤 `1bae9c`·`1ca57`·`1b7106`.
- **M1-02t**(조사·구현, 02k 뒤): LU 풀이 `9e288`·`9e376`·`9d112`·`2207de`의 커널별 누적과 합산 순서.
- **M1-02u**(조사): `48d5f`·`8b473`의 반복별 분기.
- 모두 끝나면 degen2 피벗 356 판정과 그 뒤 경로를 02n 검사기 `--rust`로 대조한다.
