# M1-02a-1 검증 계약과 결과: kb2 반복 12의 남은 DSE w 차이(τ = B⁻¹ρ)

작성 기준은 [스프린트 검증 기준](../15_sprint_verification.md)이다. [M1-02b](m1_02b_beta.md) §7 후속 조사이고, 사용자의 "다음 스프린트 진행" 지시로 착수했다(2026-11-11). M2는 다른 세션이 M2-03d-13을 점유하고 있어 [시작 절차](../handoff/README.md) §1-3 순서대로 M1을 골랐다.

## 1. 범위와 주장

- 작업 종류: 조사. 산출물은 [M1 설계](sprint_design.md) §2대로 최초로 다른 값, 그 값을 마지막으로 쓴 원본 함수·연산, 같은 입력의 Rust 연산이다. Rust 솔버 코드는 바꾸지 않는다. 임시 계측·실험은 되돌리고 탐색으로만 기록한다.
- 질문: M1-02b 뒤 kb2(Method=1, Presolve=0, Threads=1)의 스냅숏 12(피벗 11)에서 DSE 가중치 w가 2개 위치에서 다르다. 갱신식의 어느 입력이 처음 다르고, 원본은 그 입력을 어떤 연산으로 만드는가.
- 탐색(§6.1)에서 세운 가설. 판정은 §3 검사로 한다.
  - 원본 갱신식은 `1bae9c`(`0xc0050`) C:420–459다. 갱신 경로(LU+0x18c ≠ 0, C:177)이고 spx+0x3ec ≠ 0이면 `w_r = (β/α_r)/α_r`, α_q 희소 목록의 k번째 원소마다 `t = α_k/α_r`, `w_{idx_k} = max(1e-8, (β·t·t − (t+t)·τ_k) + w_{idx_k})`다. τ_k는 spx+0x218 val의 k번째로, 행 번호가 아니라 α_q 목록 위치 k로 읽는다. Rust 식(`simplex.rs` DSE 갱신)과 같다.
  - 다른 입력은 τ다. 피벗 11의 α_q 13개 위치 중 위치 20·22의 τ가 Rust와 다르다. 그 밖의 입력(α_q 값, β, α_r, 이전 w)은 같다.
  - τ는 `8b473`(`0x11f620`) C:419의 `09d112`(`0x125f50`)가 α_q와 함께 FTRAN해 만든다. 모드 1이면 C:226 `8b281`이 spx+0x218(ρ)과 spx+0x228 벡터 구조체를 맞바꾼 뒤 부른다. 그래서 인자는 `09d112(LU, α_q 출력 0x210, a_q 입력 0x220, τ 출력 0x218, ρ 입력 0x228, &nnz, r, work)`로 본다(C 근거, 이번 캡처로 확인). C:466–482의 피벗 제거는 α_q 원소를 마지막 원소와 바꿀 때 τ val도 같이 바꾼다.
  - Rust는 τ를 `rho`의 조밀 복사본에 `ftran_lower`·`ftran_upper`를 적용해 만든다. α_q에 쓰는 것과 같은 함수다.
- 포함 범위: kb2 피벗 0–37(원본), Rust 대조는 같은 입력이 보장되는 피벗 0–21(피벗 분기 21 전).
- 완료 기준: 처음 다른 입력과 위치를 원본 캡처로 직접 보인다(역산 아님). 그 τ를 만든 `09d112`의 실행 경로(호출 커널, 조밀·희소 판정)를 특정하고, Rust 연산과 무엇이 다른지 C·실행 근거로 답한다. 원본 τ를 같은 입력에서 비트 재현하는 규칙을 찾으면 함께 기록한다. 찾지 못하면 원인 특정을 주장하지 않고 국소화한 단계까지만 적고 후속 번호를 둔다.
- 제외 범위와 후속:
  - 수정(구현)은 새 하위 번호다.
  - 반복 22 이후의 피벗 분기와 Method=1 Netlib 64 재측정(M1-02c)은 범위 밖이다.
  - devex(spx+0x3ec = 2, C:178–417)와 모드 3 경로는 kb2에서 실행되지 않으면 C만이다.
- 선행: main `79d1d5c`. 미커밋 선행 변경 없음.

- 처음 계약에서 바뀐 점: A는 τ val이 α_q 출력 목록에 맞춰 정렬된 형식임을 반영했다(처음에는 출력 형식 미정). U·I·R·G를 더했다. 원본 τ를 같은 입력에서 재현하려면 L·R 단계 값이 필요한데, 원본 캡처에는 없어서 Rust LU 덤프(임시 계측, §5 패치)를 기준 자료로 고정하고 U·I·R로 원본·현재 코드와 묶었다. 판정 규칙을 넓힌 것은 없다.
- 비교는 모두 비트(u64) 정확 비교다. 허용오차 없음.
- 목표 사건이 없으면 실패: `09d112` 사건 0개, T의 차이 0개(또는 피벗 11에 없음), W·G 대상 0개, 모으기 대상 중 2항 이상 행 0개.
- 자기검사(`--self-test`): 바이너리 해시, 회차 차이, 빈 사건, 캡처 파일 해시, 도구 해시, 덤프 해시, 피벗 11 원본 τ 한 비트(A·W·G), 피벗 11 α_q 한 원소 누락(A·W), `09d112` ρ 한 비트(X·I), w 한 비트(W), 원본 U 행 하나의 두 원소 순서 교환(G), Rust τ를 원본 τ로 대체(T), 원본 피벗 11 τ를 Rust τ로 대체(T·W), 덤프 L 값 한 비트(R), 캡처 U 값 한 비트(U), 원본 a_q 입력 한 비트(I)를 모두 거부해야 한다.
- C만으로 남길 것: 8항 이상 U 행 내적의 레인 결합(캡처에 없음), 재분해 직후 U 행 초기 순서의 생성 규칙(원본 캡처 순서를 그대로 씀).

## 6. 실행 결과

### 6.1 탐색(계약 확정 전, 판정 근거 아님)

- worktree 빌드에서 `tools/m1_beta_check.py` PASS, `statecmp kb2` 반복 12 w 2개(첫 var 58)를 재현했다.
- 저장 오라클 스냅숏 12의 `aq`(13원소)·`beta`·`ar`와 스냅숏 11의 w에 Rust 스냅숏 τ를 넣어 §1 식을 계산했다(스크래치). 13개 중 11개 위치가 원본 w와 비트까지 같고, 위치 20·22만 다르다. 원본 w를 내는 τ는 Rust τ에서 위치 20이 −1~−2 ulp, 위치 22가 +12~+16 ulp 떨어진 값이다(역산). 스냅숏 13에서는 위치 19(−2~−21 ulp)·35(+1 ulp)가 같은 방식으로 다르다. Rust τ의 두 값은 가수 끝이 0으로 끝나 상쇄가 있었던 값이다.

- 반복 11 상태로 원본 `09d112`의 τ를 직접 읽었다(탐색 캡처 2회, 스크래치). 피벗 11의 α_q 13개 위치 중 20·22만 Rust와 다르다(역산과 같은 결론). τ val은 모든 경로에서 α_q 출력 목록 순서로 정렬돼 있다. τ 구조체의 nnz 필드는 그 개수가 아니다. 희소 τ 출력 피벗 14개에서는 nnz가 `09d112` 입력 ρ의 nnz와 같았고(idx는 다름), 피벗 10 이후의 −1은 ρ 작업 벡터가 조밀 경로를 탔다는 뜻으로 보인다(추정, 교환된 구조체의 잔여 필드).
- R 단계(row eta 내적)는 두 RHS가 같은 8레인 구조로 보였다(C:1135–1355). Rust 덤프(임시 계측, 커밋 안 함)를 Python으로 재현해 R 결합 순서·순차 합·L drop 변형을 시험했지만 원본 차이는 바뀌지 않았다.
- 피벗 11 행 17·19(위치 20·22)는 L 기여 3개, U 기여 2개(꼬리 단계 18·21)를 받는다. 원본은 U 기여를 21 → 18 순서로, Rust는 18 → 21(U 위치 내림차순)로 뺀다. 순서만 바꾸면 두 값이 원본과 비트까지 같다.
- `09d112` C:1888–2430(두 RHS 조밀 경로)을 읽었다. α_q는 꼬리 열(U 위치 ≥ LU+0x100)을 열 방향으로 모든 행에 흩뿌린다. τ는 꼬리 열 원소 중 접두 행 구간(LU+0x98..0x90)을 건너뛴다(C:2205–2263). 그 대신 출력 단계(C:2279–2402)에서 α_q가 비영인 접두 행마다 LU+0xf8 ≥ 0이면 U 행(LU+0xb0..0xb8, idx LU+0xd0, val LU+0xc8)을 내적해 `(τ_i − Σ u·τ_j)/d_i`로 모은다. −1이면 `τ_i/d_i`, −2(꼬리)면 이미 나눈 값을 쓴다.
- U 행 저장 순서를 "열 삽입 순서, 열 삭제 때 마지막 원소로 채움"으로 모의하면 피벗 0–21의 τ 269개가 모두 같았다. 삭제를 안정 삭제로 바꾸면 피벗 14(위치 17·35)가, 새 열을 앞에 넣으면 피벗 11–21이 틀린다. 재분해 직후 초기 순서(오름차순·내림차순)는 판별되지 않았다. 이 모의는 검사 근거로 쓰지 않고, 고정 캡처에 원본 U 행 저장 자체를 넣었다(§3 G).

## 7. 판정과 인수인계

- 작업 수행 상태: **완료(조사)**.
- 답:
  - 처음 다른 입력은 DSE 갱신식의 τ(=B⁻¹ρ)다. 피벗 11(스냅숏 12)의 위치 20·22이며, 원본 캡처로 직접 확인했다. α_q·ρ·β·α_r·이전 w와 U 인자(행·값·대각·순서·접두 t)는 원본과 비트까지 같다.
  - 그 τ를 쓴 원본 연산은 `8b473` C:419의 `09d112` 두 RHS FTRAN이다(캡처). 해당 피벗이 인라인 조밀 경로(C:1888–2430)를 탄다는 것은 간접 근거다. U 단계 분기(C:1788–1887)의 피호출이 없고, τ 출력 nnz가 −1이며, 그 경로의 규칙이 τ를 재현한다. 블록 안 주소 훅으로 직접 확인하지는 않았다.
  - τ의 U 단계 규칙: 꼬리 열(U 위치 ≥ LU+0x100)은 U 위치 내림차순으로 나누고 꼬리 행에만 흩뿌린다. α_q 목록의 접두 행은 U 행을 저장 순서대로 내적해 `(x_i − Σ u·τ_j)/d_i`로 모은다(LU+0xf8 ≥ 0. −1이면 `x_i/d_i`).

  - 실행 근거: 이 규칙을 원본 U 행 저장 순서와 Rust L·R 결과에 적용하면 피벗 0–21의 τ 269개가 모두 원본과 비트까지 같다. 같은 입력에 Rust 규칙을 적용하면 정확히 34개(피벗 11–14·18–21)가 다르다.
