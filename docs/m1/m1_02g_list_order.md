# M1-02g 검증 계약과 결과: kb2 반복 22 가격 목록(mode 1) 순서 차이

작성 기준은 [스프린트 검증 기준](../15_sprint_verification.md)이다. [M1-02f](m1_02f_bfrt_rust.md) §7의 후속 조사이고, 사용자의 "다음 스프린트 진행" 지시로 착수했다(2026-11-11). M2는 다른 세션이 M2-06f·shared를 먼저 점유해 [시작 절차](../handoff/README.md) §1-3 순서대로 M1을 골랐다.

## 1. 범위와 주장

- 작업 종류: 조사. Rust 솔버 코드는 바꾸지 않는다. 임시 계측·주입 실험은 되돌리고 탐색(§6.1)으로만 기록한다.
- 질문: M1-02f 뒤 kb2(Method=1, Presolve=0, Threads=1) 스냅숏 22에서 vstat·x_B·d·w는 같은데 가격 목록(mode 1, 길이 13)의 순서가 위치 8부터 다르다(원본 변수 `[23, 1, 45, 12, 77, 25, 79, 10, 17, 19, 64, 24, 66]`, Rust `[…, 10, 19, 24, 64, 66, 17]`). 처음 다른 입력은 무엇이고, 원본은 그 순서를 어떤 규칙으로 만드는가.
- 착수 전 가설(탐색 근거, 판정은 §3):
  - 목록 집합은 같고 피벗 21 갱신에서 새로 붙는 위치의 순서만 다르다. 원본은 위치 `[20, 5, 17, 13, 19]` 순으로, Rust는 위치 오름차순으로 붙인다.
  - 원본 mode 1 갱신 루프 `1bae9c`(`0xc0050`) C:597–700은 `puVar19 = spx+0x210`(C:156), 즉 `8b473`이 피벗 위치를 마지막 원소로 채워 뺀 최종 α_q 희소 목록을 저장 순서대로 돌며 x_B를 갱신하고, 위반이면서 표시 bit 0이 0이고 점수 ≥ 문턱이면 목록 끝(P+0x10[P+0x28])에 붙인다. Rust `simplex.rs`는 같은 판정을 α_q 지지의 위치 오름차순(`supp`)으로 한다.
  - α_q 목록 순서는 `09d112` 출력 순서다. 조밀 경로는 위치 오름차순이라 Rust와 같고, 희소 U 경로(`21686f`·`21841f`)는 다르다. kb2 mode 1 구간(반복 6–30)에서 희소 U 경로는 피벗 21·24뿐이고, 처음이 피벗 21이다. 그래서 02f의 재훑기 자체가 아니라, 재훑기가 바꾼 진입 열(25)의 FTRAN이 희소 경로를 탄 것이 원인이다.
- 완료 기준: (1) 원본 스냅숏만으로 mode 1 피벗마다 CHUZR 정리와 갱신 루프를 재생해 다음 스냅숏의 목록 전체(순서 포함)·표시를 맞히고, 판별 피벗에서 "위치 오름차순" 변이가 거부된다. (2) Rust에 원본 순서를 임시 주입하면 statecmp 반복 22가 같아짐을 보여 충분성을 확인한다. (3) α_q 목록을 만든 `09d112` 경로(커널)를 특정한다. 희소 출력 순서 자체의 재현 규칙은 시간을 정해 한 번 시도하고, 재현하지 못하면 후속 번호로 넘긴다.
- 제외 범위와 후속:
  - Rust 수정(FTRAN 희소 출력 순서 + 갱신 루프 순서)은 새 구현 번호다.
  - 반복 23 이후의 d·w 끝자리 차이는 이 순서 차이와 별개일 수 있다. 주입 실험에서 남으면 새 행으로 둔다.
  - flip 패스(`1c8477`)의 touch 순서, LU 갱신 spike 순서가 같은 출력 순서에 의존하는지는 범위 밖이다(미확인으로 기록).
  - 원본은 다시 실행하지 않는다(저장 기준 재생). 판별 피벗을 늘리려 다른 모델을 캡처하면 §6에 따로 적는다.
- 선행: main `49c622d`(M1-02f 병합). 미커밋 선행 변경 없음.

## 2. 원본과 상태 경계

- Gurobi 13.0.3, `libgurobi130.so` SHA-256 `8e87fca221fdffc922331c8619426031b3e72dfd419446422f88af0cb0e98f9c`. 주소는 file offset이다. 모델 `../re/bench/data/netlib/kb2.mps.gz`.

| 위치 | 내용 |
|---|---|
| `1bae9c` `0xc0050` C:149–165 | 지역 별칭: `lVar15` = P+0x10(목록), `pcVar17` = spx+0x280(표시), `puVar19` = spx+0x210(α_q 목록), `local_b0` = spx+0x2c8(인공 bound 단계), `lVar52` = spx+0x1e8(x_B) |
| `1bae9c` C:466–490 | 나간 위치 r(spx+0x2f8): x_B[r] 갱신, 위반이면 표시 1(mode 0이면 P+0x28 −1), 아니면 2 |
| `1bae9c` C:497–543 | mode 1(P+0x40 ≠ 0): P+0x48 갱신 뒤 목록 길이 P+0x28 > max(P+0x48, spx+0x46c)이면 문턱 P+0x30 ×1.1. r의 표시가 1이면 점수만 새로 쓰고, 아니면 3 |
| `1bae9c` C:544–700 | α_q 목록 k = 0..nnz 순서로 x_B 갱신, 위반이면 점수를 쓰고 표시 3 → 1, 표시 bit 0 = 0이면 점수 < 문턱 → 0, 아니면 목록 끝에 붙이고 1. 위반 아니면 표시 \|= 2. C:546 분기는 spx+0x2c8(허용오차 식)만 다르다 |
| `2896a3` | mode 1 CHUZR: 목록 정리(표시 < 2이고 점수 ≥ 문턱만 유지)와 문턱 낮춤 스캔(Rust `Pricing::full_pick`) |
| `8b473` `0x11f620` C:419, C:466–482 | `09d112` 호출과 피벗 제거(마지막 원소로 채움) |
| `09d112` `0x125f50` | 두 RHS FTRAN. 희소 U 커널 `21686f`(`0x1295e0`)·`21841f`(`0x129547`), 조밀 `2126cd`(`0x12959f`) |

- 시작 경계: 스냅숏 k(spx_oracle, 반복 k의 SIMPLEX 콜백 = 피벗 k−1 갱신 뒤, 피벗 k CHUZR 전). 종료 경계: 스냅숏 k+1.
- 읽는 상태: 스냅숏 k의 P+0x10[:P+0x28] 목록, 표시, 점수, 문턱. 스냅숏 k+1의 r·q·α_q 목록(`aq`, 피벗 k의 최종 spx+0x210)·x_B·l·u·vstat·점수·문턱·표시·목록.
- 조밀·희소 경로 식별: [M1-02a-1](m1_02a1_tau.md) 고정 캡처 `bench/oracle/m1_02a1_tau/kb2_{1,2,3}.json.gz`의 피벗별 `09d112` 피호출 순서.

## 3. 비교 계약

새 `tools/m1_list_order_check.py`가 판정한다. 하나라도 실패하면 종료코드 1이고, 첫 차이의 피벗·위치·기준값·실제값을 출력한다.

| 검사 | 규칙 |
|---|---|
| M 입력 | 저장 오라클 `bench/oracle/iter0-30/kb2.jsonl.gz`와 02a-1 캡처 gz의 SHA-256 고정. 02a-1 3회 피벗별 α_q 목록이 같다 |
| X 연결 | 스냅숏 k+1의 `aq` 목록 = 02a-1 캡처 피벗 k의 최종 α_q 목록(피벗 0–29), r = 02a-1의 r |
| L 목록 재생 | mode 1 피벗(스냅숏 k·k+1 모두 mode 1, 재분해 없음)마다: 스냅숏 k 상태에 CHUZR 정리·스캔을 적용하고 고른 위치 = 스냅숏 k+1의 r, 그 뒤 r 처리와 α_q 목록 순서의 갱신 루프(위반은 스냅숏 k+1 x_B·bound·허용오차 1e-6로, 점수·문턱은 스냅숏 k+1 값)를 적용한 목록이 스냅숏 k+1 목록과 순서까지 같고, 건드린 위치의 표시가 같다. flip이 있는 피벗(비기저 vstat −1↔−2 변화)은 따로 세고 목록이 맞지 않으면 실패로 둔다 |
| P 경로 | 피벗마다 02a-1의 U 커널(`21686f`·`21841f`·`2126cd`·없음)과 α_q 목록이 위치 오름차순인지 표. mode 1 구간에서 비정렬 목록이 희소 U 커널 피벗에만 있다 |
| V 변이 | (`--self-test`) 갱신 루프를 위치 오름차순으로 돌린 변이가 판별 피벗(그 순서로 붙는 위치가 2개 이상이고 α_q 순서와 오름차순이 다른 피벗)에서만 거부된다. 판별 피벗이 0이면 실패 |
| T 변조 | (`--self-test`) 피벗 21의 `aq` 붙는 두 원소 교환, 스냅숏 22 목록 두 원소 교환, 스냅숏 21 표시 하나 변경, 02a-1 α_q 목록 두 원소 교환(X)이 각각 거부된다 |

- 비교는 정수 위치·표시 정확 비교다. 점수·x_B는 원본 값을 그대로 쓰고 다시 계산하지 않는다(위반 판정만 x_B·bound 비트로 한다).
- 충분성(탐색, 판정 아님): Rust `price_touch`에 원본 피벗 21의 α_q 순서를 임시 주입한 빌드로 statecmp 반복 22·23을 본다. 패치는 되돌린다.
