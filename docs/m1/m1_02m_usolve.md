# M1-02m 검증 계약과 결과: 희소 U 커널의 접두 행 출력 순서

작성 기준은 [스프린트 검증 기준](../15_sprint_verification.md)이다. [M1-02j](m1_02j_lsolve.md) §7의 후속이다. 사용자의 "다음 스프린트 진행" 지시로 착수했다(2026-11-11). M2는 다른 세션이 M2-06c-2를 점유 중이라 M1을 골랐다([시작 절차](../handoff/README.md) §1-3).

## 1. 범위와 주장

- 작업 종류: 조사(새 읽기 전용 캡처 포함) + 조건부 구현. 구현은 §3 (a)가 원본 규칙을, (b)가 Rust U 열 상태가 원본과 같음을 보인 뒤에만 같은 branch 둘째 단계로 넣는다. (b)가 다르면 열 유지(`05b257`) 복원이 필요하므로 조사 완료로 닫고 후속 번호를 붙인다.
- 조사 질문: dual DSE 두-RHS FTRAN `09d112`의 희소 U 커널 `21686f`(ρ 쪽 희소)·`21841f`(ρ 쪽 조밀)이 α_q 출력에서 접두 행(LU+0xf8 ≥ 0)을 어떤 순서로 내는가. degen2 피벗 8 첫 차이(원본 `[239, 183, 202, 50]`, Rust 슬롯 오름차순)의 원인인가.
- 포함 분기: 두 커널의 α_q 쪽 전체 출력(−1 행·꼬리·접두), C의 경로 판정 세 개(§2). degen2·kb2 Method=1 Presolve=0 Threads=1의 모든 호출.
- 함께 닫는 항목: 커널 입력 벡터 = α_q 쪽 L+R 출력이므로 02j가 미검증으로 둔 인라인 희소 R 순서(degen2 146피벗)를 같은 캡처로 대조한다.
- 제외 범위와 후속: `21686f`의 힙↔순차 전환은 처리 순서가 같아 work에만 닿는다(순서·값은 비트 비교로 확인). `21574d`(ρ 쪽 U)·τ 값은 M1-02o. LU+0xf0 목록 자체의 이탈 순서는 M1-02n.
- 선행: main `497233f`. 미커밋 선행 변경 없음.

## 2. 원본과 상태 경계

- Gurobi 13.0.3 `libgurobi130.so` SHA-256 `8e87fca2…0e98f9c`. 모델 `../re/bench/data/netlib/degen2.mps.gz`, `kb2.mps.gz`.
- 커널 인자(`09d112` C:1804·1883, tol은 xmm0): `21686f(m, U, in, out, mark, work, &work)`, `21841f(LU, m, U, in, out, ρin, ρout, mark, work, &work)`. U = LU+0x20. 인덱스는 기저 위치 공간이다.
- U 구조(U+오프셋): 행→U 위치 +0x20, U 위치→행 +0x28, 대각 +0x30, 열 시작 +0x68, 꼬리/접두 경계 +0x78, 끝 +0x70, 값 +0x80, 행 +0x88, f0 목록 +0xd0, f8 +0xd8, ec +0xcc, t +0xe0, D = +0xe8 + +0xf0.

| 위치 | 내용 |
|---|---|
| `21686f` C:89–108 / `21841f` C:201–225 | `m ≤ nnz_in·D²`(경로 S1): 입력 순서대로 f8 = −1이면 `tol < |v/d|`일 때 바로 출력, 아니면 work에 둔다 |
| `21686f` C:109–162 / `21841f` C:226–270 | 아니면 입력 순서대로 −1은 바로 출력, −2(꼬리)는 work, f8 ≥ 0(접두)은 mark = 1, "구간 2"(out idx의 m − ec 칸부터)에 입력 순서로 둔다. `D²·(접두 입력 + 꼬리 입력) ≤ ec + (m − t)`가 거짓이면 경로 S2 |
| `21686f` C:162–374 / `21841f` C:270–413 | 경로 H: 꼬리를 U 위치 내림차순으로 풀며(21686f 힙·순차, 21841f 순차) `tol < |v/d|`이면 출력하고 열의 꼬리 부분 [+0x68, +0x78)만 흩뿌린다. b8 = 접두 입력 수 + Σ 꼬리 출력 열의 접두 부분 길이(+0x70 − +0x78) |
| `21686f` C:375–416 / `21841f` C:414–450 | `2.5·b8 ≤ ec`(H2): 꼬리 출력 순으로 각 열의 접두 부분을 저장 순으로 흩뿌리며 mark = 0인 행을 구간 2 끝에 붙이고, 구간 2 순서로 `tol < |v/d|`면 출력 |
| `21686f` C:417–507 / `21841f` C:451–552 | 아니면(H1): 접두 부분을 흩뿌리고 f0 목록 순으로 출력 |
| `21686f` C:508–625 / `21841f` C:553–772 | S1·S2: 꼬리 U 위치 m−1 → t 순차(열 전체 흩뿌림), 접두는 f0 목록 순 |

- 시작 경계: 피벗 k의 `09d112`(`8b473`에서) 안 커널 진입. 종료 경계: 커널 반환. 커널은 U를 바꾸지 않는다.
- 읽는 상태: 입력 벡터(진입에서 복사, `21686f`는 입력 idx를 제자리에서 압축), 위 U 구조 전체(꼬리 열의 세 부분 행·값, 대각), f0·f8·ec·t·D, 출력 벡터.

## 7. 구현(같은 branch 둘째 단계, 범위 확대)

U 열 저장 규칙이 C에서 모두 읽혔고 필요한 상태(spike 목록 순서, 행의 꼬리/접두 소속, 분해 단계 순서)가 Rust 값으로 정해져 구현을 넣었다. 계약 §3의 (b) C·(c) O·I를 그대로 쓰고, C는 "t·f0가 같은데 접두 부분 순서가 다르면 실패"로 조였다. t·f0 자체가 다른 피벗은 `05b257` 접두 판정(이 계약 밖)이라 제외로 센다. 줄인 판정은 없다.

| 원본 | 규칙(열 = [꼬리 부분 \| 접두 부분]) |
|---|---|
| `05b257` C:1228–1260 | 새 열: 대각 자리를 마지막 원소로 채운 spike 목록 순으로, 꼬리 행은 앞에서부터, 접두 행은 끝에서부터 쓴다 |
| C:979–1019 (행 eta 있음) | 행 r 제거: r이 접두(q < t)면 열의 마지막 원소가 빈칸을 채운다. 꼬리면 꼬리 끝 원소가 빈칸을, 접두 끝 원소가 접두 맨 앞을 채운다 |
| C:871–899 (eta 없음, r이 접두에서 나감) | r을 접두 첫 원소와 맞바꾸고 경계 +1 |
| C:1040–1069 (빈 열이 p를 대신함) | 접두로 들어오는 행을 꼬리 끝 원소와 맞바꾸고 경계 −1(C만, 아래 변이 생존) |
| 분해 직후(`036ade`, 캡처) | 열 원소가 U 위치 내림차순(꼬리가 자연히 앞). `05b257` C:2570–2600은 끝(LU+0x90)만 다시 쓰고 경계는 건드리지 않는다 |

- `lu.rs`: `umid`(열별 꼬리 원소 수, U+0x78), `finish`가 분해 직후 순서, `update`가 위 네 연산, `prefix_part`. `ftran2`가 S1·S2·H 판정과 b8로 구간 2 순서를 낸다(값은 그대로 조밀 규칙). 스냅숏 `ucp`(꼬리 열별 접두 부분), `f0k`(FTRAN 시점 LU+0xf0), `aqk`(피벗 제거 전 커널 출력).
- 분해 직후 순서: degen2 분해 9회(피벗 82–536, 열 582개 이상)의 모든 열이 U 위치 내림차순이다. 그 모델에서는 분해 직후 U 위치 = 기저 위치라 "기저 위치 내림차순"과 구별되지 않는다(kb2 분해는 갱신 0에서 커널 호출이 없어 캡처 0회).
