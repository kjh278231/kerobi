# M1-02e 검증 계약과 결과: kb2 피벗 21 진입 선택(BFRT `1c35c5`)

작성 기준은 [스프린트 검증 기준](../15_sprint_verification.md)이다. [M1-02d](m1_02d_tau.md)의 후속 조사이고, 사용자의 "다음 스프린트 진행" 지시로 착수했다(2026-11-11). M2는 다른 세션이 M2-06b-2와 shared를 먼저 점유해 [시작 절차](../handoff/README.md) §1-3 순서대로 M1을 골랐다.

## 1. 범위와 주장

- 작업 종류: 조사.
- 조사 질문:
  1. kb2 피벗 21(BFRT 코퍼스 호출 21)에서 원본은 열 25를 flip 없이 넣고, `tools/proto/bfrt.py`와 Rust는 열 4를 넣고 25를 flip한다. 반복 0–21 상태(statecmp)와 코퍼스 입력(α·d·vstat·bound·δ)이 같은데 원본이 25를 고르는 분기와 그 입력은 무엇인가.
  2. 같은 원인이 BFRT 코퍼스의 남은 불일치 18건(fit1d 12, tuff 4, kb2 1, stocfor1 1, [m1_notes §8.6](m1_notes.md))을 설명하는가.
- 착수 전 가설(H1, C만): `1c35c5` 재선별(C:805–870)의 |α| 문턱은 `max(1e-13·max|α|, |spx+0x438|)`이고, `spx+0x438`은 PIVOTTOL 상수가 아니라 행 거부 때 갱신되는 누적값이다(C:1265·1966·2181, `28c93` C:787, 0 초기화 `28c93` C:90·625, `1df51` C:59, `534f7` C:134). 기록 후보가 0이고 lo > 0이면 C:878부터 `cand[0..lo)`로 다시 고른다. 재선별 θ 초기값은 −1e100이 아니라 1패스의 진행형 문턱(`dVar110`)이다. 프로토타입은 셋 다 다르게 가정한다.
- 계약 변경(첫 캡처 뒤, 결과 판정 전): kb2 캡처에서 `spx+0x438`은 38회 모두 0이라 H1의 문턱 부분은 기각했다. 같은 캡처에서 호출 21 진입의 `spx+0x3fc = −1`, 반환의 `spx+0x308`(α_q) = −16.97(열 25의 α)이다. 이에 따라 가설 H4를 더한다: 진입 q가 정해진 뒤 `spx+0x3fc ≠ 0`이면 C:1500–1610이 flip 구간 `cand[0..lo)`를 다시 훑어, `0 ≤ d_t ≤ θ_q·α_t − (보정)`이고 |α_t|/w′_t가 q의 |α_q|/w_q보다 큰 후보를 새 진입으로 바꾸고 flip 목록을 θ_new로 다시 만든다(w′ = (열 원소 수 또는 slack 0.5 + `spx+0x178 < 10`이면 ((θ_q·α_t − d_t)/OptTol)^0.25)·(0.3f + 0.7)). 진입 필드에 `spx+0x3fc`·`spx+0x178`·`spx+0x380`, 반환 필드에 `spx+0x3fc`·`spx+0x178`·`spx+0x308`을 더해 Netlib 64 코퍼스 전체를 `bench/oracle/m1_02e_bfrt`에 다시 캡처한다. 보정항 `dVar103·OptTol`의 dVar103은 C에서 정하지 못해 후보값(0 등)을 코퍼스로 고른다. 이 값은 판별되는 범위까지만 주장한다.
- 제외 범위와 후속:
  - Rust `bfrt.rs` 수정은 구현 작업(M1-02f, 새 행 제안)으로 나눈다. 이번에는 프로토타입(`tools/proto/bfrt.py`)으로 원본 코퍼스 대조만 한다.
  - 대체 경로 C:878 이후의 비용 이동(`a7b54f`·`a7b4d6` 난수)은 코퍼스에 RNG 상태가 없어 사건이 나오면 미검증으로 남긴다.
  - `0x2cc ≠ 0`(인공 bound 단계) 변형 루프(C:342–420)는 기존 코퍼스 범위 그대로 둔다.
- 선행: main `51e12e2`(M1-02d 병합 포함). 미커밋 선행 변경 없음.

- 원인(C + 코퍼스): 재선별(C:790–870)까지는 프로토타입과 원본이 같다. quickselect는 lo = 1(flip 후보 열 25, 기여 50.9 < |δ| 924.5)이고 본 선택은 열 4(|α| 0.64)다. 그 뒤 `LAB_001c8ecf`(C:1500–1610)가 `spx+0x3fc`(NONDEGENFLIP, 기본 0, 노트 13 §표)가 0이 아니면 flip 구간을 다시 훑는다.
  - θ_q = d_q/α_q(α_q는 `spx+0x308`).
  - 대상: flip 구간 t 중 `d_t ≥ 0`이고 `d_t ≤ θ_q·α_t − 보정`. 보정은 asm `0xc8f29`의 `[rsp+0x88]·[rsp+0x90]`이다. `0xc8ecf`로 오는 세 경로(`0xc8ec7` 직전 흐름, `0xca52a`, `0xcaf1f`/`0xcaf2f`)가 모두 두 슬롯을 다시 읽는다. `[rsp+0x88]`의 첫 쓰기(`0xc8626`, `0xc8923`)는 `.rodata 0x2a5d240` = 1000.0이다. 다른 쓰기 지점(`0xc9007`, `0xcafff` 등)이 이 경로에 오는지와 `[rsp+0x90]`의 값은 확정하지 못했다. C의 `dVar103·OptTol`은 이 곱의 Ghidra 표기다. 따라서 "1000·OptTol"은 **asm 부분 근거 + 코퍼스 적합**이다. 코퍼스에서 보정 8e-4–1.2e-3만 최대 일치이고, 0이면 3092, 1e-6이면 3094, 5e-3이면 3104다. 코퍼스의 OptTol·FeasTol이 모두 1e-6이라 1000·OptTol, 1000·FeasTol, 상수 1e-3은 구별하지 못한다.
  - 점수: `w′ = (열 원소 수(slack 0.5) + ((θ_q·α_t − d_t)/OptTol)^0.25)·(0.3f + 0.7)`. pow 항은 `spx+0x178 < 10`일 때만 더한다. `α_t < s·w′`(s = 본 선택의 α_q/w_q)이면 바꾼다.
  - 바꾸면 진입은 t, flip은 나머지 flip 구간 중 `d ≤ α·θ_new`(순서 유지).
  - kb2 21: 열 25의 |α|/w′가 열 4보다 커서 25가 진입하고 flip 목록이 빈다.
- 코퍼스 대조(`python3 tools/proto/bfrt.py --dir bench/oracle/m1_02e_bfrt -vv`):

| 규칙 | 진입 일치 | flip 일치 |

| 수정 전(`BFRT_RESCAN=0`) | 3094/3112 | 3098/3112 |
| 재훑기, 보정 1000·OptTol(최종) | **3108/3112** | **3112/3112** |

- 남은 4건은 모두 tuff 호출 31·33·36·37이다. lo = 0(flip 없음)이라 재훑기와 무관하다. 네 호출 모두 후보에 `−OptTol < d < −1e-13`인 열 228이 있고 프로토타입은 228을 고른다.
  - 반환 때 d(AX:0x1e0)는 228이 양수로 바뀌어 있다(−5.28e-7 → 2.41e-7 등, 캡처). 원본 C:1690–1740은 이런 d를 난수(`a7b54f`)로 비용 이동한다.
  - 그 d만 반환값으로 바꿔 재생하면 4건 모두 원본 진입과 같다(`--shift-replay`, `mismatches equal after shift replay 4`).

  2. 남은 불일치 18건 중 14건(fit1d 12, kb2 1, stocfor1 1)이 같은 원인이다. 수정 프로토타입은 flip 3112/3112, 진입 3108/3112다. 나머지 tuff 4건은 작은 음의 d에 대한 비용 이동이다(반환 d로 재생하면 일치, 이동량 RNG는 미검증).
