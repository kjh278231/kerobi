# M1 LP presolve: `47c445`(PreDepRow) 해독 노트

[m1_presolve.md](m1_presolve.md) §7 10단계(종속 행)의 해독이다. 2026-11-05에 의사코드와 asm으로 해독하고 오라클로 확인했다. 줄 번호는 `re/decomp/c/0041c920_PRIVATE000000000047c445.c` 기준이다. 코드는 `crates/lp/src/presolve/deprow.rs`.

## 0. 범위

- presolve는 `47c445(μ, state, 0, env, 0, mode, work)`로 부른다. spx 문맥(param_3)이 0이라 `local_68`은 늘 0이다. 그래서 조밀 LU `474ae5`, `47821a`, crossover 로그·콜백 분기는 돌지 않는다. 남는 것은 함수 안의 희소 Markowitz 소거뿐이다(MKL은 쓰지 않는다).
- state+0xe0 = 1(CSR)이라 행렬은 `515b74`(mode 1), `516cb4`(mode 2)가 만든다. +0xe0 = 0(연결 리스트) 분기는 LP presolve에서 쓰이지 않는다.
- state+0x1d8은 `390989`의 param_4다. `Model.presolve()` 경로(`999702`)는 0을 넘기므로 "작업량이 많으면 −1000으로 포기" 분기(L1035–1044, L1413–1425)는 돌지 않는다.
- postsolve 레코드: 함수 안에 `ac68d7` 호출이 없다. mode 1은 레코드 없이 행만 지운다. mode 2의 열 고정은 `4fa83a(rec=1)`이라 type 1(`FixCol`)을 남긴다. 그래서 `PostRec`에 새 변형이 필요 없다.

## 1. 두 모드

| | mode 1 (`515b74`) | mode 2 (`516cb4`) |
|---|---|---|
| 행 | `=`이고 행 개수 > 0인 행(번호 다시 매김) | 모든 행 m (제거된 행은 빈 행) |
| 열 | 모든 열 n (제거된 열은 빈 열) | 자유 열: 개수 ≥ 1, +0x170 = 0, lb ≤ −1e30, ub ≥ 1e30 |
| 값 | 열 CSR(+0x58) | 행 CSR(+0x38) |
| 순회 | 열 0..n, 열 CSR 순서 | 행 0..m, 행 CSR 순서 |
| 함께 소거하는 벡터 `b` | 행의 rhs 사본 | 열의 비용 사본 |
| 끝 판정 | 빈 행: \|b\| ≤ 10ft면 행 삭제, ≥ 1e4·ft면 3(불가능), 그 사이는 그대로 | 빈 열: \|b\| ≤ 10ft면 `4fa83a(0, INF, rec 1)`, ≥ 1e4·ft면 5(비유계) |

- 노드는 32바이트(값, +8 행, +0xc 열(−1 = 죽음), +0x10 행 안 다음, +0x18 열 안 다음)다. 순회 순서대로 행 목록·열 목록 꼬리에 붙인다. 그래서 mode 1의 행 목록은 열 번호순, 열 목록은 열 CSR 순서다. mode 2는 반대다.
- 행 삭제(mode 1 끝, L2362–2433): 원래 행 번호 순으로 돌며 `537da8`(행의 열 표시), 살아 있는 열마다 col_cnt−1과 row_ind = −1, row_cnt = −2. 마지막에 +0x404 += 지운 수. 3을 돌려줄 때는 +0x404를 더하지 않는다(앞에서 지운 행은 지운 채 남는다).
- 상태 코드 3/5를 돌려줄 때 +0x470/+0x478은 쓰지 않는다.

## 3. 개수 버킷

- 열 버킷은 행 수만큼, 행 버킷은 열 수만큼 있다. 버킷 k에는 개수 k+1인 줄이 있다. 개수 0인 줄은 빈 줄 카운터(`local_40` 열, `local_3c` 행)로 간다.
- 원형 이중 연결 리스트다. 머리의 prev = −2 − 꼬리, 꼬리의 next = −2 − 머리, 원소 하나면 둘 다 −2 − 자기. 처음에는 줄 번호 순으로 머리에 넣는다(그래서 버킷 안은 번호 내림차순). 그 뒤 옮기는 줄은 꼬리에 붙는다.
- 회전(L2037 `LAB_0052315f`, `LAB_0052283a`): 리스트를 잠깐 닫고, 마지막에 본 줄이 피벗의 줄이면 그 줄, 아니면 그다음 줄을 새 머리로 한다. 다음 탐색이 멈춘 곳에서 이어진다.
- 플래그(`local_190` = state+0x3b8, 0으로 지움): 행 비트 1, 열 비트 2 = "목록에 죽은 노드가 있다". 압축하면 지운다. 열 목록 압축에서 나온 죽은 노드만 빈 노드 수로 센다(행 목록은 노드를 소유하지 않는다).

## 4. 소거 루프 (`LAB_0051e164`)

```
loop {
  [100회마다 3ba5ac(로그), 3ba9de(작업 예산. 넘으면 +0x1dc = −1 → 마무리로)]   // 포팅 안 함
  싱글턴: 열 싱글턴을 다 처리하고, 행 싱글턴 하나, 다시 열 싱글턴 전부 … 반복
  남은 행 R = 행 − 빈 행 − 피벗, 남은 열 C, u = min(R, C). u = 0이면 마무리
  첫 번째만: auto && mode 1 && u ≥ 3001이면 개수 > 3000인 열이 닿는 행을 빼고 keep 표시
             (u를 다시 구해 0이면 마무리, 싱글턴이 생겼으면 다음 바퀴)
  u > 50이면 밀도 검사: auto(PreDepRow = −1)면 max(100, 빈 행) < R이고 (8R² < nnz' 또는 0.3RC < nnz')일 때,
                         아니면 0.3RC < nnz'일 때 마무리
  탐색 → 피벗 또는 작은 줄 제거
}
```

싱글턴(L1430–1750):
- 행 싱글턴 r(열 c): 작업량 += 개수(c)·10μ. \|a\| ≥ TINY이거나 mode 2면 피벗한다. mode 1은 c의 다른 행에 b[i] −= b[r]·a_ic/a, 그다음 `47bbb6`(c를 지우며 그 행들의 개수를 줄이고 버킷 이동, 행 플래그, 노드 해제). 아니면(mode 1의 작은 피벗) 행을 빈 행으로 세고 `47bec3`(행의 열들 개수 감소), \|a\| > 1e-10이면 b[r] = keep.
- 열 싱글턴 c(행 r): 작업량 += 개수(r)·10μ. \|a\| ≥ TINY이거나 mode 1이면 피벗한다. mode 2는 r의 다른 열에 b[k] −= b[c]·a_rk/a. r의 열들 개수 감소. 아니면(mode 2) 열을 빈 열로 세고 `47bbb6`, \|a\| > 1e-10이면 b[c] = keep.

탐색(L1784–2190, asm 0x420cd0에서 하한 확인):
- kc = 비지 않은 열 버킷 중 가장 작은 번호 ≥ 1(없으면 행 수), kr = 행 버킷의 같은 값(없으면 열 수). k = min(kc, kr), 하한 lb = kc·kr, 한도 = min(u, max(8, k/2)), best = 행 수·열 수(전체), 비율 0.
- k마다 열 버킷 k를 머리부터 본다. 열을 압축하고 최대 \|a\|를 구한다. mode 2에서 최대 < TINY면 그 열을 "작은 줄"로 기억(최대 > 1e-10이면 b = keep)하고 열 쪽을 끝낸다. 최대 < ZERO면 다음 열.
- 후보 검사: mk = (그 행 개수 − 1)·k. (mk < best && 0.01·최대 < \|a\|) 또는 (mk == best && 비율·최대 < \|a\|)이면 비율 = (int)(\|a\|/최대), best = mk, 피벗 = 그 노드. 비율은 0 아니면 1이라, 동률은 나중 후보가 이긴다(앞 후보가 그 줄의 최대였으면 바뀌지 않는다).
- 줄 하나를 볼 때마다 cnt+1. 작은 줄을 이미 기억했으면 한 줄 더 보고 그 쪽을 끝낸다. cnt ≥ 한도면 (피벗이 있고 지금 줄이 꼬리가 아니면 회전하고) 탐색 끝. best ≤ lb면 (같은 조건으로 회전하고) 탐색 끝.
- 열 쪽 다음 best > lb면 행 버킷 k를 같은 방식으로 본다(mode 1에서 행 최대 < TINY면 작은 줄 = 행 + 열 수, 행에는 ZERO 건너뛰기가 없다). best ≤ lb면 끝, 아니면 k+1(u에 닿으면 끝).
- 작업량 += cnt·10μ·k (k는 끝났을 때의 버킷 번호).

피벗(L2975–3690):
- 작은 줄이 있으면 피벗 대신 그 줄을 지운다(열이면 `47bbb6`, 행이면 `47bec3`와 같은 루프, 빈 줄로 센다).
- 피벗 (r, c): 버킷에서 빼고 fill = (개수 r − 1)(개수 c − 1). fill > fill 한도면 포기. 빈 노드 ≤ fill이면 해제 목록을 합치고, 플래그가 선 열(죽은 노드 해제)·행을 모두 압축하며 작업량 += 목록 길이·μ. 그래도 모자라면 max(2·fill, 청크) 청크를 더 잡는다(노드 한도 검사).
- 작업량 += 20μ·개수 r·개수 c. nnz' −= 개수 r + 개수 c − 1.
- 피벗 노드를 죽이고 r, c 목록을 압축한다. c의 행 i마다 (mode 1) b[i] −= b[r]·a_ic/p, Σ개수(i), 버킷에서 뺀다. r의 열 k마다 (mode 2) b[k] −= b[c]·a_rk/p, Σ개수(k), 버킷에서 뺀다.
- Σ열 개수 ≤ Σ행 개수면 열 방향: r의 열 k마다 (플래그면 압축) k 목록을 행 번호로 흩고, c의 행 i마다 d = (−a_ic·a_rk)/p. 없던 자리는 \|d\| ≥ ZERO일 때 새 노드를 행 i·열 k 목록 **머리**에 넣는다. 있던 자리는 값 += d, \|값\| < ZERO면 죽인다(개수 감소, 플래그는 아래에서 선다). 아니면 같은 일을 행 방향으로 한다(행 i를 열 번호로 흩고 r의 열을 돈다).
- 끝으로 c의 살아 있는 노드마다 행 개수 −1(0이면 빈 행, 아니면 버킷 꼬리), 행 플래그, 노드 해제. r의 노드마다 열 개수 −1, 열 플래그, 노드 죽임.

노드 재사용: 해제한 노드는 행 목록에 죽은 채 남아 있을 수 있다. 원본은 해제 목록을 쓰기 전에 모든 플래그 목록을 압축하므로 재사용된 노드가 옛 목록에 남지 않는다. 그래서 포트는 노드를 재사용하지 않고 빈 노드 수만 센다(포기 조건과 작업량이 같다).

## 7. 남은 것

- `3ba9de` 작업 예산 정지(100회마다)는 다른 reduction처럼 옮기지 않았다(`mod.rs`의 shortcut과 같은 P2 항목).
- MarkowitzTol, GURO_PAR_ZERO는 Params에 없어 기본값을 상수로 둔다.
